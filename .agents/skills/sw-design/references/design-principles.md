# 설계 원리와 지침

`sw-design` design 모드 전 단계에서 읽는다.

## 1. 설계란

요구사항 분석이 "무엇을 만들까(What)"를 정했다면, 설계는 "어떻게 만들까(How)"를 정한다. 코드를 쓰기 전에 전체 구조를 미리 계획하는 일이며, 건축의 설계도에 해당한다.

설계의 목표 세 가지:
1. 시스템 구성 요소를 **추상화**한다. 전체를 개략적으로 나눈다.
2. 요소 간 **인터페이스**를 정의한다. 누가 누구에게 무엇을 어떤 순서로 넘기는가.
3. **품질 보증과 개선**을 고려한다. 나중에 고치기 쉽게, 기능을 더할 때 기존 것에 영향이 적게.

## 2. 설계 모델 4단계

| 순서 | 모델 | 정하는 것 | 입력 |
|------|------|-----------|------|
| 1 | 데이터 설계 | 데이터 구조, 키, 제약, 접근 모듈 | SRS 자료사전, 저장소, ERD |
| 2 | 구조(아키텍처) 설계 | 모듈 트리, 계층, 모듈별 책임 | SRS DFD |
| 3 | 인터페이스 설계 | 모듈 간 호출 규약(매개변수·반환·오류), 화면, 외부 연동 | 2의 모듈, SRS 5장 |
| 4 | 절차 설계 | 최하위 모듈의 알고리즘 | SRS 소단위 명세서 |

데이터가 먼저다. 구조·인터페이스·절차는 모두 "어떤 데이터를 다루는가"에 종속된다.

## 3. 기본 원리

### 추상화 (Abstraction)

복잡한 것을 단순하게 표현한다. 처음부터 벽돌 하나하나를 생각하지 않고 "몇 층, 방 몇 개"부터 정하는 것.

| 종류 | 설명 | 예 |
|------|------|-----|
| 기능 추상화 | 입력을 출력으로 바꾸는 과정을 이름 하나로 | "성적 입력 → 등급 산출" |
| 제어 추상화 | 제어 흐름(순서·조건·반복)의 세부를 감추고 무엇을 제어하는지만 | "검증 통과 시 다음 화면으로" |
| 자료 추상화 | 데이터와 그 데이터에 대한 연산을 함께 묶어 이름 하나로 | "성적 레코드" = {학번, 과목, 점수} + {등급 계산} |

추상화 기법은 이 **셋**이다. 정보 은닉은 추상화의 한 종류가 아니라 모듈 설계 원리다.

### 단계적 분해 (Stepwise Refinement)

큰 문제를 점점 작은 문제로 나눈다. 분할 정복의 소프트웨어 판.

```
학사관리 시스템
├── 학적 관리
│   ├── 학생 등록
│   ├── 학적 조회
│   └── 학적 변경
├── 성적 관리
│   ├── 성적 입력
│   │   ├── 수강생 목록 조회
│   │   ├── 성적 검증
│   │   └── 등급 계산
│   └── 성적 조회
└── 수강신청
```

한 번에 다 만들려 하지 않고 한 단계씩 구체화한다. 각 단계에서 "이 모듈이 한 문장으로 설명되는가"를 묻고, 아니면 한 번 더 나눈다.

### 프로그램 구조 (Program Structure)

모듈들이 어떤 계층으로 연결되어 있는가를 트리로 표현한다. 실행 순서가 아니라 호출 관계다.

| 용어 | 뜻 | 기준 |
|------|----|------|
| 깊이(Depth) | 계층 수 | 7 이하 |
| 넓이(Width) | 같은 계층의 모듈 수 | 한 상위 모듈 아래 7 이하 |
| Fan-In | 어떤 모듈을 호출하는 상위 모듈 수. "나를 부르는 수" | 공용 모듈은 높아도 됨. 단, 그 모듈은 안정적이어야 |
| Fan-Out | 어떤 모듈이 호출하는 하위 모듈 수. "내가 부르는 수" | 7 이하 |

Fan-In이 높으면 재사용성이 높다는 뜻이지만 동시에 수정 시 영향 범위가 넓다. Fan-Out이 높으면 조정자 역할이지만 복잡도가 높다. "Fan-In은 재사용성, Fan-Out은 복잡도"로 기억하고 둘 다 균형을 본다.

### 모듈화 (Modularity)

프로그램을 독립적으로 실행 가능한 작은 단위로 나눈다.

왜 하는가:
- 이해하기 쉽다 (작고 명확한 단위)
- 유지보수성 (한 부분을 바꿔도 다른 부분에 영향 적음)
- 재사용성 (다른 프로젝트에서 같은 모듈 재활용)
- 확장성 (기능 추가 시 전체를 바꿀 필요 없음)

모듈화의 품질 척도가 **응집도와 결합도**다. 응집도는 높게, 결합도는 낮게. 등급표는 `cohesion.md`, `coupling.md`.

모듈화는 객체지향만의 개념이 아니다. 구조적 설계에서도 같은 원리로 쓴다.

### 정보 은닉 (Information Hiding)

모듈 내부의 세부 내용(자료 구조, 알고리즘)을 다른 모듈로부터 감춘다. 다른 모듈은 "이 모듈이 무엇을 하는가"만 알면 되고 "어떻게 하는가"는 몰라야 한다.

감기약 캡슐: 겉에서는 알약 하나, 안에 어떤 성분이 어떻게 조합됐는지는 사용자가 알 필요 없다.

효과: 독립성 향상, 내부 변경이 외부로 전파되지 않음, 결합도 감소, 보안.

```python
class GradeCalculator:
    def get_grade(self, score):        # 공개 인터페이스
        return self.__calculate(score)
    def __calculate(self, score):      # 숨긴 내부 로직
        ...
```

### 기능적 독립성 (Functional Independence)

각 모듈이 다른 모듈에 의존하지 않고 자기 역할을 스스로 수행하는 정도. 응집도가 높고 결합도가 낮으면 기능적 독립성이 높다.

효과: 한 모듈을 고쳐도 다른 모듈에 영향 없음, 오류 영향 범위가 작음, 모듈 단위 테스트가 쉬움.

## 4. 좋은 설계의 지침

| 지침 | 뜻 | 위반 시 |
|------|----|---------|
| 응집도 높게, 결합도 낮게 | 모듈 독립성 | 한 곳 수정이 전체로 전파 |
| 단일 입구·단일 출구 | 모듈에 들어오는 곳 하나, 나가는 곳 하나 | 흐름 추적 불가, 테스트 경로 폭증 |
| 적당한 크기 | 너무 크면 복잡, 너무 작으면 인터페이스 비용 | 한 화면(50~100줄)을 기준으로 |
| 단순한 인터페이스 | 매개변수 5개 이하, 필요한 값만 | 호출마다 실수, 스탬프·제어 결합 |
| 예측 가능 | 같은 입력이면 같은 출력. 숨은 상태 없음 | 재현 안 되는 오류 |
| 기능별 논리적 모듈 분리 | 한 모듈 한 기능 | 수정 범위를 알 수 없음 |
| 복잡도·중복 최소화 | 같은 코드를 두 곳에 두지 않음 | 한쪽만 고쳐 불일치 |

## 5. 설계 품질 평가 기준

| 기준 | 설명 |
|------|------|
| 모듈성 | 작은 단위로 분리되어 있는가 |
| 계층 구조 | 상위-하위가 명확한가 |
| 자료와 프로시저 분리 | 데이터 정의와 처리 절차가 구분되는가 |
| 명확성 | 구조를 이해하기 쉬운가 |
| 독립성 | 각 모듈이 독립적으로 동작하는가 |
| 확장성 | 기능 추가·변경이 쉬운가 |
| 이식성 | 다른 환경에서도 동작하는가 |
| 유지보수성 | 수정·보완이 쉬운가 |

"설계는 전체적으로 통합되어야 한다"는 기준이 **아니다.** 통합적(모노리식) 설계는 모듈성의 반대이며 유지보수·확장에 가장 나쁘다.

## 6. 바람직하지 않은 설계 신호

| 신호 | 문제 |
|------|------|
| 서브루틴이 통합적으로 얽힘 | 독립성 상실 |
| 전역 변수로 모듈 간 통신 | 공통 결합 |
| 모듈 크기 극단적 불균형 | 일부는 거대, 일부는 한 줄 |
| 인터페이스 매개변수 10개 | 추적 불가 |
| 모듈 이름이 "처리", "관리", "공통" | 책임 불명 |
| 같은 저장소를 여러 모듈이 직접 접근 | 외부 결합 |
| 호출 트리가 그물망 | 순환, 허브 |

## 7. 절차 설계 표기

최하위 모듈의 알고리즘은 다음 중 하나로 쓴다. 모두 순차·선택·반복 세 구조만 쓴다.

**의사코드**
```
성적 검증(성적입력, 기간):
    IF 현재일시 NOT IN 기간 THEN RETURN 거부("기간 외")
    FOR EACH 행 IN 성적입력
        IF 행.점수 NOT IN 0..100 THEN 오류목록.추가(행)
    IF 오류목록 비어있지 않음 THEN RETURN 거부(오류목록)
    RETURN 통과(성적입력)
```

**N-S 도표(Nassi-Shneiderman)**: 상자 안에 순차는 위아래, 선택은 좌우 분할, 반복은 L자 테두리로. goto를 그릴 수 없어 구조적 설계에 강제력이 있다.

**의사결정표**: 조건이 3개 이상 조합될 때. 조건 행 × 규칙 열, 아래에 동작 행.
