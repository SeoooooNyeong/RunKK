# 학사관리 시스템 요구사항 명세서
> 작성: 2026-03-10 | 버전: v1.1 | 입력: plan.md, 교무처 인터뷰(03-02), 교수 인터뷰(03-03, 03-04), 학생 설문(03-05, 212명), 현행 성적 양식·수강신청서, 시제품 평가(03-09)

## 1. 개요

### 1.1 목적
이 문서는 OO대학교 교무처가 발주한 학사관리 시스템의 요구사항을 정의한다. 발주자(교무처)와 개발사 사이의 인수 기준이며, 설계·구현·테스트는 이 문서를 기준으로 수행한다. 이 문서에 없는 기능은 인수 대상이 아니다.

### 1.2 범위
**하는 일**
- 학적 관리: 학생 등록·수정, 학적 조회, 기존 학적 DB 연동
- 성적 관리: 성적 입력·수정, 등급 계산, 성적 조회, 이의신청, 성적표 출력
- 수강신청: 과목 개설 조회, 수강신청, 승인·반려, 신청 결과 조회

**하지 않는 일**
- 재정 관리(등록금, 장학금). 기존 재정 시스템이 담당한다
- 시설 관리(강의실 배정)
- 모바일 전용 앱. 모바일 브라우저 접근은 범위에 포함하되 앱은 제외한다
- 교수 인사·급여

### 1.3 용어 정의
| 용어 | 정의 | 비고 |
|------|------|------|
| 학적 | 학생의 신분 정보(학번, 성명, 학과, 학년, 재학 상태) | "학생 정보"와 같은 뜻으로 쓰지 않는다. 학생 정보는 연락처를 포함 |
| 성적 입력 기간 | 교무처가 학기마다 정하는 성적 입력 허용 기간 | 기간 밖 입력은 거부 |
| 이의신청 | 학생이 공개된 성적에 대해 재확인을 요청하는 행위 | "정정 요청"이라고도 불렀으나 이 문서는 이의신청으로 통일 |
| 수강 철회 | 수강신청 확정 후 학생이 취소하는 것 | 신청 기간 중 취소는 "신청 취소"로 구분 |
| 승인대기 | 정원 초과 또는 선수과목 미이수로 교수 승인이 필요한 신청 상태 | |
| 평점평균 | 학기 또는 누적 등급의 학점 가중 평균 | 4.5 만점 |

### 1.5 문서 구성
2장은 시스템 전체와 환경·제약, 3장은 기능 요구(FR), 4장은 비기능 요구(NFR), 5장은 외부 연동, 6장은 DFD·자료사전·소단위 명세서, 7장은 추적표·검토·변경 이력·승인이다.

## 2. 전체 설명

### 2.1 시스템 개요 (배경도, Level 0)
```
                    ┌──────────┐
                    │  교무처   │
                    └────┬─────┘
    학생등록정보, 성적입력기간,  │     ▲ 등록결과, 수강통계, 이의신청목록
    수강승인기준               ▼     │
┌──────┐  성적입력, 승인결정  ┌──────────────────┐  수강신청, 이의신청  ┌──────┐
│ 교수 │ ─────────────────▶ │                  │ ◀───────────────── │ 학생 │
│      │ ◀───────────────── │  학사관리 시스템   │ ─────────────────▶ │      │
└──────┘  입력확인, 수강생목록, │        0         │  신청결과, 성적조회, └──────┘
          승인대기목록        └────────┬─────────┘  성적표
                       학적조회요청 │     ▲ 학적정보
                                  ▼     │
                        ┌──────────────┐
                        │ 기존 학적 DB  │
                        └──────────────┘
```
시스템은 교무처·교수·학생 세 사용자 유형과 기존 학적 DB 하나의 외부 시스템과 자료를 주고받는다. 학적의 원본은 기존 학적 DB에 있고 이 시스템은 조회·동기화한다.

### 2.2 사용자 특성
| 사용자 유형 | 인원 | 숙련도 | 사용 빈도 | 권한 |
|------------|------|--------|-----------|------|
| 교무처 직원 | 8 | 높음(기존 시스템 5년 이상) | 매일 | 전체 조회, 기준값 설정, 등록 |
| 교수 | 약 320 | 중간 | 학기당 2~3회 집중 | 담당 과목 성적·승인 |
| 학생 | 약 9,000 | 다양 | 수강신청 기간 집중, 성적 공개일 집중 | 본인 자료만 |
| 전산실 | 3 | 높음 | 장애·연동 시 | 시스템 관리 |

### 2.3 운영 환경
- 서버: 교내 전산실 가상 서버 (OS는 전산실 표준을 따름)
- 클라이언트: PC 웹 브라우저(Chrome, Edge 최신 2개 버전), 모바일 브라우저
- 네트워크: 교내망과 외부 인터넷 모두 접근
- 기존 시스템: 학적 DB(Oracle, 전산실 운영), 통합 인증(SSO)

### 2.4 제약 조건
| ID | 제약 | 출처 |
|----|------|------|
| C-001 | 기존 학적 DB(Oracle)의 학번 체계와 테이블을 변경하지 않고 연동해야 한다 | 전산실 (03-06) |
| C-002 | 로그인은 교내 통합 인증(SSO)을 써야 한다 | RFP 4.2 |
| C-003 | 학기 시작 2주 전(2026-08-17)까지 가동해야 한다 | RFP 1.3 |
| C-004 | 개인정보보호법에 따라 주민등록번호를 저장하지 않는다 | 교무처 (03-02) |

### 2.5 가정과 의존성
| ID | 가정 | 깨지면 영향받는 요구 |
|----|------|---------------------|
| A-001 | 기존 학적 DB의 학번 10자리 체계가 유지된다 | FR-001, FR-002, 자료사전 "학번" |
| A-002 | 통합 인증이 사용자 유형(교직원/교수/학생)을 제공한다 | FR-020, NFR-003 |
| A-003 | 등급 기준(A+ 95 이상 등)은 학기 중 바뀌지 않는다 | FR-012 |

```
[교무처] ──학생등록정보──▶ (1. 학적 관리) ◀──학적정보── [기존 학적 DB]
                              │  ▲
                   학적정보   │  │ 학적조회요청
                              ▼  │
                          ║학적 파일║
                              ▲
                     수강생목록│(읽기)
                              │
[교수] ──성적입력──▶ (2. 성적 관리) ──성적조회결과, 성적표──▶ [학생]
  ▲                     │  ▲                                  │
  │ 입력확인             ▼  │ 이의신청                          │
  │                 ║성적 파일║  ◀────────────────────────────┘
  │                     ▲
  │                     │ 수강확정정보(읽기)
  │                     │
[학생] ──수강신청──▶ (3. 수강신청 관리) ──신청결과──▶ [학생]
  ▲                     │  ▲
  │ 승인대기목록          ▼  │ 승인결정

                              └──알림──▶ ║알림 파일║ ──▶ [교수], [학생]
```

배경도의 입출력(학생등록정보, 성적입력, 입력확인, 수강신청, 신청결과, 성적조회, 성적표, 이의신청, 승인결정, 학적조회요청, 학적정보, 수강통계)이 모두 Level 1에 나타난다. 저장소 5개(학적, 성적, 수강, 기준값, 알림)가 여기서 처음 등장한다.

### 6.2 자료사전
```
개설과목목록   = {과목코드 + 과목명 + 담당교수 + 학점 + 요일시간 + 정원 + 신청인원 + (선수과목코드)}
검증된 성적    = 검증된 점수 + 등급
검증된 점수    = 학번 + 과목코드 + 학기 + 점수 + (비고)
                 * 2.2에서 범위·기간 검증을 통과한 성적입력 *
과목코드       = * 7자리. 학과코드 3자리 + 일련번호 4자리 *
기준값설정     = [성적입력기간 | 성적공개일 | 수강신청기간 | 학기최대학점 | 등급기준표]
                 * 교무처가 학기마다 설정. 변경 이력 보관 *
등급           = [A+ | A | B+ | B | C+ | C | D+ | D | F]
등급기준표     = {등급 + 하한점수} + (상대평가분포)
성적레코드     = 학번 + 과목코드 + 학기 + 점수 + 등급 + 입력자 + 입력일시 + {수정이력}
성적입력       = 학번 + 과목코드 + 학기 + 점수 + (비고)
                 * 교수가 성적 입력 화면에서 보내는 자료 *
성적조회결과   = 학번 + 학기 + {과목코드 + 과목명 + 학점 + 등급} + 평점평균
                 * 공개일 전이면 등급 대신 "미공개" *
성적표         = 성적조회결과 + 성명 + 학과 + 발급번호 + 발급일시
수강생목록     = 과목코드 + 학기 + {학번 + 성명 + 학과}
                 * 상태가 확정인 신청만 *
수강신청       = 학번 + 학기 + {과목코드}
수정이력       = 이전점수 + 수정자 + 수정일시 + 사유
승인결정       = 신청ID + [승인 | 반려] + (사유)
신청결과       = 학번 + 학기 + {과목코드 + 상태 + (거부사유)}
신청레코드     = 신청ID + 학번 + 과목코드 + 학기 + 상태 + 신청일시
알림           = 사용자ID + 종류 + 내용 + 발생일시 + 읽음여부
이의신청       = 학번 + 과목코드 + 학기 + 사유 + 신청일시
이의처리       = 이의신청ID + [유지 | 수정] + (수정점수) + 답변
입력확인       = 저장건수 + {오류학번 + 오류사유}
점수           = * 0~100 정수. 결시는 비고에 사유, 점수 0 *
상태           = [확정 | 승인대기 | 반려 | 취소]
학번           = * 10자리 숫자. 입학년도 4자리 + 일련번호 6자리. 기존 학적 DB와 동일 *
학생등록정보   = 학번 + 성명 + 학과코드 + 입학년도 + 연락처 + (보호자연락처)
학적정보       = 학번 + 성명 + 학과코드 + 학년 + 재학상태
학적 파일      = {학적정보 + 연락처 + {학적변경이력}}
성적 파일      = {성적레코드} + {이의신청 + (이의처리)}
수강 파일      = {신청레코드} + {과목코드 + 과목명 + 담당교수 + 학점 + 요일시간 + 정원 + (선수과목코드)}
기준값 파일    = {기준값설정 + 설정자 + 설정일시}
알림 파일      = {알림}
```

### 6.3 소단위 명세서

#### 2.2 성적 검증
```
입력: 성적입력, 기준값(성적입력기간)
IF 현재일시가 성적입력기간 밖이면
    입력확인 ← "기간 외 입력 거부" + 교무처 연락처
    종료
각 성적입력 행에 대해
    IF 점수가 정수가 아니거나 0 미만 또는 100 초과이면
        오류목록에 (학번, "점수 범위 오류") 추가
    ELSE IF 학번이 해당 과목 수강생목록에 없으면
        오류목록에 (학번, "수강생 아님") 추가
    ELSE
        검증된 점수에 추가
IF 오류목록이 비어 있지 않으면
    입력확인 ← 저장건수 0 + 오류목록      * 부분 저장하지 않는다 *
ELSE
    검증된 점수를 2.3으로 보냄
    입력확인 ← 저장건수
```

#### 2.3 등급 계산
```
입력: 검증된 점수, 등급기준표
IF 과목이 상대평가이면
    과목 수강생 점수를 내림차순 정렬
    상대평가분포(예: A 30%, B 40%, C 이하 30%)에 따라 등급 부여
ELSE
    등급 ← 등급기준표에서 점수 이상인 하한점수 중 가장 높은 등급
검증된 성적 ← 검증된 점수 + 등급
성적 파일에 저장
```

#### 2.5 이의신청 처리 (접수 부분)
| 조건 \ 규칙 | 1 | 2 | 3 | 4 |
|-------------|---|---|---|---|

| 동작: 거부 "수강 내역 없음" | | | | X |

#### 3.2 신청 검증·등록
```
입력: 수강신청, 기준값(수강신청기간, 학기최대학점), 수강 파일
IF 현재일시가 수강신청기간 밖이면
    신청결과 ← 전체 거부 "기간 외"
    종료
각 과목코드에 대해
    IF 학생의 확정·승인대기 과목과 요일시간이 겹치면
        상태 ← 거부, 거부사유 ← "시간표 중복"
    ELSE IF 누적 학점 + 과목 학점 > 학기최대학점이면
        상태 ← 거부, 거부사유 ← "최대 학점 초과"
    ELSE IF 신청인원 < 정원 AND (선수과목 없음 OR 선수과목 이수)이면
        상태 ← 확정, 신청인원 + 1
    ELSE
        상태 ← 승인대기
    신청레코드 저장
신청결과 ← {과목코드 + 상태 + (거부사유)}
```

### 6.4 상태전이도 — 수강신청 상태
```
          신청(정원 내, 선수 이수)
  [시작] ───────────────────────────▶ (확정)
    │                                  │  ▲
    │ 신청(정원 초과 또는 선수 미이수)     │  │ 교수 승인
    ▼                                  │  │
 (승인대기) ───────────────────────────┼──┘
    │          교수 반려 / 기한 내 미처리  │
    ▼                                  │ 학생 취소(기간 중)
  (반려)                               ▼
                                     (취소) ──▶ [종료]
```
상태: 확정, 승인대기, 반려, 취소. 사건: 신청, 승인, 반려, 기한 경과, 취소. 반려 상태에서는 더 이상 전이하지 않는다.
