# 하위 작업자 지시서 양식

`sw-implement` 3단계에서 단계 하나를 맡길 때 쓴다. 빠진 절이 있으면 작업자가 추측으로 메운다. 아래 절을 모두 채운다.

```markdown
너는 <프로젝트> <단위> 구현 <단계 ID>(<한 줄 범위>)를 맡는다. 한국어로 보고한다.

## 작업 위치 (여기서만 편집)
- worktree: `<절대 경로>` (브랜치 `<브랜치>`, 앞 단계 커밋 <해시>까지 있음).
- 고칠 곳: `<폴더>`. 고치지 말 곳: `<폴더>`(다른 작업자가 동시에 고치는 중). 불가피하면 추가 위주 최소 변경, 보고서에 기록.
- **브랜치를 바꾸거나 커밋을 체크아웃하지 않는다.** 커밋 전후 `git branch --show-current` 확인.
- push·MR 금지, 로컬 커밋만. 비밀 파일(`local.properties`, `.env`) 커밋 금지.
- 팀 규칙: `AGENTS.md`, `CLAUDE.md`.

## 정답 자료
- 설계서: `<경로>` — 반드시 읽을 절: <절 목록>.
- 요구사항: `<경로>` — <해당 FR·화면>.
- 시안·계약 표본: `<경로>`.
- 앞 단계 코드부터 읽는다: <패키지·파일>.
- 코드 리뷰 기준: `docs/sw/code-review.md`(앞 리뷰에서 지적된 유형을 반복하지 않는다).

## 사용자 결정 (바꾸지 말 것)
- <스택, 이름 규칙, 범위 결정>

## 범위 (<단계 ID>)
1. <패키지·계층·엔드포인트·화면>
2. <앞 단계가 남긴 연결>
3. <시험: 단위·통합·구조·계약 항목>

## 앞 단계가 남긴 사용법
- <조회 서비스·사건·포트, 마이그레이션 번호, 공통 패턴, 시험 도구, 함정>

## ECC 흐름 (스킬을 불러 순서대로)
<references/ecc-workflows.md의 해당 스택 표>. 끝에 <reviewer> 리뷰 작업자(중위 모델)로 자가 리뷰 → 높음 이상 고침.
<스킬·리뷰어를 부르는 방법: harness-claude.md 또는 harness-codex.md의 "도구 대응" 표에서 해당 행>.

## 실행 환경
- <OS·셸·JDK 경로·검증 명령>. 검증과 커밋을 한 줄로 묶을 때 `set -o pipefail`.
- 공용 빌드 캐시 잠금이면 잠시 뒤 다시 시도(데몬 전체 정지 금지).
- 훅이 막으면 요청 한 문장·목적·사용자 지시 원문을 적고 다시 실행.

## 정확도 규칙
- 이름은 설계서와 글자 그대로. 설계서에 없는 공개 클래스는 최소로, 결정 목록에.
- 모호·모순은 설계 의도에 가장 맞는 쪽을 고르고 결정 목록에. 설계서 문서는 고치지 않는다.

## 커밋
- 의미 단위로 여러 번, 제목 `<타입>: <내용> [<이슈 키>]`, 본문 끝 공동 작성자 줄. 끝날 때 작업 트리 깨끗하게.

## 마지막 보고 (이 형식으로)
1. 커밋 목록
2. 클래스 수·엔드포인트·화면(설계 대비 구현/보류), 시험 수, 검증 결과, 커버리지
3. 구조 시험 상태
4. 결정 목록
5. 새 환경 변수
6. 다음 단계가 알아야 할 것
7. 설계서 갱신 요청
```

## 이어서 진행시킬 때 (사용량 한도 등으로 멈춘 경우)

```markdown
멈춘 자리("<마지막 작업>")부터 이어서 진행해 주세요. 먼저 `git branch --show-current`, `git status`, `git log --oneline -5`로
상태를 확인하고 이미 한 일은 반복하지 마세요. 범위·검증·보고 형식은 처음 지시 그대로입니다.
```
