# 용어 대조표 (sw-maintain)

강의에서 쓰는 표현과 이 스킬의 용어를 대조한다. 본문에서는 왼쪽 표현을 쓰지 않는다.

## 유지보수

| 강의 표현 | 스킬 용어 |
|-----------|-----------|
| 유지보수 = 인수·설치 후 모든 공학적 수정 | 유지보수 정의 (`maintenance-types.md` 1절) |
| 유지보수 비용 > 개발 비용 | 동일 |
| Corrective / 수정 보수 / 하자 보수 | 수정 보수 |
| Adaptive / 적응 보수 | 적응 보수 |
| Perfective / 완전화 보수 / 기능 개선 보수 | 개선 보수 |
| Preventive / 예방 보수 | 예방 보수 |
| CAPP | 네 유형 영어 머리글자 (암기용, 본문 미사용) |
| Perfective 비용 최대, 약 50% | 개선 보수 비용 비중 |
| 요구 확인 → 기존 시스템 이해 → 코드 수정 → 수정 후 테스트 | 절차 4단계 |
| 코딩 부작용 / 자료 부작용 / 문서화 부작용 | 부작용 3종 |
| 외계인 코드(Alien Code), 15년 이상, 방지는 문서화 | 외계인 코드 판정과 방지 |
| 유지보수 목적 중 부적절한 것: 설계 보수 | 유지보수는 설계를 다시 하는 활동이 아님 |
| 계분설구테유 중 "유" | 유지보수 단계 |

## 재공학

| 강의 표현 | 스킬 용어 |
|-----------|-----------|
| 재공학(Reengineering) | 재공학 (`reengineering.md`) |
| 재공학 = 예방 보수 | 동일 |
| 분석 → 재구성(개조) → 이식 → 역공학 | 활동 4개 |
| 재구성: 기능 불변, 구조만 개선 | 재구성 (비교 검사로 증명) |
| 이식(Migration): OS·HW·DB 변경 | 이식 |
| 역공학(Reverse Engineering): 코드 → 설계, 재문서화 | 역공학 |
| 재사용은 재공학 활동이 아님 | 동일 |
| 해킹은 재공학 목표 아님 | 동일 |
| 소프트웨어 위기를 유지보수 생산성으로 해결 | 재공학의 목적 |
| 모델링은 유지보수 단계에서만 쓰는 것이 아님 | `reengineering.md` 9절 |

## 재사용

| 강의 표현 | 스킬 용어 |
|-----------|-----------|
| 재사용(Reusability) | 재사용 (`reuse.md`) |
| 합성 중심(Composition-based) / 생성 중심(Generation-based) | 동일 |
| 가장 많이 재사용되는 요소: 소스 코드 | 동일 |
| 부품이 작을수록 재사용률 높음 | 동일 |
| 재사용 효과와 거리가 먼 것: 사용자 책임·권한 부여 | 재사용과 무관한 것 |

## 형상 관리·테스트 (다른 스킬에서 가져옴)

| 강의 표현 | 스킬 용어 |
|-----------|-----------|
| 변경 제어, 기준선 | 변경 통제, 기준선 (`sw-code-review/references/scm.md`) |
| 비교 검사(Comparison Testing) | 비교 검사: 수정 전후 출력 비교 (`sw-test/references/black-box.md`) |
