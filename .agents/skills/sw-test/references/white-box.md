# 화이트박스 테스트

프로그램 **내부 구조**를 알고 수행하는 테스트다. 제어 흐름, 조건문, 반복문, 변수의 정의와 사용을 직접 검사한다. 모든 문장이 최소 1회 실행되고 모든 분기가 참·거짓 양쪽으로 실행되도록 케이스를 설계한다. 개발 초기(단위 테스트)에 적용한다.

## 1. 기초 경로 검사 (Basic Path Testing)

Tom McCabe가 제안했다. 절차의 논리적 복잡도를 수치화하고, 그 수만큼의 독립 실행 경로를 정의해 각 경로를 최소 1회 실행하는 케이스를 만든다.

### 1.1 제어 흐름도 (Control Flow Graph, CFG)

| 요소 | 의미 |
|------|------|
| 노드(node) | 명령문 하나, 또는 분기 없이 순서대로 실행되는 명령문 묶음 |
| 간선(edge) | 제어가 이동하는 방향 |
| 영역(region) | 노드와 간선으로 둘러싸인 면. 그래프 바깥 영역도 1개로 센다 |
| 술어 노드 | 조건을 평가해 간선이 2개 이상 나가는 노드 |

기본 구조의 그래프:

```
순차            선택(if-else)        반복(while)         반복(do-while)      다중 선택(switch)

 (1)               (1)                 (1)◄──┐              (1)◄─┐               (1)
  │               ╱   ╲                 │    │               │   │            ╱  │  ╲
 (2)            (2)   (3)              (2)   │              (2)  │          (2) (3) (4)
  │               ╲   ╱               ╱  ╲   │               │   │            ╲  │  ╱
 (3)               (4)              (3)  (4)─┘              (3)──┘              (5)
                                     │                        │
                                    (5)                      (4)
```

- if-else: 술어 노드에서 둘로 갈라졌다가 반드시 다시 합류한다. if만 있고 else가 없어도 "건너뛰는 간선"이 있으므로 영역은 같다.
- while: 술어 노드가 먼저 나오고, 본체가 끝나면 술어로 돌아오는 간선이 있다. 0회 실행이 가능하다.
- do-while: 본체가 먼저, 술어가 나중. 최소 1회 실행된다.
- for: 초기화 → 조건 → 본체 → 증가 → 조건. CFG는 while과 같은 모양이다.
- switch: 술어 노드에서 case 수만큼 갈라졌다가 합류한다. fallthrough가 있으면 case 사이에 간선이 추가된다.

### 1.2 순환 복잡도 (Cyclomatic Complexity)

세 가지 계산법. 서로 같아야 한다.

| 방법 | 공식 | 설명 |
|------|------|------|
| 1 | V(G) = E − N + 2 | E 간선 수, N 노드 수 |
| 2 | V(G) = 영역 수 | 바깥 영역 포함 |
| 3 | V(G) = P + 1 | P = 단순 조건 수. if, while, for, 각 case, 그리고 복합 조건 안의 `&&`, `||` 각각 |

의미:
- 독립적으로 실행될 수 있는 **최소 경로 개수**
- 모든 문장을 최소 1회 실행하기 위해 필요한 **최소 테스트 케이스 수**
- 값이 높을수록 복잡하고 오류 가능성이 높다. **10을 넘으면 리팩터링을 권고**한다.

### 1.3 독립 경로

독립 경로는 이전까지의 경로 집합에 없던 간선(또는 조건의 새로운 참·거짓 결과)을 적어도 하나 포함하는 경로다. V(G)개를 고르면 모든 간선이 최소 1회 덮인다. 고르는 요령:

1. 가장 짧은 경로(모든 조건을 거짓으로, 또는 가장 먼저 반환하는 경로)를 첫 번째로 잡는다.
2. 첫 경로에서 술어 노드 하나의 결과만 뒤집어 두 번째 경로를 만든다.
3. 술어 노드를 하나씩 바꿔 가며 V(G)개가 될 때까지 반복한다.
4. 반복문은 0회 실행 경로와 1회 실행 경로를 각각 포함시킨다.

### 1.4 작업 예: calculateGrade

```java
 1  public String calculateGrade(int score) {
 2      if (score < 0 || score > 100) {        // 조건 1, 2
 3          return "INVALID";
 4      }
 5      if (score >= 90) {                      // 조건 3
 6          return "A";
 7      } else if (score >= 80) {               // 조건 4
 8          return "B";
 9      } else if (score >= 70) {               // 조건 5
10          return "C";
11      }
12      return "F";
13  }
```

제어 흐름도 (노드 번호는 실행 단위):

```
          ┌───────────────┐
          │ N1: score<0 ? │
          └──┬────────┬───┘
         true│        │false
             │   ┌────▼──────────┐
             │   │ N2: score>100?│
             │   └──┬────────┬───┘
             │  true│        │false
          ┌──▼──────▼──┐  ┌──▼───────────┐
          │ N3: INVALID│  │ N4: score>=90?│
          └─────┬──────┘  └──┬────────┬───┘
                │        true│        │false
                │        ┌───▼──┐  ┌──▼───────────┐
                │        │N5: A │  │ N6: score>=80?│
                │        └───┬──┘  └──┬────────┬───┘
                │            │    true│        │false
                │            │    ┌───▼──┐  ┌──▼───────────┐
                │            │    │N7: B │  │ N8: score>=70?│
                │            │    └───┬──┘  └──┬────────┬───┘
                │            │        │    true│        │false
                │            │        │    ┌───▼──┐  ┌──▼───┐
                │            │        │    │N9: C │  │N10: F│
                │            │        │    └───┬──┘  └──┬───┘
                │            │        │        │        │
          ┌─────▼────────────▼────────▼────────▼────────▼─────┐
          │                    N11: 종료                       │
          └───────────────────────────────────────────────────┘
```

계산:

| 방법 | 값 |
|------|----|
| 노드 N | 11 |
| 간선 E | 15 (N1→N2, N1→N3, N2→N3, N2→N4, N3→N11, N4→N5, N4→N6, N5→N11, N6→N7, N6→N8, N7→N11, N8→N9, N8→N10, N9→N11, N10→N11) |
| V(G) = E − N + 2 | 15 − 11 + 2 = **6** |
| 단순 조건 P | `score<0`, `score>100`, `>=90`, `>=80`, `>=70` = 5 → P + 1 = **6** |
| 영역 수 | 6 (N1-N2-N3 사이, N2-N4-…-N3 사이, N4-N5-N6, N6-N7-N8, N8-N9-N10, 바깥) = **6** |

세 값이 일치한다. 독립 경로 6개와 케이스:

| 경로 | 노드 순서 | 입력 | 기대 결과 |
|------|-----------|------|-----------|
| P1 | N1→N3→N11 | score = −1 | "INVALID" |
| P2 | N1→N2→N3→N11 | score = 101 | "INVALID" |
| P3 | N1→N2→N4→N5→N11 | score = 95 | "A" |
| P4 | N1→N2→N4→N6→N7→N11 | score = 85 | "B" |
| P5 | N1→N2→N4→N6→N8→N9→N11 | score = 75 | "C" |
| P6 | N1→N2→N4→N6→N8→N10→N11 | score = 50 | "F" |

`||`로 묶인 조건 1과 2는 단락 평가 때문에 별도 간선을 가지며, 그래서 P1과 P2가 서로 다른 독립 경로다. 조건을 `if (score < 0) … if (score > 100) …`으로 나눠 써도 V(G)는 같다.

## 2. 조건 검사 (Condition Testing)

복합 조건 안의 각 단순 조건이 전체 결과를 독립적으로 결정하는 조합을 고른다. `a > 10 && b < 5`:

| a > 10 | b < 5 | 결과 | 목적 |
|--------|-------|------|------|
| 참 | 참 | 참 | 기준 |
| 거짓 | 참 | 거짓 | a가 결과를 바꾸는가 |
| 참 | 거짓 | 거짓 | b가 결과를 바꾸는가 |

n개 단순 조건이면 n+1개 조합으로 충분하다. 모든 2^n 조합을 돌릴 필요는 없다.

## 3. 루프 검사 (Loop Testing)

| 루프 종류 | 케이스 |
|-----------|--------|
| 단순 루프 (최대 n회) | 0회, 1회, 2회, m회 (m < n), n−1회, n회, n+1회 |
| 중첩 루프 | 가장 안쪽을 단순 루프로 검사하되 바깥은 최소값 고정 → 안쪽을 전형값 고정하고 바로 바깥을 단순 루프로 → 바깥으로 올라감 |
| 연결 루프 | 서로 독립이면 각각 단순 루프로. 한 루프의 결과가 다음 루프의 횟수를 정하면 중첩으로 취급 |
| 비구조적 루프 | 테스트하지 않는다. 구조적 루프로 재구성을 요구한다 |

검출 대상: 초기화 오류, 증가·감소 오류, 종료 조건의 하나 차이(off-by-one), 반복 변수의 반복 중 수정.

## 4. 데이터 흐름 검사 (Data Flow Testing)

변수마다 **정의(define)** 지점(값 대입)과 **사용(use)** 지점(읽기)을 찾아 모든 정의-사용 쌍을 지나는 경로를 1회 이상 실행한다.

| 점검 | 질문 |
|------|------|
| 정의 전 사용 | 초기화 전에 읽는 경로가 있는가 |
| 사용 없는 정의 | 대입했지만 읽지 않는 값이 있는가 (죽은 저장) |
| 재정의 | 사용 없이 두 번 대입하는가 |
| 정의-사용 쌍 | 모든 쌍이 최소 1개 케이스로 덮이는가 |

## 5. 기법 선택

| 함수 특성 | 우선 기법 |
|-----------|-----------|
| 분기가 많음 (V(G) ≥ 4) | 기초 경로 검사 |
| 복합 조건이 있음 | 조건 검사 추가 |
| 반복문이 있음 | 루프 검사 추가 |
| 변수가 여러 분기에서 대입됨 | 데이터 흐름 검사 추가 |
| V(G) > 10 | 케이스를 만들되 `sw-code-review`에 리팩터링 권고 |
