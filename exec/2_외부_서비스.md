# 런크크 외부 서비스

> 기준: main 브랜치 코드(2026-11-18). 키·비밀번호·서비스 계정 파일은 쓰지 않는다. 값은 팀에 별도 전달한다.
> 키가 비어 있으면 대부분 그 연동만 꺼지고 서버·앱은 뜬다(아래 "비었을 때").

## 1. 요약

| 서비스 | 쓰는 곳 | 하는 일 | 설정 이름 | 비었을 때 |
|---|---|---|---|---|
| 카카오 로그인 | 앱 `feature/me`, 서버 `infra/integration/auth` | 카카오 계정으로 가입·로그인, 게스트 계정 연동 | 앱 `KAKAO_NATIVE_APP_KEY`(`_DEVELOP`, `_LOCAL`), 서버 `KAKAO_APP_ID` | 카카오 로그인 거부 |
| 카카오맵 | 앱 `core/ui` (`KakaoMapSupport`) | 러닝 측정 화면 지도, 기록 상세 코스 지도 | 카카오 네이티브 앱 키(같은 키) | 격자 바탕으로 대신 그림 |
| 카카오톡 공유 | 앱 `feature/battle`, `feature/share` | 친구 대결 초대 메시지, 카드 공유. 카카오톡이 없으면 웹 공유 | 카카오 네이티브 앱 키(같은 키) | 초대 실패로 처리 |
| Google 로그인 | 앱 `feature/me`(Credential Manager), 서버 `GoogleLoginGateway` | 구글 계정으로 가입·로그인 | 앱 `GOOGLE_WEB_CLIENT_ID`, 서버 `GOOGLE_CLIENT_IDS` | 구글 로그인 거부 |
| Firebase Cloud Messaging | 앱 `firebase-messaging`, 서버 `FcmPushGateway`(HTTP v1) | 푸시 알림 | 앱 `google-services.json`, 서버 `FCM_PROJECT_ID`·`FCM_CREDENTIALS_FILE` | 알림함에만 저장, 푸시는 로그만 |
| Firebase App Distribution | CI `android:beta` | 베타 테스터에게 APK 배포(그룹 `beta-testers`) | CI `FIREBASE_APP_DISTRIBUTION_SA`(없으면 `FCM_SERVICE_ACCOUNT`) | 잡 실패 |
| Google Play Console | 사람이 업로드 | 앱 배포(비공개 테스트·출시), 앱 서명, Android vitals(비정상 종료 확인) | CI가 만든 prodRelease AAB | 해당 없음 |
| SSAFY GMS (OpenAI 호환) | 아바타 서버 `avatar-ai` | 셀카 특징 분석(`gpt-4.1-mini`), 아바타 머리 그림 생성(`gpt-image-2.5-sunburst`) | `AVATAR_GMS_KEY`, `AVATAR_GMS_BASE_URL` | 셀카 아바타 생성 실패(기본 얼굴은 됨) |
| Anthropic Claude (GMS 프록시 경유 가능) | ai 서버 `comment`, `coach` | 런바디 AI 코멘트, AI 코치 대화(기본 모델 `claude-haiku-5-5`) | `RUNKK_ANTHROPIC_API_KEY`, `RUNKK_ANTHROPIC_BASE_URL`, `RUNKK_LLM_*`, `RUNKK_COACH_*` | 코멘트는 규칙 문구로 대신, AI 코치 503 |
| OpenAI (선택) | ai 서버 | `RUNKK_LLM_PROVIDER=openai`일 때 AI 코멘트 | `RUNKK_OPENAI_API_KEY` | 쓰지 않으면 필요 없음 |

| Let's Encrypt | `infra/init-letsencrypt.sh`, certbot | HTTPS 인증서 | 관리자 이메일(발급 때 인자) | HTTP 모드 |

| 외부 가동 감시(UptimeRobot 등) | 서버 밖 | `/actuator/health` 5분 간격 확인 | 팀 계정 | 해당 없음 |

쓰지 않는 것: Apple 로그인은 없다(로그인 제공자는 `ProviderType`의 KAKAO·GOOGLE 두 개). 앱에 크래시 수집 SDK는 넣지 않았다(비정상 종료는 Play Console Android vitals로 본다).

## 2. 서비스별 준비

### 2.1 카카오 (Kakao Developers)

1. Kakao Developers에서 애플리케이션을 만든다. 앱 키 중 **네이티브 앱 키**는 앱 빌드 속성 `KAKAO_NATIVE_APP_KEY`, **앱 ID**는 서버 `KAKAO_APP_ID`에 넣는다. 서버는 앱이 보낸 액세스 토큰을 `kapi.kakao.com`에 조회해 이 앱 ID에서 나온 토큰인지 확인한다.
2. **카카오 로그인**을 켠다.
3. **플랫폼 > Android**에 패키지를 등록한다: `com.a207.runkk`(prod), `com.a207.runkk.dev`(develop), `com.a207.runkk.local`(local). 패키지마다 네이티브 앱 키가 따로면 develop·local 키를 `KAKAO_NATIVE_APP_KEY_DEVELOP`·`KAKAO_NATIVE_APP_KEY_LOCAL`에 넣는다.
4. 같은 화면에 **키 해시**를 등록한다: 디버그 키, 업로드 키, Play 앱 서명 키(Play Console > 앱 무결성 > 앱 서명에서 확인). 서명 키가 다르면 카카오 로그인이 실패한다. 마켓 URL(Play 스토어 주소)도 넣는다.
5. **카카오톡 공유**를 쓰려면 **플랫폼 > Web 사이트 도메인**에 `https://k15a207.p.ssafy.io`와 `https://k15a207.p.ssafy.io:8443`을 등록한다(초대 링크 webUrl).
6. 카카오맵 SDK는 같은 네이티브 앱 키를 쓴다. 카카오맵 제품을 켜 두었고, 계정의 일일 무료 사용량 안에서 쓴다(결제 수단 연결 없음, 2026-10-23 기록).

현재 등록 상태(2026-10-30 기록, `docs/sw/design-oo/05-08-설계-v0.14-API-외부준비.md` 6절): 운영 키 해시 5개, 베타 2개 등록. 기본(`com.a207.runkk`)·개발(`com.a207.runkk.dev`) 네이티브 앱 키 모두 디버그·릴리스 키 해시가 들어 있다(2026-10-23 실기기 확인). 키 해시를 바꾸면 이 문서도 고친다.

### 2.2 Google (Google Cloud Console)

1. OAuth 동의 화면을 설정한다. 테스트 모드로 두면 테스트 사용자로 등록한 계정만 로그인된다. 런크크는 동의 화면을 프로덕션으로 게시해 두어 누구나 Google 계정으로 로그인할 수 있다(2026-11-18 팀 확인).
2. **웹 애플리케이션** OAuth 클라이언트 ID를 만든다. 이 ID를 앱 `GOOGLE_WEB_CLIENT_ID`에 넣는다(Credential Manager가 이 ID로 ID 토큰을 받는다).
3. **Android** OAuth 클라이언트를 패키지·서명 지문(SHA-1)마다 만든다(prod, dev, 필요하면 local).
4. 서버 `GOOGLE_CLIENT_IDS`에는 ID 토큰의 aud로 받을 클라이언트 ID를 쉼표로 넣는다. 서버는 `oauth2.googleapis.com/tokeninfo`로 토큰을 검증한다.

### 2.3 Firebase

1. Firebase 프로젝트를 만들고 Android 앱 `com.a207.runkk`를 등록해 `google-services.json`을 받는다(CI 변수 `GOOGLE_SERVICES_JSON`, 로컬은 `android/app/`). json에 없는 패키지(`.dev`·`.local`)는 빌드가 경고만 하고 푸시 없이 만든다.
2. 서버 푸시용 서비스 계정 키(JSON)를 만들어 CI 변수 `FCM_SERVICE_ACCOUNT`에 넣는다. 배포가 `infra/secrets/fcm-service-account.json`으로 복사하고, `.env`에 `FCM_PROJECT_ID`와 `FCM_CREDENTIALS_FILE=/run/secrets/fcm-service-account.json`을 둔다.
3. 베타 배포(App Distribution)는 테스터 그룹 `beta-testers`를 만들고, 업로드 권한이 있는 서비스 계정을 `FIREBASE_APP_DISTRIBUTION_SA`에 넣는다.

### 2.4 Google Play Console

- 패키지 `com.a207.runkk`. 폰·워치 prodRelease AAB를 업로드한다(CI `android:release`·`android:play` 아티팩트). versionCode는 폰 = 파이프라인 번호 × 10, 워치 = × 10 + 1.
- Play 앱 서명을 쓴다. 앱 서명 키·업로드 키 지문을 카카오 키 해시와 `assetlinks.json`에 반영한다.
- R8 매핑 파일(`mapping.txt`)을 앱 번들 탐색기에 올리면 비정상 종료 스택을 읽을 수 있다.

### 2.5 SSAFY GMS

- 아바타 서버는 OpenAI 호환 주소(`https://gms.ssafy.io/gmsapi/api.openai.com/v1`)를 쓴다. 키는 `AVATAR_GMS_KEY`. 이미지 생성은 과금되므로 키를 채팅·커밋에 남기지 않는다.
- ai 서버의 Anthropic 호출도 `RUNKK_ANTHROPIC_BASE_URL`에 GMS 주소(`https://gms.ssafy.io/gmsapi/api.anthropic.com`)를 넣으면 GMS를 거친다. 비우면 공식 주소다. 운영·개발 서버 모두 GMS를 쓴다(2026-11-18 서버 설정 확인).

### 2.6 공공데이터포털

- 기상청 단기예보 조회서비스(`VilageFcstInfoService_2.0`, `getUltraSrtFcst`) 활용 신청 뒤 받은 서비스 키를 `KMA_SERVICE_KEY`에 넣는다.

## 3. 개인정보 관련 외부 전송

| 보내는 것 | 받는 곳 | 조건 |
|---|---|---|
| 셀카 이미지 | GMS(OpenAI 호환) | "얼굴 변환 서비스 전송" 동의 뒤. 생성 뒤 원본은 지운다. ai·avatar는 셀카를 디스크에 남기지 않는다 |
| 러닝 집계값, AI 코치 질문 원문 | Anthropic(또는 GMS 프록시) | "AI 리포트와 코치용 데이터 외부 전송" 동의 뒤. 동의가 없으면 AI 코치를 쓸 수 없고 리포트는 규칙 문구로 나온다 |
| 약 1km 정밀도 좌표, 시작 시각 | 공공데이터포털 기상청 | 러닝 기록 저장마다 1회 |
| 푸시 토큰, 알림 내용 | Firebase | 알림이 생길 때 |
