#### 2.1.10.5 WithdrawalService.withdrawIdleGuests(now)와 CrewWithdrawalListener의 크루장 처리

설계 위치: 6.1.2 WithdrawalService, 6.1.7 CrewWithdrawalListener, D-118·D-141, FR-200

```
withdrawIdleGuests(now):                                  CrewWithdrawalListener.onMemberWithdrawn(e) 크루장 부분:
    guests ← findIdleGuests(now − GUEST_IDLE_LIMIT(365일))      IF 활성 소속 없음 THEN 나머지 정리만
    count ← 0                                                IF 역할 ≠ LEADER THEN 소속 행 삭제(운영진 역할도 사라짐)
    FOR g IN guests                                          ELSE IF 다른 활성 구성원 없음 THEN CrewDeletion.deleteAll
        FOR guard IN idleGuards                              ELSE 후임 ← 운영진 있으면 운영진 중, 없으면 크루원 중 가입일 최소
            IF guard.check(g.id) 있음 THEN 건너뜀(다음 게스트)      transferLeadership, 감사 LEADER_TRANSFER(SYSTEM), 알림 LEADER_TRANSFERRED
        g.withdraw(now); 감사 WITHDRAWAL("system:idle-guest", SYSTEM); MemberWithdrawn 발행; count + 1
    RETURN count
```

#### 2.1.10.6 Crew.appointManager·dismissManager와 운영진 상한

설계 위치: 6.1.7 Crew·CrewMembership·CrewService, 5.3 운영진 2명 상한 행, D-98, FR-204

```
appointManager(targetId):                              -- crew 행 잠금 안(CrewAccess.checkForUpdate), 권한은 서비스가 먼저
    m ← 활성 소속(targetId)
    IF m 없음 THEN THROW TARGET_INVALID
    IF m.role = LEADER THEN THROW TARGET_INVALID          -- 크루장 본인
    IF m.role = MANAGER THEN THROW TARGET_INVALID         -- 이미 운영진
    IF 활성 운영진 수 ≥ MAX_MANAGERS(2) THEN THROW MANAGER_LIMIT
    m.appointManager()                                    -- MEMBER → MANAGER
```

제어 흐름도: N1 [소속 없음?] ─T─▶ N6 [TARGET_INVALID]; N2 [LEADER?] ─T─▶ N6; N3 [MANAGER?] ─T─▶ N6; N4 [운영진 ≥ 2?] ─T─▶ N7 [MANAGER_LIMIT]; ─F─▶ N5 [role ← MANAGER]; N5·N6·N7 → N8 [종료].

#### 2.1.10.8 SchedulePost.answer 다형성: MeetupPost와 CrewRunPost
