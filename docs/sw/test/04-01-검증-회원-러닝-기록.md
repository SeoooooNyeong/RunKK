## 4. 검증 테스트 (요구 기반)

검증 테스트의 질문은 "사용자가 원한 그것인가"다. 기준 문서는 srs.md v0.8 3장(이 조각은 3.1 회원 관리, 3.2 러닝 측정, 3.3 기록 분석)이고, 입력 조건과 사유는 6.3 소단위 명세 1.1~3.7.2, 값의 범위·형식은 6.2 자료사전, 상태는 6.4.4 러닝 기록 전송 상태전이도, 예외 흐름은 2.6 시나리오 S-01·S-02·S-06·S-12·S-15·S-16·S-18에서 가져왔다. HTTP 상태는 설계 06-06 ApiExceptionHandler(BusinessRuleException → 409 + 사유 코드, PermissionDeniedException → 403, IllegalArgumentException → 400)와 05-03 API 목록을 따른다. 이 케이스들은 요구와 다르게 동작하는 곳을 찾으려는 것이다. 통과는 결함이 없다는 증명이 아니다.

- 구현 판정 기준: 통합 브랜치 `feature/runkk-impl` 커밋 **18442f7** (작업 트리 `S15P31A207-impl`). 이 커밋에는 백엔드 B1·B2·B3(member·notification·running·runimal·battle·realtime·가상 기록), 안드로이드 A1·A2·A3a·A4, ai 서버가 있다. analysis·profile(B5), crew·reward·avatar(B4), 안드로이드 A3b(대결·크루·Runimal·아바타 화면)는 없다
- 표 열: `시나리오`는 사용자 관점의 한 줄, `입력`은 값과 상태, `실행 조건`은 사전 상태와 기기·권한, `기대 결과`는 SRS·설계가 정한 관찰 가능한 결과다. `구현`은 `구현됨` / `부분(빠진 쪽)` / `미구현(단계)`. `대응 시험`은 18442f7의 시험 폴더를 grep해서 같은 것을 검사하는 시험이 확인될 때만 `파일이름#메소드`로 적고, 아니면 `없음`. `결과`는 모두 `미실행`
- 표는 영역마다 동치 분할 → 경곗값 → 원인-효과 결정표 → 케이스 → FR 커버 순서다. 케이스는 FR 번호 순이다
- 기대 결과를 SRS가 정하지 않았던 28개 TC는 2026-10-21에 규칙(R1 SRS 우선, R2 SRS 안 우선순위, R3 조정자 결정)으로 확정했고, 기대 결과 끝의 꼬리표와 조각 끝 "기대 결과 확정 기록" 표에 근거를 남겼다
- 기준일은 2026-10-21(수)이다. 나이는 이 날짜 기준이다
- v0.4: design-oo v0.9 반영 (2026-10-21). 설계가 v0.8(결정 D-63~D-78, CR-U01~41)과 v0.9(검증 권고 R35~R39)로 바뀐 영향만 반영했다. 기준 문서는 srs.md v0.9, design-oo.md v0.9이고 범위·기기·"문서만" 결정은 그대로다. 고친 칸 끝에 `(v0.4, D-nn)`, `(v0.4, R-nn)`, `(v0.4, TF-AN-06)`, `(v0.4, CR-U12)` 중 하나를 붙였고, 새 케이스는 "v0.4 추가 케이스" 절의 TC-4201~TC-4218이다. 구현 열의 "설계 v0.9, 코드 미반영"은 설계는 바뀌었으나 통합 브랜치 코드가 아직 따라오지 않았다는 뜻이다. 변경 목록은 "v0.4 변경 기록" 표에 있다.
- v0.6: srs.md v0.10 반영 (2026-10-22). 변경 요청 7.13(CR-01 자유런 일시정지, CR-03 가입 축소, CR-04 러너 성향 태그 삭제, CR-06 랜드마크 배경, CR-07 화면 테마, CR-09 게스트, CR-10 유효 판정 다섯째 조건)에 맞춰 기존 TC의 기대 결과를 고치거나 폐기하고, 새 케이스를 "v0.6 추가 케이스" 절의 TC-7001~TC-7153에 더했다. 고친 칸 끝에 `(v0.6, CR-nn)`을 붙였고, 폐기한 TC는 결과 열을 "폐기(v0.6, CR-nn)"로 바꿔 실행 대상에서 뺐다(번호와 옛 기대 결과는 남김). 사유 코드·enum 값·HTTP 상태는 design-oo F-v0.11 변경 명세(F.2.3·F.5.1)의 이름을 썼다. 변경 목록은 "v0.6 변경 기록" 표에 있다. v0.6 후속 정정(설계 D-142~D-166, 2026-10-22): 설계 확정으로 바뀐 기대 결과 TC 19개를 고치고(칸 끝에 `(D-nn)`) 새 케이스 22개(TC-7048~TC-7060, TC-7135~TC-7142, TC-7154)를 더했다. 폐기는 없다. 목록은 "v0.6 후속 정정" 표에 있다.
- v0.5: design-oo v0.10 반영 (2026-10-21). 설계 v0.10(결정 D-79~D-88)이 이 조각의 발견 사항 TF-VA-29·30·31을 TC-4204·TC-4215·TC-4210과 같은 값으로 확정했다. TC 기대 결과는 바뀌지 않고 해소 표시와 구현 열(설계 v0.10, 코드 미반영)만 고쳤다.
