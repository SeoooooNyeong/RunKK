### 2.2.15 화이트박스(설계 v0.11): ProximityAlertRule.evaluate·shouldSend (v0.6)

A-23 의사 코드 그대로다. 두 연산 모두 상태가 없다(D-119). v0.6 후속: D-158로 evaluate의 간격은 10ms 단위로 반올림하고, shouldSend는 앞에 "이 회에 보낸 적 없음(sinceLastSent == null)" 판정이 늘었다.

```kotlin
// 설계 v0.11 의사 코드 (A-23, D-96, D-119, D-124, D-137)
fun evaluate(gapMeters: Int?, isAlertOn: Boolean, isWatchConnected: Boolean): ProximityAlert? {
    if (!isAlertOn) return null                                            // E1 → E5
    if (!isWatchConnected) return null                                     // E2 → E5
    if (gapMeters == null) return null                                     // E3 → E5
    val g = abs(gapMeters); if (g > 100) return null                       // E4 → E5
    val c = g.coerceIn(5, 100)
    return ProximityAlert(g, (((300 + 1700 * (c - 5) / 95.0) / 10).roundToInt() * 10).ms, isAhead = gapMeters > 0)   // E6
}
fun shouldSend(previous: ProximityAlert?, next: ProximityAlert?, sinceLastSent: Duration?): Boolean {
    if (sinceLastSent == null) return next != null                          // S0 → S8 (D-158 (2), v0.6 후속)
    if ((previous == null) != (next == null)) return true                  // S1 → S2
    if (next == null) return false                                         // S3 → S4
    if (abs(next.interval - previous!!.interval) >= 100.ms) return true    // S5 → S2
    return sinceLastSent >= 2.s                                            // S6
}
```

evaluate 간선 10개: E1→E5, E1→E2, E2→E5, E2→E3, E3→E5, E3→E4, E4→E5, E4→E6, E5→E7, E6→E7. shouldSend 간선 12개(v0.6 후속: 보낸 적 없음 판정 S0과 `next != null` 반환 S8이 늘었다, D-158 (2)): S0→S8, S0→S1, S8→S7, S1→S2, S1→S3, S3→S4, S3→S5, S5→S2, S5→S6, S2→S7, S4→S7, S6→S7.

| 방법 | evaluate | shouldSend |
|------|----------|------------|
| E − N + 2 | 10 − 7 + 2 = **5** | 12 − 9 + 2 = **5** |
| 단순 조건 + 1 | 꺼짐, 미연결, 격차 없음, 100 초과 = 4, + 1 = **5** | 보낸 적 없음, 켜짐·꺼짐 변화, 계속 꺼짐, 간격 차 ≥ 100ms = 4, + 1 = **5** |
| 영역 수 | E1·E2·E3·E4 4 + 바깥 1 = **5** | S0 1, S1 1, S3 1, S5 1, 바깥 1 = **5** |
