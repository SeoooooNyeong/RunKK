### 2.1.10 v0.6 설계 결정 단위 케이스 (설계 v0.11)

설계 v0.11(부록 F 변경 명세 D-89~D-114, 설계 검증 D-115~D-141)이 더하거나 바꾼 서버 클래스의 단위 케이스다. 기대 결과는 6.1 클래스 명세의 v0.11 표시 문장, 6.2 A-03·A-12·A-17·A-24~A-28 의사코드, 5.3 동시성 행, 5.6 결정 표, 부록 F F.2 계약에서 가져왔고, 요구는 srs v0.10 3장 FR 본문과 3.0.3 권한표·3.0.4 해석 기준으로 맞췄다. 설계와 SRS가 다르면 기대 결과 칸에 따른 쪽을 적고 "(확인 필요)"를 달아 발견 사항(TF-BE-27~TF-BE-43)으로 넘겼다. 그중 TF-BE-29·31~37·41·42와 TF-BE-30·38·39의 일부는 설계 D-142~D-166이 정해 v0.6 후속에서 기대 결과를 고쳤고(고친 칸 끝에 `(v0.6 후속, D-nn)`), 새 케이스는 2.1.10.22·2.1.10.23(TC-6210~TC-6223)에 있다.

v0.11 코드는 아직 없다(통합 브랜치에 S0~S4 미반영). 그래서 화이트박스 그래프는 6.2 의사코드와 6.1 연산 규칙(사전·사후 조건 열)을 문장 순서대로 옮겨 그렸고, 코드가 들어오면 같은 경로 표로 다시 대조한다. 모든 케이스의 결과는 "미실행(구현 전)"이다. 이 절의 표는 대응 시험 열 대신 연산 열과 기법 열을 둔다(시험 이름은 코드가 생기면 기대 결과 끝에 덧붙인다).

공통 실행 조건: 인메모리 저장소, 가짜 Gateway·Messenger·NotificationService·AuditService·DomainEventPublisher(호출 기록), 커밋 뒤 실행을 흉내 내는 트랜잭션 도구, 고정 Clock N = 2026-10-22T19:00:00+09:00(목요일, Week.of(N)의 월요일 2026-10-19). 크루 기본 자료(크루 7, 정원 10): 회원 1 LEADER(가입 2026-01-01), 2 MANAGER(2026-02-01), 3 MEMBER(2026-01-15), 4 MEMBER(2026-03-01), 9는 크루 밖(OUTSIDER). 따로 적지 않으면 L = 1, M = 2, R = 3, O = 9다.

#### 2.1.10.1 RunRecord.judgeValidity(ValidityRule rule)와 ValidityRule.isBackedBy

설계 위치: 6.1.3 RunRecord·ValidityRule, 6.2 A-03 (D-94, CR-10, CR34-08)

```
judgeValidity(rule):
    IF 이미 판정함 THEN THROW IllegalStateException                     -- FR-043 재계산 금지
    wall ← Duration.between(startedAt, endedAt).minus(pausedTotal())      -- 벽시계 − 정지
    IF NOT rule.isSatisfiedBy(distance, elapsed, averagePace, track.maxSegmentSpeedKmh(pauses))
        valid ← false
    ELSE IF NOT rule.isBackedBy(distance, track.pathLength(pauses), elapsed, wall)
        valid ← false
    ELSE
        valid ← true; score ← RunningScore.of(distance, elapsed)
    판정함 표시; RETURN valid

isBackedBy(declared, path, elapsed, wall):
    RETURN declared ≤ path × 2.0 AND elapsed ≤ wall + 1초
```

#### 2.1.10.4 SignUpService.startAsGuest(GuestStartForm form)

설계 위치: 6.1.2 SignUpService·Member.guest·attachGuestCredential, 5.3 자동 닉네임 행, D-89·D-90·D-128

```
startAsGuest(form):
    form.validate()                                   -- RequiredConsents.check: CONSENT_MISSING, UNDER_14, 받지 않는 동의 항목(HEART_RATE·FACE_TRANSFER)이 있으면 IllegalArgumentException(400, D-164)
    FOR i IN 0..19                                    -- 4자리 후보 최대 20번
        n ← Nickname.numbered(무작위 0~9999)
        IF n이 회원 닉네임·가상 닉네임과 겹치지 않음 THEN 확정, BREAK
    겹침이 20번이면 FOR j IN 0..4                      -- 5자리 후보 최대 5번(D-164)
        n ← Nickname.numbered(무작위 10000~99999)
        IF n이 겹치지 않음 THEN 확정, BREAK
    5자리도 5번 모두 겹치면 THROW BusinessRuleException(TEMPORARILY_UNAVAILABLE)   -- 503
    m ← save(Member.guest(n, consents, now))           -- 회원 ID 확정
    issued ← GuestCredential.issue(m.id, random); m.attachGuestCredential(issued.hash)   -- 같은 트랜잭션(D-128)
    감사(SIGN_UP_CONSENT, 행위자 RUNNER); tokens ← TokenIssuer.issue(m.id)
    RETURN GuestStartResult(m.id, n, tokens, issued.token)
```
