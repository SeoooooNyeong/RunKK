V(G) 세는 규칙: 단순 조건 = `if`·`else if`·`while`·`when` 갈래(마지막 갈래는 나머지 전부를 받으므로 빼고 셈)·`&&`·`||`·`?:`·`takeIf` 술어. `?.` 연쇄는 값을 null로 흘려 보낼 뿐이라 따로 세지 않고 뒤따르는 `?:`·null 검사 하나로 합친다. 코드 리뷰 약산(조건·반복·when 갈래·&&·||·?: + 1)과 같은 규칙이고, 차이가 나는 곳은 함수마다 이유를 적는다. 표준 라이브러리 안의 반복(`map`, `firstOrNull`, `MutableStateFlow.update`의 비교 교환 반복)은 호출 하나로 본다. v0.6: `coerceIn`(clamp)도 호출 하나로 보고 그 두 경계는 경곗값 케이스로 덮는다(TC-6346). 불리언 값을 돌려주는 식(`return a ≥ b`, `isAhead = gap > 0`)은 갈래가 아니라 값이므로 세지 않고 경곗값으로 본다.

### 2.2.2 화이트박스: BattleRunCoordinator.handle(run, m)

```kotlin
private fun handle(run: BattleRun, m: ServerMessage) {                      // 205
    when (m) {                                                              // N1
        is BattleStart -> run.round.scope.launch { start(run, m) }          // N2
        is OpponentProgress -> onOpponentProgress(run, m)                   // N3
        is BattleGuidance -> onBattleGuidance(run, m)                       // N4
        is CountdownStarted -> onCountdownStarted(run, m)                   // N5
        is BattleEnded -> if (m.battleId == run.battleId) finish(run, m.status)  // N6, N7
        is MatchFound, is CrewRunStart, is CrewRunCancelled, is CrewRunRelay, is CrewRunEnded -> Unit  // N8
    }
}                                                                           // N9
```

v0.4: D-65로 ServerMessage가 11종이 되어도(MatchFailed 추가) 조정자는 MatchFailed를 받지 않는다(R38, 6.1.14 onMessage). 봉인된 when을 다 덮으려면 MatchFailed를 N8 `Unit` 갈래에 넣으므로 CFG와 V(G)는 바뀌지 않는다(TC-1839).

제어 흐름도:


### 2.2.4 화이트박스: UploadPendingRunsUseCase.invoke()와 private uploadLateHeartRates()

v0.5: 설계 v0.10(D-80)이 이 UseCase를 보관 기록 반복(invoke)과 늦은 심박 항목 반복(private uploadLateHeartRates)으로 나눴다. 늦은 심박을 서버로 보내는 유일한 주체라는 점(D-77, R37)은 그대로다. 코드(18442f7)에는 늦은 심박 항목이 아직 없어 아래 그래프는 설계 문장(6.1.14)을 옮긴 의사 코드 기준이다. v0.4 TF-AN-19의 R3 결정 셋(목록 읽기 실패는 Failed(null, error), 그 밖 거부도 남기고 Failed, 성공한 항목은 결과를 더하지 않음)은 설계 v0.10이 그대로 채택했다.

```kotlin
// 설계 v0.10 의사 코드 (D-80)
suspend operator fun invoke(): List<UploadOutcome> {
    val runs = when (val p = pendingRuns.pending()) {                          // N1
        is Failure -> return listOf(Failed(null, p.error))                      // N2 (항목 반복도 하지 않는다)
        is Success -> p.value
    }
    val results = mutableListOf<UploadOutcome>()
    runs.forEach { run ->                                                       // N3
        val up = remote.upload(run)
        if (up is Failure) { results += Failed(run.recordId, up.error); return@forEach }   // N4, N5
        val kind: Sent 또는 AlreadySaved
        var appended: Outcome<Unit> = Success(Unit)
        if (up.value.alreadySaved) {                                            // N6 (한 번만 검사)
            kind = AlreadySaved
            if (run.heartRates.isNotEmpty())                                    // N7
                appended = remote.appendHeartRates(run.recordId, run.heartRates)   // N8 (심박이 없으면 N9)
        } else kind = Sent                                                      // N10
        val removed = if (appended is Failure) appended                         // N11, N12
                      else pendingRuns.remove(run.recordId)                     // N13
        results += if (removed is Failure) Failed(run.recordId, removed.error)  // N14, N15
                   else kind(run.recordId)                                      // N16
    }
    return results + uploadLateHeartRates()                                     // N17
}

private suspend fun uploadLateHeartRates(): List<UploadOutcome> {
    val items = when (val l = pendingRuns.pendingLateHeartRates()) {            // L1
        is Failure -> return listOf(Failed(null, l.error))                      // L2
        is Success -> l.value
    }
    val results = mutableListOf<UploadOutcome>()
    items.forEach { item ->                                                     // L3
        val sent = remote.appendHeartRates(item.recordId, item.samples)
        if (sent is Success || sent.isRejected("RECORD_NOT_FOUND")) {           // L4, L5
            val removed = pendingRuns.removeLateHeartRates(item.recordId)
            if (removed is Failure) results += Failed(item.recordId, removed.error)   // L6, L7
            // 성공이면 결과를 더하지 않는다                                        // L8
        } else results += Failed(item.recordId, sent.error)                     // L9
    }
    return results                                                              // L10
}
```
