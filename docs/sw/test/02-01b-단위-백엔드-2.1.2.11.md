#### 2.1.2.11 Battle.judge(LocalDateTime now)와 decide(List inTime)

코드 위치: `battle/Battle.java:320-334`(judge), `367-372`(mayStillRun), `383-391`(awaitsDecisiveRecord), `399-421`(decide). 기준 srs.md 6.3 4.5 의사결정표, design-oo A-10. 도착 시각은 startAt + 기록상 대결 거리 도달 경과 시간이다(D-30).

```java
public Optional<Judgement> judge(LocalDateTime now) {
    if (status == BattleStatus.WAITING_START || hasForfeit()) return Optional.empty();
    List<ArrivalClaim> claims = claims();
    if (claims.stream().anyMatch(this::mayStillRun)) return Optional.empty();
    List<ArrivalClaim> inTime = arrivedInTime(claims);
    if (awaitsDecisiveRecord(inTime)) return Optional.empty();
    Map<Side, Verdict> verdicts = decide(inTime);
    boolean changed = status == BattleStatus.FINISHED && !verdicts.equals(currentVerdicts());
    return Optional.of(apply(verdicts, now, changed));
}
```

#### 2.1.2.12 Matchmaker.tick(LocalDateTime now) — 랜덤 매칭 한 바퀴 (tick·partnerOf·pairUp·resolveUnpaired)

코드 위치: `battle/Matchmaker.java:47-66`(tick), `73-81`(partnerOf), `84-100`(pair)는 18442f7의 한 연산 구조다. 기준 srs.md 6.3 4.2 표 두 개, design-oo A-06(v0.10, D-79), 활동도 11.2. v0.5부터 설계 v0.10이 한 연산이던 tick을 tick·partnerOf·pairUp·resolveUnpaired 넷으로 나눠(V(G) 4·4·4·6, 매개변수 모두 4개 이하) 연산마다 그래프를 그린다. partnerOf·pairUp·resolveUnpaired는 private이라 시험 입력은 모두 tick(now)이고 경로는 그 안에서 고른다. 코드 18442f7은 아직 partnerOf·pair만 나뉜 구조다(TF-BE-26).

```
tick(now):                                                              -- V(G) 4
    cond ← policy.matchCondition(); waiting ← queue.waitingOldestFirst(); paired ← {}
    FOR a IN waiting
        IF a.memberId ∈ paired THEN CONTINUE
        b ← partnerOf(a, waiting, paired, cond)
        IF pairUp(a, b, now) THEN paired ← paired ∪ {a, b}
        ELSE resolveUnpaired(a, cond, now)

partnerOf(a, waiting, paired, cond):                                    -- V(G) 4. 없으면 null
    FOR b IN waiting에서 a 뒤의 표 (가장 오래 기다린 순)
        IF a.canPairWith(b, cond) AND b.memberId ∉ paired THEN RETURN b
    RETURN null

pairUp(a, b, now):                                                      -- V(G) 4. 배정했으면 true
    IF b = null OR NOT queue.tryAssignPair(a, b) THEN RETURN false
    ok ← 새 트랜잭션(대결 저장 + announceMatch 예약)
    IF ok THEN remove(a), remove(b) ELSE release(a), release(b), 로그 random_match_failed
    RETURN true                                                         -- 커밋이 실패해도 배정은 했으므로 true

resolveUnpaired(a, cond, now):                                          -- V(G) 6
    IF a.isExpired(now, ghostAfter + 15초)                              -- 30초 초과
        IF queue.remove(a) THEN send(a, MatchFailed(MATCH_UNAVAILABLE))
    ELSE IF a.isExpired(now, ghostAfter)                                -- 15초 초과
        IF queue.tryAssign(a)
            ok ← 새 트랜잭션 GhostMatcher.match(a, now)
            IF ok THEN remove(a) ELSE release(a), 로그 ghost_match_failed
```
