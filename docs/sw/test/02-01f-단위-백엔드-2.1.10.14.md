#### 2.1.10.16 TierReconcileService.reconcile(now)

설계 위치: 6.1.3 TierReconcileService, 6.2 A-27, D-108. 반환 값은 6.1.3 문장("새로 반영한 유효 기록 건수", v0.11 정리)을 따랐다. A-27 의사코드는 보정한 회원 수라 다르다(확인 필요 TF-BE-40).

```
reconcile(now):
    members ← savedBetween((now.date − 2일) 0시, now)의 유효 기록 회원
    fixed ← 0
    FOR m IN members                                       -- 회원마다 REQUIRES_NEW
        TRY
            applied ← appliedValidRunCount(m)
            IF running 유효 기록 수 ≤ applied THEN CONTINUE
            FOR r IN validRunsAfter(m, applied)                -- 저장 순
                recordValidRun(m, RunScoreInput(r.score, r.distance, r.ordinal)); fixed ← fixed + 1
        CATCH → 로그 tier_reconcile_failed 뒤 다음 회원
    RETURN fixed
```

#### 2.1.10.22 JpegMetadataStripper.strip와 PhotoUpload (D-142, NFR-042)

설계 위치: 6.1.7 PostPhoto·PhotoUpload·JpegMetadataStripper, D-142 (2), 7.13.5 TF-SY-25. v0.6에서는 서버 안에 위치 메타데이터를 지우는 클래스가 설계에 없어 케이스를 만들지 않았다(TF-BE-42). 설계 v0.11이 D-142로 crew 패키지 전용의 상태 없는 순수 Java 클래스 `JpegMetadataStripper.strip(byte[])`와 `PhotoUpload` 생성자 검사 순서(크기 ≤ 1MB → 머리 FF D8 FF → strip, 깨졌으면 UNSUPPORTED_IMAGE 422)를 정해 이 절을 더했다. 코드가 없어 그래프는 6.1.7 연산 규칙 문장("SOI 뒤 SOS 전까지 마커를 차례로 읽어 APP1·APP13·COM을 빼고 나머지 세그먼트와 SOS 뒤 영상 자료는 그대로 잇는다. 마커·길이가 깨졌으면 UNSUPPORTED_IMAGE")으로 그렸다. 마커: SOI FF D8, APP0 FF E0(JFIF), APP1 FF E1(EXIF·XMP), APP2 FF E2(ICC), APP13 FF ED(IPTC), APP14 FF EE, COM FF FE, DQT FF DB, SOF0 FF C0, DHT FF C4, SOS FF DA, EOI FF D9.

```
strip(jpeg):
    out ← SOI;  pos ← 2
    WHILE pos < 길이
        IF jpeg[pos] ≠ FF THEN THROW UNSUPPORTED_IMAGE
        marker ← jpeg[pos + 1]
        IF marker = SOS THEN RETURN out + jpeg[pos .. 끝]          -- 영상 자료는 읽지 않고 그대로
        len ← 2바이트 길이(마커 뒤)
        IF len < 2 OR pos + 2 + len > 길이 THEN THROW UNSUPPORTED_IMAGE
        IF marker ∈ {APP1, APP13, COM} THEN 건너뜀 ELSE out ← out + 세그먼트
        pos ← pos + 2 + len
    THROW UNSUPPORTED_IMAGE                                       -- SOS 없이 끝남 (설계 문장에 없음, TF-BE-44)
```

제어 흐름도: N1 [out ← SOI, pos ← 2] → N2 [남은 바이트 있음?] ─F─▶ N9 [UNSUPPORTED_IMAGE]; ─T─▶ N3 [FF 아님?] ─T─▶ N9; ─F─▶ N4 [SOS?] ─T─▶ N5 [나머지 그대로 붙여 반환]; ─F─▶ N6 [길이 깨짐?] ─T─▶ N9; ─F─▶ N7 [APP1·APP13·COM?] ─T─▶ N2(건너뜀); ─F─▶ N8 [세그먼트를 이음] → N2. N5·N9 → N10 [종료].

간선(14): N1→N2, N2→N9, N2→N3, N3→N9, N3→N4, N4→N5, N4→N6, N6→N9, N6→N7, N7→N2, N7→N8, N8→N2, N5→N10, N9→N10

| N / E | 10 / 14 |

| P + 1 | 남은 바이트, FF 아님, SOS, 길이 깨짐, 제거 대상 = 5 → **6** |
