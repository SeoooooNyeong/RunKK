## 수정 내용과 검토

- ask의 기존 일반 예외 복구 앞에서 currentCoroutineContext().ensureActive()로 요청 Job이 살아 있는지 확인한다.
- 실제 Job이 취소됐으면 상태를 쓰기 전에 취소를 전파한다. 흐름 자체의 취소·시간 초과만이면 기존 RETRY 복구 경로를 사용한다.
- 기존 부분 답·대화 ID를 유지해 재시도하고 질문을 중복 추가하지 않는다. 새 함수·의존성·실패 enum을 추가하지 않는다.
- AC-9는 상태 이력이 덮어써지는 간접 검사 대신 ViewModelStore.clear의 실제 수명 종료를 별도 시험한다. 기존 새 대화 취소 시험도 유지한다.
- AC-10은 여섯 CoachFailure를 순회하며 기존 문구와 복구 버튼의 조건을 단언한다.
- AC-1은 "AI 리포트·코치용"을 "AI 리포트와 코치용"으로 바꾼다. 확인 전 저장·취소·철회 동작을 유지한다.
- 기준 이미지: 가입 다크·라이트, 게스트 가입, 동의 설정. 설정 제목은 두 줄로 배치되며 스위치·설명과 겹치지 않음을 이미지로 확인했다.
- 정적 자가 검토: 공개 시그니처·의존 방향·취소 전파·원본 질문 취급을 유지하며 새 로그나 외부 전송은 없다. 사람 승인은 별도다.
