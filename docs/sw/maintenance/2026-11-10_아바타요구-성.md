### 1.1 요청 원문 (2026-11-10, 세 번)

> "홈화면에 아바타 나오게 만들고, 사진도 아바타 나와야 되고, 러닝 중일때 아바타 뛰는거 보여야돼, 그리고 아바타 띄울때 시간 걸리면 화면 로딩바 보여줘서 대기시켜두고 왠만하면 미리 로딩 해놓고, 거리에서 북한 도시는 제외해, 내 러너 페이지랑 아바타 꾸미기 상용급으로 피그마 디자인 제안해줘 제안 페이지에서 작업해 체형 배가 블록 피부색 낮형 이런 부가적인 설명들은 빼, 그리고 사진 올렸으면 보여주고 작업 중을 띄우거나 작업 페이지로 이동하고 나중에 다시 확인해도 된다 이런식으로 가야될거 같은데 이것도 제안 페이지 만들어줘, 그리고 아바타가 지금 이미지 공중에 떠있어, 어떤 배경이든 바닥 규격 만들어서 아바타가 바닥에 있도록 해야할거 같아"

> "아바타 상점에 들어갈 이미지도 제안해주고 아바타 옷 퀄리티는 후드집업을 기준으로 잡아, 규격에 맞춰서 디자인 옷들 아바타한테도 적용이 가능해야해"

> "배경도 뭔가 녹색이 됐는데 원래대로 돌려줘"

같은 날 사용자 결정:

| 번호 | 결정 |
|------|------|
| U-1 | 「사진도 아바타 나와야」는 셀카·앨범 사진을 올리면 무엇을 올렸는지 보여 준다는 뜻이다. AV-2를 AV-7에 합친다 |
| U-2 | 개성(120km)을 지우고 춘천(약 100km)과 강릉(약 170km)을 둘 다 넣는다. 개성을 해금한 회원은 없다 |
| U-3 | 의상 1차 범위는 규격 + PNG 자산 파이프라인 + 기존 7종(상의·하의·신발)을 후드집업 품질로 다시 그려 옮기는 것이다 |
| U-4 | 중립색(배경·카드·구분선·보조 글자)은 원래 무채색으로 되돌리고 브랜드 색만 피그마 값을 쓴다 |
| U-5 | 구현 착수 전에 설계 검증(`/sw-design`)까지 차례로 마친다(구현 작업자는 멈춤) |

| 번호 | 결정 | 바꾼 것 |
|------|------|---------|

### 1.2 측정 가능한 문장으로 다시 쓰기

| AV | 원문 요지 | 재정의 (완료 조건) |
|----|-----------|--------------------|
| AV-1 | 홈화면에 아바타 | 홈의 아바타 칸에 내 러너와 같은 Rive 전신 아바타(성별, 체형, 착용 의상, 셀카 머리, 고른 배경)가 서기 동작으로 보인다. 홈 아바타를 누르면 내 러너로 간다(FR-236 그대로) |
| AV-2 | 사진도 아바타 | AV-7에 합침(U-1) |
| AV-3 | 러닝 중 아바타 뛰는 모습 | 자유런·크루런·대결의 측정 중 화면에 내 아바타가 달리기 동작으로 보이고, 일시정지 중에는 서기 동작으로 바뀐다. 움직임 줄이기 설정이 켜져 있으면 멈춘 그림이다. (U-9) 화면에서 왼쪽(서쪽)으로 달리면 달리기 아바타를 좌우로 뒤집는다 |
| AV-4 | 시간 걸리면 로딩바, 미리 로딩 | 아바타 칸은 그릴 준비가 끝나기 전에 빈 칸이나 다른 성별 그림을 보이지 않고 로딩 표시를 보인다. 앱 시작 뒤 홈 첫 표시에서 아바타가 보이기까지 시간은 NFR-061을 따른다 |
| AV-5 | 거리에서 북한 도시 제외 | 개인 랜드마크 목록에 북한 도시가 0개다(지금 개성 하나). ~~개성 자리에 춘천·강릉을 넣는다~~ → 개성을 지우고 춘천(왕복 약 150km)을 인천과 대전 사이에 넣는다(U-7) |
| AV-6 | 내 러너·꾸미기 상용급 제안, 부가 설명 제거 | 피그마 「제안」 페이지에 내 러너(H-2)와 꾸미기(H-3)의 상용 시안을 둔다. 두 화면에서 체형·피부색 상태를 말로 풀어 쓴 표시(꾸미기 「체형 배가 볼록」「피부색 낮형」 줄, 내 러너 아바타 카드 위 칩 두 개)를 없앤다. (U-6) 근거 문장과 그 문장을 담은 체형 변화·피부톤 카드도 없앤다. 두 화면에는 아바타, 숫자(잔액·가격), 단추만 남는다 |
| AV-7 | 올린 사진 보여 주기, 작업 중, 나중에 확인 | 셀카·앨범 사진을 보내면 그 사진을 보이고 「작업 중」 상태를 띄운다. 러너가 화면을 나가도 작업은 이어지고, 다시 들어오거나 완료 알림을 누르면 결과를 본다. 실패하면 사유와 「다시 시도」를 보인다. 피그마 「제안」 페이지에 이 흐름 시안을 둔다 |
| AV-8 | 아바타가 공중에 떠 있음, 바닥 규격 | 어떤 배경(기본, 랜드마크, 카드 크기)이든 아바타 발끝이 배경의 바닥선 위에 놓인다. 바닥선 비율·그림자는 설계 [05-30](../design-oo/05-30-설계-아바타요구-성.md) 4절 수치다 |
| AV-9 | 상점에 들어갈 이미지 | 상점 칸·구매 확인의 아이템 그림을 아바타에 입히는 의상 자산과 같은 원본에서 만든다. 피그마 「제안」 페이지에 시안을 둔다 |
| AV-10 | 옷 퀄리티 = 후드집업, 규격에 맞춘 옷은 아바타에 적용 가능 | 의상 품질 기준은 코랄 집업 후드다. 규격(남녀 × 서기·달리기 × 체형 3)에 맞춘 PNG를 정해진 폴더에 넣으면 코드 변경 없이 아바타에 입혀지고 상점 그림이 나온다. 기존 7종(부위마다 번호 0~6, 상의·하의·신발 21가지)을 이 규격으로 다시 그려 옮긴다 |
| 중립색 | 배경이 녹색, 원래대로 | 배경·카드·구분선·보조 글자 색이 W1 이전 무채색(zinc 계열) 값이다. 브랜드 색(라임, 보라)은 피그마 값 그대로 |

## 2. 분류

| 순서 | 질문 | 답 |
|------|------|----|
| 1 | 요구·환경 그대로인데 동작이 명세와 다른가 | 일부 예. AV-8(아바타가 떠 있음)은 FR-162 「아바타와 함께 선택한 배경을 보인다」의 품질 결함이지만, 바닥선 규격이 요구에 없으므로 규격을 새로 정하는 일이 대부분이다. AV-5(개성)는 코드가 srs 3.3.1 표와 같으므로 결함이 아니다 |
| 2 | 요구 그대로인데 운영 환경이 바뀌어 안 되는가 | 아니오 |
| 3 | 요구사항이 바뀌는가 | 예. 홈 Rive, 러닝 중 아바타, 미리 로딩, 셀카 흐름, 랜드마크 목록, 의상 규격, 중립색 |
| 4 | 장래를 위한 구조·문서 개선인가 | 일부(의상 자산 파이프라인은 다음 의상 추가 비용을 줄인다). 그러나 요구 변경이 먼저다 |

유형: **개선 보수**. 버전 영향: MINOR. `/sw-srs` 회귀(srs v0.31 → v0.32, 2026-11-14 병합). 별도 견적은 하지 않는다(사용자가 범위를 정했고 일정은 Jira -300 하위로 관리).

AV-5 판단: 개성 삭제는 코드가 명세(3.3.1)와 같으므로 수정 보수가 아니라 **운영 기준값(랜드마크목록) 정책 변경**이다. 운영 기준값 변경이라 FR-201·FR-202 본문은 그대로이고 3.3.1 표만 바뀐다. 다만 이미 해금한 배경은 유지한다는 FR-201 규칙의 예외(북한 도시 행은 지운다)를 하나 더하므로 따로 나누지 않고 개선 보수 CR 하나(CR-191)로 둔다. 해금자는 0명(U-2)이라 자료 이전은 방어용이다.

AV-8 판단: 결함 성격이 있지만 고치는 방법이 「바닥 규격」이라는 새 요구라서 수정 보수로 나누지 않고 CR-194에 둔다.
