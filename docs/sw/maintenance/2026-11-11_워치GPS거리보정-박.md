# 워치 단독 자유런 GPS 거리 보정

> 작성: 2026-11-11 | 작성자: 박재영 | 입력: S15P31A207-303, S15P31A207-302, FR-032·FR-033·FR-245, NFR-007, D-368

## 접수와 분류

- 변경 요청 [임시:CR-박-1]. 기존 거리·경로 측정의 GPS 오차를 줄이는 수정 보수다.
- 요청은 “워치도 gps가 그냥 일반 폰이랑 비슷하다면 같은 방식으로 보정 해줄래?”다.
- 다음 배포 검토 범위는 워치 단독 자유런이다. 워치 실측 거리 편차와 영향 기종은 확인 전이다.

## 영향 범위와 수정

- Wear Health Services가 제공하는 좌표·수평 정확도·측정 시각을 기존 도메인 필터에 전달한다. 한 콜백에 묶여 온 위치는 측정 시각순으로 전달한다.
- 폰 자유런의 이상치 제거와 칼만 필터를 사용한다. 워치 IMU 정지 판정과 속도 정확도는 워치 필터 입력에 포함하지 않는다.
- 워치 오프라인 기록 대결은 저장할 때 자유런으로 분류된다. 측정 시작 조건에서 이를 구분해 기존 거리 계산을 적용한다.
- 보정 뒤 경로와 누적 거리만 달라질 수 있다. 서버·저장 형식·페이스 산식은 기존 계약을 적용한다.

## 회귀 조건

- 위치 점프를 보낸 뒤 정상 좌표를 역순으로 묶어서 보내면 점프를 거르고 정상 경로와 거리 기록을 이어간다. 수정 전 워치 서비스 테스트에서 점프가 경로에 포함되는 것을 재현했다.
- GPS 보정을 요청한 오프라인 대결에서도 기존 목표 도착과 기록 저장이 동작한다.
- 워치 화면, 폰 자유런, 대결, 거리·경로 공용 코드의 회귀를 Android 검증 게이트에서 확인한다.
- 실기기에서는 같은 1km 코스의 거리 오차와 화면을 끈 상태에서의 위치 수집을 확인한다.

## 상태

- Android `ktlintCheck lintLocalDebug testLocalDebugUnitTest` 통과. 워치 서비스의 점프·묶음 처리와 오프라인 대결 저장을 확인했다.
- 코드 검토에서 측정 서비스가 보정을 요청하고 도메인이 적용 대상을 판정하는 흐름을 확인했다. 위치 처리에 모듈 의존이나 저장 스키마 변경이 없다.
