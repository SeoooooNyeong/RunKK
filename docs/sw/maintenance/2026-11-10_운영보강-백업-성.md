## 1. 백업 익명 볼륨 정리 (fix/S15P31A207-275-backup-volume-cleanup, 수정 보수)

- 원인: infra/restore-check.sh, infra/offsite-backup.sh의 정리 함수가 `docker rm -f`로 컨테이너만 지워 postgres 이미지의 익명 데이터 볼륨이 남았다. `docker rm -fv`로 바꿨다.
- 경위: 2026-11-09 서버 점검에서 연결 없는 익명 볼륨 22개를 찾아 지웠다. 복구 점검이 남긴 postgres 데이터 10개(45~71MB, 복원한 운영 백업 사본일 수 있어 개인정보), 매일 오프사이트 백업이 남긴 빈 볼륨 12개(4KB). 서버에서 `docker rm -fv`가 익명 볼륨을 함께 지우는 것을 일회용 컨테이너로 확인했다.
- 운영 기록: 2026-11-09 EC2 디스크 91%. /srv/gitlab-runner/cache 브랜치 캐시 154GB를 정리해 41%가 됐다. /etc/cron.d/runkk-runner-cache-cleanup으로 매일 04:30 KST에 3일 지난 cache.zip을 자동으로 지운다.
- 관련 요구: NFR-026(탈퇴 자료 7일 안 파기), NFR-037(백업 7일 보존). 복원 사본이 익명 볼륨으로 남으면 두 요구를 어길 수 있었다.
- infra/README.md 7절(백업과 복구)에 「복구 점검과 오프사이트 복사는 끝나면 익명 볼륨까지 지운다」 한 줄을 넣는 일은 docs 밖이라 코드 MR에서 한다.

## 2. 아바타 결과 볼륨 백업 (fix/S15P31A207-300-avatar-ops, 2차 릴리스 v0.12 운영 보강)

- backup 서비스가 avatar-data 볼륨을 읽기 전용으로 붙여 매일 DB 덤프와 같은 시각에 `runkk-<환경>-avatar-daily-*.tar.gz`를 같은 폴더, 같은 7일 보존, 권한 0600으로 남긴다(배포 직전 덤프는 DB만).
- offsite-backup.sh가 묶음도 같은 26시간 규칙으로 서버 밖에 올린다(50MB를 넘으면 경고 뒤 뺀다).
- smoke.sh는 COMPOSE_PROFILES에 avatar가 있으면 avatar healthy와 ai → avatar /api/health를 확인한다.
- 요구 반영: srs v0.32 4.7 NFR-018, NFR-019, NFR-037 출처 칸에 「백업 대상에 아바타 결과 볼륨(사용자별 머리 그림)을 더한다, 서버 밖 사본은 묶음 50MB 이하일 때만」을 적었다.
