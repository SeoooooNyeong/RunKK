## 0. 범위와 검토 방식

- 대상: 핫픽스 0.11.4(MR !90)의 이벤트(코치님을 이겨라, 1km 걷거나 달리기, 알림함 진입점, 상세 웹 화면)와 운영자 공지 알림. 배포 뒤 확인(test/이벤트-성 8절)의 결과를 품질 판정에 반영하는 변경 단위 점검이다. 제품 전체 배포 판정은 아니다.
- 방식: 에이전트가 체크리스트(8절)를 순서대로 실행하고 결과를 대조했다(인스펙션 형식, 1인). 사람 FTR은 열지 않았다. 실기기 대신 에뮬레이터를 썼으므로 GPS는 에뮬레이터 콘솔(geo fix)로 넣은 값이다.
- 운영 서버 제약: 운영(443)에서는 읽기와 화면 확인만 했다. 게스트 계정 1개(러너9641)를 새로 만들었고, 「달리러 가기」를 눌렀을 때 자유런 측정이 곧바로 시작되어 2초 만에 「러닝 취소」(기록 없음)로 끝냈다. 러닝 기록 저장, 셀럽런 대결, 응모, 포인트 지급은 운영에서 하지 않았다.
- 데이터를 만드는 항목(1km 기록 저장과 응모, 셀럽런 승리와 500P)은 develop 서버(8443)와 develop 빌드에서 게스트 계정(러너1699)으로 했다. 운영자 공지 발송과 운영자 토큰이 필요한 항목은 실행하지 않았다.
- (v0.12 보완) 2026-11-09 오후에 18항(알림함 공지와 링크 열기)만 따로 확인했다. 관리 API로 보내지 않고 develop DB(runkk-develop-postgres-1)에 NoticeService와 V35_3이 만드는 모양 그대로 공지 알림 행 1건(notification id 16, 받는 회원 러너1699 id 11, 종류 NOTICE, 제목 「이벤트 당첨 안내 시험」, 대상 EXTERNAL_LINK, 대상 ID https://forms.gle/runkkTest)을 넣고 develop 앱 0.11.4-dev로 보았다. 운영자 토큰과 자격 증명은 쓰지 않았고 운영 서버와 운영 DB는 건드리지 않았다. 행은 지우지 않았다.

| 항목 | 결과 | 남은 것 |
|------|------|---------|
| 16 공지 발송(관리 API, 감사, 점 조각 409) | 미실행(운영자 발송 필요) | TC-2770 발송 부분, TC-2774 |
| 17 공지 기기 알림(앱 앞, 뒤, 종료, 마케팅 미동의) | 미실행(운영자 발송 필요) | TC-2772, TC-2773 |

새 결함: 없음. DB 시각 9시간 차이는 결함이 아니라 운영 주의로 정리했다(3절, 2026-11-09 사용자 결정). 재집계: 치명 0, 중 0, 경 1(DF-072 열림), 운영 주의 1.

판정: **조건부**를 유지한다(확인에 사용자 미참여, 공지 발송 미확인). 조건을 다음과 같이 고친다.

1. 11/17 당첨 공지 전에 8443에서 운영자가 관리 API로 16, 17, 19항을 실행한다(0.11.4 기기와 0.11.3 기기, 앱 앞, 뒤, 종료, 점 조각 주소 409). 18항은 링크 없는 공지 한 가지만 남는다. 앱 쪽 알림함 표시와 링크 열기는 이번에 합격했으므로 발송 확인은 서버 결과, 감사 기록, 기기 알림, 옛 앱에 집중한다.
2. 기간 종료(11-16) 뒤 운영자 토큰으로 응모자 명단(15항)을 확인한다.
3. DF-072 표시 규칙을 정한다.
4. DB 시각 운영 주의: DB에 시각을 직접 넣거나 시각 조건으로 조회하는 운영 SQL은 한국 시각 기준으로 쓴다(DB 현재 시각은 UTC로 보인다). infra/README.md 운영 주의에 적었다. 판정 조건은 아니다.
