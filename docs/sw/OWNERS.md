## 3. 규칙

1. 자기 담당 파일만 고친다. 남의 파일에 고칠 것이 있으면 병합 대기 파일의 "다른 담당에게 요청"에 적는다.
2. 공용 파일은 공용 담당(이성현)만 고친다. 박재영은 넣을 내용을 병합 대기 파일의 "공용 파일 반영"에 적는다.
3. 새 번호(FR, NFR, C, D, R, CR, TC, 결함 번호)는 `[임시:FR-박-1]`, `[임시:D-성-1]` 형식으로 쓴다. 정식 번호는 병합 때 공용 담당이 매긴다. 임시 번호는 `docs/sw/` 밖(커밋 메시지, 지라, 코드 주석)에 쓰지 않는다.
4. 산출물 버전은 올리지 않는다. 조각 안의 변경 표시는 "(다음 판 변경)"으로 쓴다.
5. 경계 계약(API 명세, DTO, ERD, 패키지 인터페이스)은 제공하는 쪽 담당이 고치고, 쓰는 쪽 담당이 MR에서 승인한다. 기존 동작을 깨는 변경은 변경 요청(CR)으로 적는다.
6. 코드 MR에는 그 도메인의 문서 조각과 병합 대기 파일을 함께 올린다. 병합 뒤 공용 담당이 `/sw-sdlc merge`로 정식 번호, 공용 파일, 버전을 반영한다.

> 작성: YYYY-MM-DD | 작성자: <이름> | 스킬: <sw-srs 등>

## 고친 조각

|-----------|------|------------|------|

## 공용 파일 반영
| 파일 | 넣을 내용 |
|------|-----------|
| srs/07-11-추적표-v0.18.md | [임시:FR-박-1] 행 |
| srs.md | 머리 헤더 입력란에 <입력> |

- <담당>: <파일> <고칠 것>
