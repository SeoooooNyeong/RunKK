# AI 코치 앱 진입과 재동의 설계

> 작성: 2026-11-09 | 버전: v0.39(같은 판 보완, sw-sdlc merge) | S15P31A207-273, D-438·D-451·D-474, #241 서버 계약

| 경계 | 처리 |
|---|---|
| 런바디 | 기존 AI 코치 버튼이 코치 경로를 연다. 1차 배포 잠금은 런바디와 코치 경로에 적용한다. |
| 코치 | GET /api/v1/coach/conversations 성공 뒤 입력을 허용한다. CONSENT_REQUIRED면 G-24에서 기존 설정의 동의 관리로 이동한다. 복귀 시 서버를 다시 읽는다. |
| 설정 | G-34에서는 서버가 요구한 최신 동의를 받는다는 점을 알리고 G-35 상태에서 내용을 보여 준다. 성공 때만 복귀한다. 일반 설정에서도 같은 확인 상태를 사용한다. |
| 계정 API | PUT /api/v1/me/consents/LLM_TRANSFER?version=2. 다른 동의와 가입은 기존 요청 형식이다. |
| 코치 API | 인증 Retrofit을 재사용한다. POST /api/v1/coach/questions를 스트림으로 읽고 started·delta·done·failed를 변환한다. 화면 수집 종료는 HTTP 호출 취소로 연결한다. |

- 공용 D-438의 확정 내용은 서버가 현재 동의판을 관리하고, 앱이 최신 동의 저장 후 서버 판정을 다시 받는 방식이다. 로컬 동의 스위치 값으로 코치 허용을 판단하지 않는다.
- 네트워크 지연과 완료 없는 SSE는 재시도 가능 상태다. 현재 대화 목록은 다시 읽을 수 있고 문답 본문은 AI 서버에 있다.
- 동의 저장·대화 목록·질문 요청에는 시작한 로그인 세대를 붙인다. 질문은 목록에서 확인한 세대만 사용할 수 있다. 세대가 바뀌면 초기 전송과 401 재전송을 막는다.
- 코치에서 들어온 설정은 동의 저장 중 뒤로 가기를 막고, 현재 활성 설정 화면이 저장 성공 이벤트를 받은 때에만 돌아간다.
