이 조각은 srs v0.18의 워치 단독 러닝을 설계로 옮긴다. 지금까지 워치는 폰이 측정한 값을 보여 주고 심박만 보내는 표시 전용이었다(C-002 옛 문장, 6.1.15). v0.21부터 워치는 **워치에서 시작한 러닝을 스스로 측정·기록·전송**하고, 폰에서 시작한 러닝은 지금처럼 **동행 표시**를 한다. 이 판은 코드를 바꾸지 않은 상태에서 쓴 설계다. 이름은 새로 정하되 이미 있는 클래스는 코드 이름을 그대로 쓴다.

설계 원칙은 하나다: **측정·대결·보관 규칙은 폰과 같은 객체를 그대로 쓴다.** 폰 domain의 RunTracker·RunSession·CoachingJudge·BattleRunCoordinator·UploadPendingRunsUseCase는 생성자로 포트만 받는 순수 Kotlin(JVM) 클래스다(6.1.14 "RunTracker의 협력 객체", D-95). 워치는 이 클래스들을 다시 만들지 않고 **포트 구현만 워치용으로 바꿔 끼운다**(다형성). 같은 규칙을 두 곳에 두면 FR-245의 "측정·기록 규칙은 폰과 같다"가 코드에서 어긋난다.

**(제안)** 표시는 사용자 결정이 필요한 갈림길이다. 기본안을 적어 두었고 7절에 질문으로 모았다.

### 9.2 시험 대상 (`/sw-test`에 넘김, design-review 22.7.1)
