##### 도메인 — 측정 (domain.run)

###### RunSession
| 항목 | 내용 |
|------|------|
| 모듈 | domain.run |
| 책임 | 한 번의 러닝 측정 상태를 보관한다 |

속성: spec(RunStartSpec), startedAt(Instant), state(COUNTDOWN / RUNNING / PAUSED / LOCKED / PAUSED_LOCKED / FINISHED), distance(Distance), points(MutableList<RoutePoint>), unstable(MutableList<UnstableSegment>), heartRates(MutableList<HeartRateSample>), recentWindow(30초 포인트), lastNormalPoint, gapMeters(Int?, 대결), rank(CrewRank?, 크루런), pauses(MutableList<PauseInterval>, 닫힌 정지 구간), 열린 정지 구간의 시작 시각(Instant?, PAUSED·PAUSED_LOCKED일 때만), 마지막 재개 시각 lastResumedAt(Instant?, D-121) (v0.11, FR-194, D-93). 지금 정지 길이는 `fun currentPause(now: Instant): Duration?`(정지 중이 아니면 null)로 읽는다.

상태 전이: COUNTDOWN → RUNNING ⇄ PAUSED, RUNNING ⇄ LOCKED, LOCKED ⇄ PAUSED_LOCKED(워치 PAUSE·RESUME), PAUSED → PAUSED_LOCKED(lock), PAUSED_LOCKED → PAUSED(unlock), RUNNING·PAUSED·LOCKED·PAUSED_LOCKED → FINISHED, 자유런 RUNNING·PAUSED → FINISHED(discard, 취소, 기록 없음, v0.12 D-194). PAUSED에서 정지가 60분이 되면 RunTracker가 끝낸다(FR-195). LOCKED에서는 폰 버튼으로 정지하지 않는다(FR-194). 워치 일시정지 요청은 폰 잠금과 무관하게 받고(부록 E E-25 잠정, D-93 (4)), 잠금 중이면 잠금을 유지한 PAUSED_LOCKED로 간다. PAUSED_LOCKED에서는 폰 버튼(재개·정지)을 받지 않고 정지 한도는 PAUSED와 같다 (v0.11, D-93, D-120). 워치 요청은 pauseFromWatch·resumeFromWatch가 받고(LOCKED ⇄ PAUSED_LOCKED 포함), "정지 중"은 isPaused(PAUSED 또는 PAUSED_LOCKED) 하나로 판정한다(D-157) (v0.11, test.md v0.6 TF-AN-23)

PauseInterval(data class, domain.run): from(Instant), to(Instant). 서버 running.PauseInterval·JSON `pauses[{from, to}]`와 같은 항목이다 (v0.11, FR-194). PauseLimit(object, domain.run): `WARN_AFTER` = 55분, `END_AFTER` = 60분. SRS (제안) 값이라 소유 클래스의 상수로 둔다 (v0.11, FR-195, D-113). `val RunMode.isPausable: Boolean`(domain.run의 확장 속성, FREE만 참)이 "일시정지할 수 있는 모드인가"를 답하는 한 곳이다(FR-194) (v0.11 검증, D-137). `val RunMode.isDiscardable: Boolean`(domain.run, FREE만 참)이 "취소할 수 있는 모드인가"를 답하는 한 곳이다(FR-219) (v0.12 구현 반영, CR-14, D-194). OverspeedRule(object, domain.run): `MAX_SEGMENT_SPEED_KMH = 25.0`, `fun isOverspeed(meters: Double, from: Instant, to: Instant): Boolean`(시각 차 ≤ 0이면 거짓, 상한과 같으면 넘지 않음). 서버 ValidityRule.maxSpeedKmh와 같은 값이고 계약 파일 contract/policy/ValidityRule.txt로 서버·앱 시험이 대조한다 (v0.12 구현 반영, CR-11, D-190).

RunStartSpec(data class): mode(RunMode), cardKind(CardKind), startDevice, battleId, crewRunPostId, recordId(UUID), todayPlan(PlanSnapshot?: 목표 거리, 목표 페이스. 자유런이면 ui.run이 RecordRepository.todayPlan()에서 채운다). PlanSnapshot(목표 거리, 목표 페이스), CrewRank(순위, 인원)는 domain.run의 값이다. GuidanceContext(data class): progress(RunProgress: 경과(운동 시간, 정지 제외), 거리, 현재 페이스, 평균 페이스, 신호 상태, isLocked, isPaused, heartRate(최근 30초 안의 HeartRateSample, 없으면 null)) (v0.11, FR-034, FR-194), todayPlan, gapMeters, rank, birthYear, guidanceSettings(둘 다 SettingsRepository에서). RunProgress.heartRate는 호흡 안내 판정(FR-045)과 워치 표시가 쓴다 (v0.8, CR-U15). CoachingJudge.evaluate의 입력이고 RunTracker가 1초마다 부르는 RunCoach.guide가 만든다(design-review.md M24) (v0.11, D-95). RunProgress에 `exactDistanceMeters: Double = distance.meters.toDouble()`(반올림 전 누적 거리 m, 기본값은 사본·미리보기용)을 더한다. 표시와 진행 전송은 반올림 값 `distance`를 그대로 쓰고, 대결 도착 판정(BattleRunCoordinator·GapTracker)만 이 값을 쓴다 (v0.35 반영, D-558).

| `fun resume(at: Instant): Boolean` | 재개 | PAUSED → RUNNING, 열린 정지 구간을 at으로 닫아 pauses에 넣고 참. lastNormalPoint를 비워 재개 뒤 첫 정상 포인트는 거리를 더하지 않고, 현재 페이스 창(30초)을 비운다. PAUSED가 아니면 거짓 (v0.11, FR-194, D-93 (1)(2), A-02) |
| `fun pauseFromWatch(at: Instant): Boolean` / `fun resumeFromWatch(at: Instant): Boolean` | 워치 일시정지·재개 | pauseFromWatch: RUNNING → PAUSED, LOCKED → PAUSED_LOCKED. resumeFromWatch: PAUSED → RUNNING, PAUSED_LOCKED → LOCKED. 정지 구간·재개 처리는 pause·resume과 같다. isPausable이 거짓이거나 상태가 맞지 않으면 거짓. at은 폰 처리 시각(D-157) (v0.11, test.md v0.6 TF-AN-23, TF-AN-34) |
| `val isPaused: Boolean` | 정지 중 | state가 PAUSED 또는 PAUSED_LOCKED. onLocation·tick·finish/end·정지 한도 검사가 이것을 쓴다(D-157) (v0.11, test.md v0.6 TF-AN-23) |
| `fun lock()` | 화면 잠금 | RUNNING → LOCKED. 잠금 중 finish·설정 조작 거부(FR-182) |
| `fun hintUnlock(): Guidance` | 해제 버튼 짧게 누름 | 상태 불변. "길게 눌러 해제" 안내를 돌려준다 |
| `fun unlock()` | 해제 버튼 길게 누름 | LOCKED → RUNNING. RunTracker.onUnlockLongPressed만 부른다(FR-182) |
| `fun hintFinish(): Guidance` | 종료 버튼 짧게 누름 | 상태 불변. "길게 눌러 종료" 안내를 돌려준다(FR-181) |
| `fun finish(now: Instant): FinishOutcome` | 종료 버튼 길게 누름 | LOCKED면 rejected. 거리 0 → notSaved. 아니면 saved(CompletedRun). RunTracker.onFinishLongPressed만 부른다. PAUSED에서도 종료할 수 있고 열린 정지 구간을 now로 닫는다 (v0.11, FR-036, D-93 (5)). PAUSED_LOCKED도 LOCKED와 같이 rejected(D-157) (v0.11, test.md v0.6 TF-AN-24) |
| `fun end(now: Instant): FinishOutcome` | 조정자·자동 종료 | 화면 입력이 아니라 잠금과 무관하게 확정한다. 거리 0 → notSaved, 아니면 saved(CompletedRun). 대결 종료 신호·도착·그만두기 때 RunTracker.endRun이 부른다. 화면 연산 finish로 조정자 종료를 대신하지 않는다(design-review.md B12·B14, D-36). 정지 60분 자동 종료도 이 연산이고 열린 정지 구간을 now로 닫는다 (v0.11, FR-195, D-93 (6)) |
| `fun discard(): Boolean` | 자유런 취소 | spec.mode.isDiscardable이고 측정 중(RUNNING·PAUSED)이며 잠금 중(LOCKED·PAUSED_LOCKED)이 아닐 때만 열린 정지 구간을 버리고 FINISHED, 참. CompletedRun을 만들지 않는다. 그 밖이면 상태 불변·거짓. RunTracker.discardRun만 부른다 (v0.12 구현 반영, CR-14, FR-219, D-194) |
| `fun arrivalAt(target: Distance): Instant?` | 목표 거리 처음 도달 시각 | 대결·크루런 도착 판정 |
| `fun updateGap(meters: Int)` | 대결 격차 반영 | gapMeters 갱신. GapGuidanceRule 입력 |
| `fun updateRank(rank: CrewRank)` | 크루런 순위 반영 | rank 갱신. RankGuidanceRule 입력 |

finish·end는 CompletedRun을 RunSession 안에서 domain.run 형식(RoutePoint, UnstableSegment, HeartRateSample, PauseInterval)만으로 만든다 (v0.11, FR-036). v0.4 3.2.2의 "CompletedRun.of"는 이 동작을 가리킨다(design-review.md M32).

###### RunTracker
| 항목 | 내용 |
|------|------|
| 모듈 | domain.run |
| 책임 | 한 번의 러닝 측정 흐름을 조정한다 |
| 의존 | RunArchive, RunWatchBridge, RunCoach, MeasurementRuntime — 모두 생성자 주입(javax.inject.Inject, D-61). v0.10의 의존 8개(PendingRunRepository, UploadScheduler, WatchGateway, GuidanceOutput, LocationPermission, MeasurementHost, SettingsRepository, Clock, CoroutineScope)를 책임이 한 문장인 협력 객체 넷으로 묶었다. 일시정지·근접 알림을 얹으면 의존이 10개가 되기 때문이다. D-73(생성자 주입은 매개변수 기준에서 뺀다)은 일반 규칙으로 남기고 RunTracker에만 4개 이하를 적용한다 (v0.11, D-95, CR34-12). 시각은 MeasurementRuntime.now()에서 읽어 RunSession에 매개변수로 넘기고, 저장·늦은 심박 덧붙이기 같은 suspend 작업은 RunArchive가 applicationScope에서 돌린다. RunSession·LocationFilter는 주입받지 않고 startRun마다 새로 만들고, CoachingJudge는 RunCoach.begin(mode)이 회마다 새로 만든다(앞 회의 상태가 남지 않게) (v0.11, D-95). Clock 바인딩은 data.device의 DeviceBindings가 `Clock.systemUTC()`로, CoroutineScope는 app의 AppScopeModule이 내준다 (v0.8, CR-U13, CR-U14, CR-U24) |
| 범위 | `@javax.inject.Singleton`. 측정 상태를 가지므로 ui.run, data.device.MeasurementService, 두 조정자가 같은 인스턴스를 받아야 한다(design-review.md M49) |

v0.4의 MeasurementService가 가졌던 측정 흐름을 순수 Kotlin으로 옮긴 클래스다. Android 포그라운드 서비스(data.device.MeasurementService)는 위치 구독과 1초 시계만 하고 이 클래스의 onLocationSample·tick을 부른다(D-56). 공개 연산은 v0.10과 같고 onPauseTapped·onResumeTapped, publishWatchHome을 더한다 (v0.11, D-95, CR2-A4).

###### ProximityAlertRule, ProximityAlert
ProximityAlert(data class, domain.run): gapMeters(Int, 절댓값), interval(Duration), isAhead(Boolean) (v0.11, FR-196). ProximityAlertRule(domain.run): 격차·설정·연결로 근접 알림을 만든다(규칙 한 곳, D-96). 상수: 켜는 거리 100m, 간격 최대 2.0초·최소 0.3초, 간격 기준 거리 5~100m, 다시 보내는 간격 변화 100ms, 유지 신호 2초(모두 SRS (제안) 값이라 이 클래스의 상수, D-113). 연산 `evaluate(gapMeters: Int?, isAlertOn: Boolean, isWatchConnected: Boolean): ProximityAlert?`(v0.11 검증, D-137에서 mode 매개변수 삭제): isProximityAlertOn, 워치 연결, 격차 값 있음(대결 4종에서만 RunSession.updateGap이 채운다), |격차| ≤ 100m를 모두 만족하면 ProximityAlert, 아니면 null. 간격 = 300 + (2000 − 300) × (clamp(|격차|, 5, 100) − 5) ÷ 95 ms(앞서든 뒤처지든 같다). isAhead = 격차 > 0(격차 0은 거짓, D-124). 보내는 때는 `shouldSend(previous: ProximityAlert?, next: ProximityAlert?, sinceLastSent: Duration?): Boolean`(켜짐·꺼짐 변화, 간격 100ms 이상 변화, 그 밖에는 2초마다 유지 신호)이 판정한다(F.4.3). 두 연산 모두 상태가 없고 마지막으로 보낸 값·시각은 RunWatchBridge가 갖는다(D-119) (v0.11, FR-196, D-96, F.4.3, A-23)

속성: lowAccuracySince(Instant?).

자유런 = Split·TargetReached·Pace·Breath, 대결 = Gap·Breath, 크루런 = Rank·Breath. 추월 안내(FR-188)는 랜덤 대결이면 서버 BattleGuidance를, 기록 대결이면 BattleRunCoordinator의 GapTracker가 만들고, 두 경우 모두 RunTracker.onLeadChanged가 대결 진동 설정으로 방식을 정한다 (v0.8, TF-AN-03). 워치 근접 알림은 이 규칙 묶음이 아니라 ProximityAlertRule이 만든다(화면·음성 안내가 아니라 워치 재생 신호라서) (v0.11, D-96).

###### CompletedRun
속성: 러닝기록 항목 전부(recordId, spec의 mode·cardKind·대결ID·크루런게시글ID, 시작 일시, 경과, 거리, 경로 RoutePoint 목록, 불안정 구간, 심박 HeartRateSample 목록) + pauses(List<PauseInterval>, 자유런만) + uploadState(UploadState: NOT_SENT / SENDING) + savedAt. 경과는 운동 시간(정지 제외)이다 (v0.11, FR-036, FR-194). 연산: `purgeRoute()`, `purgeHeartRates()`. 도메인 모델이고 Room 엔티티(data.store.PendingRunEntity)와 서버 DTO(api.run.RunUploadRequest)는 각 데이터 모듈의 매퍼가 만든다. v0.4는 이 형식을 app.store에 두어 보관 모듈이 워치 모듈의 형식을 알아야 했다(design-review.md R27). v0.5는 도메인에 두어 data.store와 data.watch가 서로 모른다.

포트의 저장·네트워크·시작 연산은 모두 `Outcome<T>`(Success / Failure(AppError))를 돌려주고 예외를 도메인으로 던지지 않는다(13.2). 값 읽기(locationConsented() 등)와 Flow는 Outcome으로 감싸지 않는다 (v0.8, CR-U11).

WatchDisplay(data class, domain.run): isRunning, elapsed, distance, currentPace, heartRateBpm, todayPlan(PlanSnapshot?), notice(WatchNotice?), isPaused, isPausable (v0.11, D-111, FR-194). notice는 문구가 아니라 enum 키 WatchNotice(ALREADY_MEASURING, OPEN_RUN_SCREEN, END_ON_PHONE + AUTO_END_SOON, AUTO_ENDED)이고 data.watch가 `WatchNotice.textRes()`로 문자열 리소스를 찾아 보낸다 (v0.11, D-111, CR34-13, FR-195). isPausable은 자유런 측정 중일 때만 참이다(F.4.2) (v0.11, FR-194). isRunning이 거짓이면 워치 시작 화면용(오늘 계획)이고 notice는 시작 요청을 버렸을 때 폰이 워치에 보내는 안내다. 심박 수집 허용 여부는 도메인 값에 없고 data.watch가 설정 사본으로 채워 wear.contract 메시지에 싣는다 (v0.8, CR-U19).
