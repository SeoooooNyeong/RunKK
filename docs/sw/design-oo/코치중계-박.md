# AI 코치 중계와 재동의 서버 설계

> 작성 2026-11-09 | 다음 판 변경 | S15P31A207-241·273, D-434~440·D-450

| 구성 | 책임 |
|---|---|
| `web.coach` | 8 KiB JSON 경계, 동시 중계 50개, 60초 SSE, 종료 이벤트 한 번 |
| `aicoach` | 운영 플래그, 최신 동의와 대화 소유권 확인, 요청 임대, AI 응답 연결 |
| `infra.aicoach` | 대화 색인, KST 완료 횟수, 75초 임대와 UUID 검증 |
| `infra.integration.ai` | 내부 토큰, 헤더 대기 5초, JDK 입력 스트림으로 AI SSE 프레임 읽기 |
| `batch.aicoach` | 매일 03:10 KST에 90일이 지난 색인 정리 |

- 회원과 사용량 행은 짧은 트랜잭션에서 그 순서대로 잠근다. AI 통신 동안 DB 트랜잭션을 유지하지 않는다.
- AI의 첫 meta를 받아 색인을 저장한다. 계속 묻는 경우 요청 ID와 같은 meta만 수락한다. AI의 done을 받아 유효한 임대에 한해서 완료 횟수를 기록한다.
- 탈퇴 트랜잭션에서 로컬 색인과 사용량을 지운다. 커밋 뒤 연결을 닫고 #244의 기존 AI 파기 호출이 이어진다. LLM 동의 철회도 커밋 뒤 현재 연결을 닫으며 이후 중계를 차단한다.
- V46은 이전 동의 기록에 1판을 부여한다. 기존 LLM_TRANSFER 동의 경로에서 명시한 2판을 기록한다. 코치는 유효한 최근 2판 동의가 필요하다.
- 대화 색인은 첫 질문 40 코드 포인트와 마지막 질문 시각을 가진다. AI 서버는 별도 90일 보관 작업에서 본문을 지운다.
- 기능 플래그 기본값은 꺼짐이다. 스케줄러의 여유 스레드 기준을 유지하기 위해 기본 풀 크기를 26으로 맞춘다.
