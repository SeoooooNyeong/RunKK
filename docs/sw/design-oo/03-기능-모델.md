## 3. 기능 모델

### 3.1 DFD 재사용

srs.md 6.1의 배경도(Level 0), Level 1, Level 2(프로세스 1~7), Level 3(3.4, 3.7, 5.1, 5.2, 5.3, 5.4, 5.5, 5.6, 5.7)를 그대로 쓴다. v0.11은 srs v0.10의 프로세스 계층(5.1.5, 5.4.1~5.4.5, 5.6.1, 5.8, 6.8, 7.7 추가, 5.2.2 삭제)을 따른다 (v0.11, CR-08). 기능 모델을 새로 그리지 않는다. DFD 자체는 바꾸지 않았고, 설계에서 정한 것은 **각 프로세스가 어느 실행 단위에서 도는가**와 **어느 클래스 연산이 맡는가** 두 가지다.

| DFD 프로세스 | 실행 단위 | 이유 |
|-------------|----------|------|
| 1 회원 관리 (1.1~1.6) | 서버 (1.1은 앱의 제공자 SDK와 나눠 맡음) | 회원 파일(D1)이 서버에 있다 |
| 2.1 위치 포인트 검증, 2.2 진행 지표 계산, 2.3 코칭·구간 안내 판정, 2.6 러닝 기록 확정 | 앱 | 측정·기록은 폰이 한다(C-002). 네트워크가 끊겨도 측정이 계속되어야 한다(FR-090) |
| 2.4 워치 표시 구성 | 앱(구성) + 워치(그리기) | 워치는 표시 전용(C-002) |
| 2.5 심박 수집 | 워치(수집) + 앱(검증·전달) | 심박 센서가 워치에 있다 |
| 2.7 러닝 기록 전송 | 앱(전송) + 서버(판정·저장·날씨) | 유효 판정과 러닝 점수는 서버가 한다(FR-038) |
| 3 기록 분석 (3.1~3.7) | 서버. 3.5의 카드 그리기·공유는 앱 | 카드 이미지와 공유 인텐트는 기기 기능(C-012) |
| 4.1~4.3, 4.5~4.7 | 서버 | 대기열·대결 파일이 서버에 있다 |
| 4.4 상대 진행도 생성 | 랜덤: 서버 중계. 고스트·나와의 싸움·유명인: 앱 보간 + 서버 시각 처리. 근접알림 계산은 앱(ProximityAlertRule) | 5.6 D-05. 근접알림은 격차가 있는 폰이 계산하고 워치는 재생만 한다 (v0.11, FR-196, D-96) |
| 5 크루 관리 (5.1~5.8) | 서버. 5.8의 채팅 수신은 realtime(/ws) | 크루 채팅은 새 패키지 crew.chat (v0.11, FR-208, D-101) |
| 6 캐릭터 관리 (6.2~6.8) | 서버(6.2는 runimal, 6.3·6.6·6.7·6.8은 avatar, 6.4·6.5는 reward 패키지). 6.3의 얼굴 변환은 ai 서버 | C-011. 6.8 배경 해금은 avatar (v0.11, FR-201, D-107) |
| 7 운영 관리 (7.1~7.7) | 서버 | 7.7 신고 처리는 새 패키지 report (v0.11, FR-214, D-104) |
