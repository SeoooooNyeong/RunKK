##### 도메인 — 실시간·대결·크루런 (domain.live, domain.battle, domain.crew)

###### LiveChannel, LiveChannelProvider
LiveChannel: `suspend fun connect(): Outcome<Unit>`(핸드셰이크 거부·네트워크 실패는 예외가 아니라 Failure, CR-U11), `fun send(m: ClientMessage)`, `val messages: Flow<ServerMessage>`, `fun close()`, `val state: StateFlow<LiveState>`(CONNECTING·CONNECTED·POLLING·CLOSED, 재연결·폴링 전환을 알린다, v0.11 정리 D-131). LiveChannelProvider: `fun open(): LiveChannel`. ServerMessage(sealed interface)와 하위 메시지 11종(5.7.2, v0.8 MatchFailed 추가, v0.8 검증, R39), 앱 ProgressReport(channel, channelId, 거리, 경과, 보낸 시각 — 서버 InboundProgress와 같은 JSON 항목)는 domain.live의 값이다.

v0.11 변경 (v0.11, D-103, F.3): 서버는 회원마다 연결 하나만 두고 새 연결이 이전 연결을 닫으므로 앱은 대결·크루런·채팅이 연결 하나를 함께 쓴다. `LiveChannelProvider.open()`은 그 연결 하나에 대한 **임대**를 돌려주고, 임대의 `close()`는 자기 임대만 반납한다. 참조 수가 0이 될 때만 실제 연결을 닫는다(data.live FallbackLiveChannelProvider). 받기 Flow(messages)는 임대들이 공유하고 쓰는 쪽(조정자, ChatRoom)이 필요한 메시지만 거른다. 보내기는 `send(m: ClientMessage)`이고 ClientMessage(sealed interface)의 하위 타입은 ProgressReport(JSON type "Progress")와 ChatPresence(crewId, isPresent → JSON `present`) 둘이다. ServerMessage에 CrewChatPosted(crewId, messageId, authorId?, authorName, content, sentAt, clientMessageId), CrewChatRemoved(crewId, messageId, reason: DELETED / HIDDEN), CrewChatReactionChanged(crewId, messageId, reactions)를 더해 14종이다 (v0.11, FR-208~FR-210). ServerMessage·ClientMessage는 sealed 계층이라 한 파일에 둘 수 있다(D-112). ChatPresence의 Kotlin 이름 isPresent는 @SerialName("present")로 F.3.2의 JSON 키 present에 대응한다(D-111·D-97). BattleStart.opponentTrack의 형식은 domain.live의 TrackTable(points: List\<TrackPoint(elapsedSeconds, distanceMeters)\>)이다. domain.battle의 OpponentTrack을 쓰지 않으므로 domain.live → domain.battle이 생기지 않는다(design-review.md M39). 구현은 data.live(D-57).

###### CoordinatedRound
internal 클래스(domain.run). 대결·크루런 조정자가 함께 쓰는 "한 회"의 기반이다. applicationScope 아래 자식 범위(SupervisorJob + 직렬 디스패처, 처리되지 않은 예외는 onFailure로), 측정 여부(원자적, endRun을 한 번만), 진행값 구독(RunTracker.progress에서 경과 시간이 늘어난 값만, 화면 onProgress와 두 번 처리하지 않게), 서버 보고 재시도(네트워크·인증 실패는 1·2초 뒤 두 번 더, Rejected는 다시 보내지 않음)를 갖는다. 연산: `begin(spec, onProgress): Outcome<Unit>`, `accept(p): Boolean`, `endMeasuring()`, `cancel()`, `suspend fun report(call): Outcome<Unit>`. 같은 모듈 안이라 화살표가 늘지 않는다 (v0.11, CR2-A1).

##### 도메인 — 알림 (domain.notification)

###### PushTokenSync
| 시그니처 | 부르는 쪽 | 설명 |
|---------|----------|------|
| `fun onTokenChanged(token: String)` | data.push.RunkkMessagingService.onNewToken | LoginState.loggedIn이 참이면 PushTokenRemote.register(token)(PUT /me/push-token). 거짓이면 아무것도 하지 않는다(로그인 뒤 syncCurrent가 보낸다) |
| `suspend fun syncCurrent()` | app의 RunkkApp(앱 시작 때, LoginState.loggedIn이 참이 될 때) | PushTokenSource.currentToken()으로 지금 토큰을 읽어 로그인 상태이면 register. 실패하면 다음 앱 시작·다음 로그인 때 다시 보낸다(design-review.md E19) |

포트: PushTokenRemote(`register(token)`, 구현 api.notification), PushTokenSource(`suspend fun currentToken(): String?`, 구현 data.push.FcmPushTokenSource), LoginState(`val loggedIn: StateFlow<Boolean>`, 구현 data.session.EncryptedTokenStore). 로그인 상태를 domain.account의 SessionRepository가 아니라 자기 포트로 읽어 domain.notification → domain.account가 없다. PushTokenSync는 `@javax.inject.Singleton`이고 생성자 의존은 PushTokenRemote, PushTokenSource, LoginState, CoroutineScope(applicationScope)다. onTokenChanged는 suspend가 아니므로 등록 호출을 applicationScope에서 띄운다 (v0.8, CR-U24)(design-review.md M49). 알림 표시는 FCM 알림 메시지를 OS가 띄운다(D-43).
