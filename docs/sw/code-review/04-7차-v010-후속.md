### 1. 설계 일치

**이름·인터페이스 대조.** 설계서(v0.11)에 없는 클래스·연산이 18개 생겼다: 서버 ExcludedSegments, RejudgeState, RunRecordRejudged, RunRejudgeService, batch.running.RunRejudgeJob, RunTrack.overspeedSegments·countedLength, RunRecord.rejudgeInvalid·stops·getExcludedDistance·getExcludedElapsed, RunRecordRepository 4연산(rejudgeCandidates·findForUpdate·storeRejudgement·moveRejudgeState), ValidityRule.isOverspeed, BackgroundService.unlockReachedQuietly, RewardService·BackgroundUnlockListener.onRunRejudged. 앱 RunMode.isDiscardable, RunSession.discard, RunTracker.discardRun, OverspeedRule, HomeViewModel.onResumed, RUNKK_BOTTOM_BAR_HEIGHT. 모두 사용자 결정(CR-11·14·15)을 옮긴 것이라 코드 결함이 아니라 U7-1~U7-6으로 넘긴다.
시그니처가 바뀐 것: `ValidityRule.isSatisfiedBy(d, t, avg, maxSegmentSpeedKmh)` → `isSatisfiedBy(d, t, avg)`(시속 조건이 판정에서 구간 제외로 옮겨 감), `TotalStats(distance, elapsed, count, validDistance)` → `TotalStats(distance, elapsed, count)`(모든 값이 유효 기록만). 매개변수가 줄어 결합도는 나빠지지 않았다.

**의존 방향.** 새 import는 모두 이미 있는 화살표 위에 있다: batch.running → running(D71, 연산 하나 추가), reward → running·avatar → running(사건 경유, D-31·D18), running → member(TierApplier와 같은 RunScoreInput·MemberQueryService), 앱 ui.battle → domain.live(BattleStart, MatchFailed와 같은 쌍). 새 화살표 0, 순환 0, 설계에 없는 양방향 의존 0.

**결합도·응집도.** RunRejudgeService의 생성자 의존은 6개(저장소 2, TierApplier, MemberQueryService, DomainEventPublisher, PlatformTransactionManager)로 Fan-Out 상한 안이다. 주고받는 것은 기록 ID·RunRecord·RunScoreInput으로 데이터·스탬프 결합이다. 재판정 서비스는 "옛 무효 기록을 새 규칙으로 맞춘다" 한 가지 일이라 기능적 응집이다. RunRecord.judge는 유효 판정 한 가지 일을 judgeValidity·rejudgeInvalid 두 입구가 같이 쓰게 묶어 규칙이 한 곳에 있다(좋음). TotalStats 정리로 "무효 포함 누적"이라는 쓰이지 않는 값이 사라졌다.

**FR-043 예외의 폭.** RunRecord.rejudgeInvalid는 패키지 전용이고 "판정했고, 무효이고, 경로가 남은" 기록만 받는다(RunRecord.java rejudgeInvalid). 거리·시간 열은 여전히 `updatable = false`이고 저장소의 조건부 갱신(storeRejudgement, PENDING일 때만)만 쓴다. 예외가 RunRejudgeService 한 곳으로 좁게 닫혀 있다.

goto 등가물(라벨 break·continue, 예외로 정상 흐름 분기, switch fallthrough): 없음. ### 4. 객체지향 구현

- 캡슐화: 새 필드는 모두 private. RunRecord의 rejudgeState는 `insertable = false, updatable = false`로 엔티티 저장이 바꾸지 못하고, markRejudgeState는 패키지 전용(메모리 저장소 시험용)이다. 외부가 필드를 직접 바꾸는 코드 없음.
- 생성자: ExcludedSegments는 compact 생성자에서 목록을 복사해 불변이다. RunRecordRejudged는 record다.
- 다형성: 새 instanceof·타입 분기 없음(MatchViewModel의 `filterIsInstance<BattleStart>`는 메시지 형식으로 거르는 것이라 해당 없음).
- 절차적 스타일: RunRejudgeService의 상태는 의존과 트랜잭션 템플릿뿐이고 실행 상태는 지역 변수다(BE7-2 집계 객체화 권고).
