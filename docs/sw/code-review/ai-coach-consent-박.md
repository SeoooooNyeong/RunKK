## 기준과 범위

대상은 feature/me의 동의 변경, domain.coach, feature/record/ui.record.coach, 신규 시험, ArchitectureTest다. 기준은 저장소 컨벤션·기존 디자인 시스템, 함수 길이 50줄 권고·중첩 3·복잡도 10·스탬프 이하·Fan-Out 7이다. UiState·Actions의 값/콜백 생성자는 기존 화면의 데이터 묶음 패턴을 따르며 객체를 더 겹쳐 감싸지 않는다.

## 점검

- 설계 이름·포트 시그니처: CoachRepository.ask(id?, text): Flow<CoachEvent>, conversations(): Outcome<List<CoachConversation>>, 화면·ViewModel·상태 이름 일치.
- 의존 방향: 도메인은 코어와 코루틴만, 화면은 데이터 구현을 모른다. 하위 패키지 배치 차이는 설계 변경 요청에 남겼다.
- 오류: 스트림이 완료 없이 닫히거나 빈 답이면 RETRY. 부분 답은 남기되 완료로 표시하지 않는다. 실패를 자동 재시도하지 않는다. 목록 실패는 질문을 막지 않는다.
- 취소: CancellationException은 다시 던진다. 새 대화로 바꾸면 Job을 취소한다. 실제 화면 종료와 OkHttp 취소 연결은 후속 범위다.
- 동의: 안내 전에 true를 저장하지 않는다. 선택 항목을 필수로 바꾸지 않는다. 새 서버 동의 판을 임의로 만들지 않는다.
- 접근성: 공용 버튼·체크·스위치·입력 라벨 재사용, 오류 문구와 상태 안내 제공. 실제 TalkBack·큰 글자·키보드는 미실측이다.
- 형상: 이슈 브랜치·기준 커밋·요구 근거·diff·검증 기록이 있다. 사용자 후속 요청으로 이슈별 커밋·Draft MR을 등록하며 사람 리뷰는 아직 받지 않았다.

## 판정

판정: 조건부. 변경 범위에서 확인된 치명·중 결함 0건, 전체 Android 게이트와 1,877건 시험이 통과했다. 구조 시험 18건도 통과했다. 사람 리뷰를 아직 받지 않았고 #246은 실제 서버·제품 경로 미연결이다. Draft MR로 공유하며 기능 전체 합격, UI 디자인 확정, 실제 서비스 연동 완료로 판정하지 않는다. 실제 TalkBack·실기기 검증은 남는다.
