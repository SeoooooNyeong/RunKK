### 3. 설계 일치와 구조

- 구조 시험(`ArchitectureTest`)의 허용 표는 이번 범위에서 바뀌지 않았다(폰 154개, 워치 37개). 새 파일 `CompanionMeasure.kt`와 `WatchCarouselMotion.kt`는 `watch.ui` 안에 있고 새 import는 `core.model`(Distance, Pace), `domain.run`(HeartRateSample, RunProgress)뿐이며 둘 다 `watch.ui`가 이미 쓰던 화살표다. `PhoneLink.leadChangedAtMillis`는 `watch.link` 안의 상태 흐름이고 `WatchViewModel`(`watch.ui`)이 `phoneLink`를 읽는 기존 화살표 하나를 그대로 쓴다. 설계에 없는 화살표는 없다. 구조 시험을 돌려 154·37이 그대로인지는 이번에 확인하지 않았다.
- 결합도: `toMeasureFlow()`는 `WatchUiState` 전체를 받아 `WatchFlow`로 바꾸는 순수 변환이다(스탬프, 같은 패키지 안, 부수 효과 없음). `WatchViewModel.reduce`→`WatchUiState`→`toMeasureFlow`→`WatchFlow.Running·Paused`→화면으로 한 방향이다. 옛 화면이 쓰던 `PauseControl`·`pauseControl`은 `WatchUiState`에서 같이 지워졌고 `WatchRoot`가 변환 결과를 `WatchRunScreen`·`WatchPausedScreen`에 그대로 넘긴다. 응집도는 통신적이다. 동행 화면이 단독 측정 화면과 같은 부품을 쓰게 되어 문자열·부품 중복이 줄었다(`WatchComponents.kt` −99줄, `WatchRunDisplay.kt` −134줄, `WatchBattleScreen.kt` −138줄).
- 지운 코드의 남은 참조: `WatchRunDisplay`, `WatchBattleScreen`, `RoundIconButton`, `RunActions`, `NoticeText`, `ConnectionStatus`, `PauseControl`, `PillTone.STOP`, `RunConnectionStatus`는 `android/wear/src/main` 안에서 0건이다(grep). 지운 문자열 10개(`phone_connected`, `label_pace`, `label_heart_rate`, `paused_distance_elapsed`, `pause`, `resume`, `battle_ahead`, `battle_behind`, `battle_proximity_interval`, `battle_my_distance`)도 `R.string.` 참조가 0건이다. `paused_heart_rate`는 남겼고 `WatchRunScreen`이 쓴다. 죽은 코드 없음.
- 가운뎃점: 화면에 나오는 문자열 리터럴·리소스에 새로 들어간 가운뎃점은 없다(추가 줄 grep 결과는 KDoc 주석뿐이고 "라임 바탕·큰 이름·설명" 같은 설명 줄이다). 사용자 규칙은 화면 문구에 대한 것이므로 위반이 아니다. `strings.xml`의 새 주석 "동행 표시(폰에서 시작한 러닝, FR-042)와 측정 화면 공용"도 가운뎃점이 없다.

### 4. UI1 캐러셀(`WatchModeCarousel.kt`, `WatchCarouselMotion.kt`)

**잘된 점.** 카드 모양을 `carouselSlot(distance)` 순수 함수로 빼서 칸 사이 보간을 시험할 수 있게 했다(`WatchCarouselMotionTest` 5개). `carouselMode(index)`는 `floorMod`라 음수 번호도 순환하고, `carouselSettle`은 반 칸 안이어도 0.3칸 이상 끌면 한 칸 넘기는 규칙이 시험으로 고정됐다. `VISIBLE_SLOTS`보다 먼 카드는 그리지 않고 바깥 두 칸은 `clearAndSetSemantics {}`로 접근성 트리에서 뺐다. 가운데 카드 설명은 `"$name, $description"`을 읽고 작은 카드는 이름만 읽으며, 카드 안 글자 컬럼은 `clearAndSetSemantics {}`라 이중으로 읽지 않는다. 접힘 높이를 `revealHeight`로 주어 이름이 부드럽게 올라간다. 저전력 표시(`isAmbient`)는 `snapTo`로 바로 바꾼다(시험 `저전력 표시면 애니메이션 없이 바로 바뀐다`).

### 5. UI3 동행 표시(`CompanionMeasure.kt`, `PhoneLink`, `WatchViewModel`)

**변환 규칙(`toMeasureFlow`).** 모드를 따로 받지 않고 `isPausable`로 추정한다. 참이면 자유런(`WatchMode.FREE`)이고 멈추면 `WatchFlow.Paused`, 거짓이면 모두 `WatchMode.BATTLE`(대결·셀프·셀럽·크루런)이다. `WatchDisplay.isPausable`은 `spec.mode.isPausable` 한 곳에서 읽으므로(D-137) 도메인 쪽 근거는 하나다. 거리 차는 `proximity`가 있을 때만(앞서면 +, 뒤처지면 −) 채우고 없으면 비운다(W35 "멀면 비운다"와 일치). 계획 거리는 `planDistanceMeters`가 0 이하이면 없는 것으로 봐 무제한 고리가 된다. 워치 안내(`HoldToEnd`·`PhoneNotConnected`)가 폰 연결 끊김보다 먼저이고 폰이 보낸 문구는 띠가 된다. 시험 9개(`CompanionMeasureTest`)가 자유런·거리 차 부호·근접 없음·역전 띠·일시정지·끊김·안내 우선순위를 덮는다.

**역전 띠 2초 타이머 수명.** 타이머를 따로 두지 않고 `leadChangedAtMillis`(받은 시각)와 `now - it < LEAD_BANNER_MILLIS(2_000)` 비교로 `reduce`가 `isLeadChanged`를 낸다. 갱신은 `ticker`(1초)가 하므로 띠는 2초에서 3초 사이에 내려간다(정확히 2초가 아니다. 단독 측정의 같은 상수 주석은 "워치 단독 측정과 같다"고 적었으나 갱신 박자는 다르다, 경미). 수명은 안전하다: 값은 시각이라 낡아도 스스로 만료되고, 러닝이 끝났다는 표시를 받으면 `PhoneLink`가 `_leadChangedAtMillis`를 null로 비우며(`!display.isRunning` 가지), `reduce`도 `isRunning &&`를 같이 본다. 러닝이 아닐 때 받은 추월 메시지는 `takeIf { isRunning() }`가 막는다. 시험 `추월 역전을 받으면 역전 띠를 잠깐 띄우고 지운다(W35)`, `러닝이 아니면 추월 역전을 받아도 띠를 띄우지 않는다`가 둘 다 있다. 저전력 표시에서는 `WatchRunScreen`이 거리·시간만 그리므로 띠가 보이지 않는다. `WatchActivity`가 `companion`도 `remember(ambientTick, flow::class)`로 1분마다만 갱신해 단독 측정과 같은 박자를 쓴다. 다만 `LeadChangeMessage.kind`(OVERTOOK·OVERTAKEN)를 버리고 띠 색을 근접 값 부호로 정한다: WR15-5.

**폰 연결·안내.** `LINK_LOST`·`PHONE_NOT_CONNECTED`를 `WatchFlow.Notice`에 더하고 `noticeRes`에 짝을 맞췄다(`when`이 빠짐없이 닫힌다). 일시정지 화면은 `notice`가 먼저이고 없을 때 폰 `banner`를 띄워 정지 자동 종료 예고(FR-195)를 잃지 않는다.

**일시정지 화면의 저전력 처리.** `WatchPausedScreen`에는 `isAmbient` 인자가 없다(단독 일시정지도 같다). 폰 동행의 일시정지는 옛 화면에서도 저전력 처리가 없었으므로 이번 변경이 만든 퇴보는 아니다. 일시정지 중 저전력 표시로 들어가면 라임 원 버튼이 계속 켜져 있을 수 있어 실기에서 한 번 볼 일이다(참고, 결함으로 세지 않음).

**모드 추정의 한계.** `WatchDisplay`에 모드 필드가 없어 옛 폰 앱이 보내는 자유런은 `isPausable` 기본값(거짓)이라 대결 측정 화면(거리 차 칸 빈칸, 일시정지 없음)으로 보인다(F.4.2가 이미 "옛 폰 앱은 거짓"으로 적었다). 크루런이 대결 화면인 것도 `isPausable`이 거짓이라서일 뿐 W35가 정한 것은 아니다. 두 경우 모두 W35의 "대결 측정 화면" 설명이 모드가 아니라 일시정지 가능 여부 기준이라는 점을 설계서에 적어 두면 된다(U15-1, 코드가 맞고 문서가 비었다).

### 7. 단계별 점검 결과

**구조적 프로그래밍.** goto 등가물 없음. `carouselSettle`은 `when` 하나, `toMeasureFlow`는 `when` 하나와 가드 반환 하나(일시정지)다. 함수 중간 반복 속 return 없음. 새 함수 중 중첩 3 초과, 50줄 초과, 순환 복잡도 10 초과 없음: `ModeCard`(167-248행, 82줄)와 `WatchModeCarousel` 본문(73-159행, 약 87줄)은 50줄을 넘는다(기준상 분리 권고). 한 카드를 그리는 한 가지 일이고 중 기준(데이터 손실·크래시 등)에 해당하지 않아 결함 번호는 따로 주지 않고 WR15-1의 교정(카드 그리기와 위치 계산 분리)에서 같이 쪼개기를 권한다.
**객체지향.** 새 클래스 없음. `CarouselSlot`은 불변 `data class`, `WatchCarouselMotion.kt`의 상수·`SLOTS`는 `private`·`internal`로 가렸다. 필드 외부 수정 없음. `WatchUiState`의 `proximity`·`isLeadChanged`는 읽기 전용 값이다.
**코딩 스타일.** 이름이 역할을 드러낸다(`carouselSettle`, `DRAG_SETTLE_SLOTS`, `LEAD_BANNER_MILLIS`). 매직 넘버는 `SLOTS`와 상수 선언부에 모았다. `ModeCard` 안의 `0.1f`·`0.06f`·`10.dp`·`8f`는 줄 위 설명 없이 박혀 있다(경미, 카드 모양 비율이라 상수로 빼면 오히려 읽기 어려워 지적만 한다).
**자유런 목표 카드 크기(UI1 두 번째 커밋).** `WatchDistancePicker`가 숫자 칸을 64dp×64dp로 고정하고 `wrapContentSize(unbounded = true)`로 글자를 넘치게 둔다. 무제한(∞)과 숫자가 같은 칸이라 설명 줄과 ± 버튼이 움직이지 않는다. 가장 넓은 "10"이 60sp에서 64dp 안에 들어가는지는 주석만 있고 단언은 없다. 스크린샷 시험(`F1_watch_free_unlimited`, `F1-3_watch_free_3km`)이 그림으로 고정하나 이번에 이미지를 보지 않았다(미확인). 칸 접근성 설명은 `semantics { contentDescription = spoken }`로 칸에 붙어 읽힌다.
