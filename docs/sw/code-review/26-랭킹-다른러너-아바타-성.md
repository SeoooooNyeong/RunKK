확인한 것(문제 없음):

- 서버 `find`의 깨진 값(JSON 형식 오류, 범위 밖 체형)은 `JsonProcessingException | IllegalArgumentException`으로 그 회원만 없는 것으로 보고 다시 읽어 덮는다. `(String) value` 캐스트는 `StringRedisTemplate`이라 실패하지 않는다.
- 같은 스냅숏 첫 조회가 겹치면 둘 다 DB를 읽고 같은 값을 쓴다(멱등). 재집계는 새 `computedAt`이라 새 키다. 같은 밀리초 재집계는 키가 겹치지만 0시 배치와 관리툴 재집계가 같은 밀리초에 날 수 없다.
- 탈퇴 회원 모습은 캐시에 남아도 조회 때 `activeMemberIds`로 거른다. 머리 받기는 서버가 탈퇴(WITHDRAWN)면 거부한다. 옛 머리 키(오늘 셀카를 다시 만든 회원)는 지난 작업이 남아 있어 그대로 받는다.
- 옛 앱은 `look`을 모른 채 무시한다(`PlacementContractTest` 「필드 더하기만」). 새 앱이 옛 서버를 만나면 `look = null`로 성별 기본 모습이다(`RecordRepositoryImplTest`).
- 시상대 나(`isMine`)는 서버 스냅숏 look이 아니라 내 아바타 저장소 모습이다(설계 의도: 내 화면의 나는 지금 모습).
- `selfie:`(옛 부위 얼굴) 키의 다른 러너는 시상대에서 셀카 머리 레이어가 없어 기본 머리, 목록 원에서는 부위 얼굴이다. Rive 머리 레이어는 `head:`만 만들 수 있어 생기는 차이로 결함이 아니다.
