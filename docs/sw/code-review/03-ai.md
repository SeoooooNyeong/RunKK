- U1. Settings 항목 추가: `anthropic_api_key`, `openai_api_key`(SecretStr), `face_api_url`, `face_api_key`, `expose_docs`. 값 검증 `internal_token min_length=16`, `llm_timeout_s < 2.7`, `face_timeout_s < 15`(H-22 불변식을 설정 단계에서 막음)도 표에 적는다.
- U2. "lifespan에서 Settings를 한 번 읽고" → "create_app(settings=None)이 Settings를 한 번 읽어 app.state.settings에 두고 lifespan·verify_internal_token은 거기서 꺼낸다". 시험이 Settings를 주입할 수 있는 시그니처도 함께 적는다.
- U3. FaceTransformer.convert의 실패 채널: `FaceTransformError(reason)`(reason 6종 밖이면 생성 거부), 시간 초과는 `TimeoutError`. 서비스가 잡아 FaceResult로 바꾼다. 오류 경로에만 쓰고 한 층 위에서 잡으므로 goto 등가물이 아니다.
- U4. LlmClient: 생성자 `(model)`, `model` 읽기 속성(로그용), `aclose()`(기본 아무것도 안 함). FaceTransformer에도 `aclose()`. lifespan의 "종료 때 aclose()"가 가리키는 연산을 계약에 넣는다.
- U5. 503 LLM_UNAVAILABLE의 범위: LLM 오류 + 프로세스 하루 상한 초과 + 출력 검증 실패. 하루 경계는 KST 자정, 실패한 호출도 센다.
- U6. 422 응답 본문을 `{"reason": "INVALID_REQUEST"}`로 고정하고 입력값을 되돌려 주지 않는다(NFR-024). 계약 표본 comment-422-invalid-request.json과 같게.
- U7. ClaudeClient·OpenAiClient의 시간 제한 형식을 `httpx.Timeout`에서 SDK 재노출 형식(`anthropic.Timeout`, `openai.Timeout`)으로. anthropic SDK 1.x는 HTTP 계층이 바뀌어 httpx 형식을 직접 넘기는 것이 맞지 않을 수 있다.
- U8. FaceRouter 본문 읽기: `await request.body()` → `request.stream()`으로 누적하며 max_image_bytes를 넘는 순간 413. Content-Length가 없거나(chunked) 틀려도 상한을 지킨다.
- U9. 415 조건: "형식이 image/jpeg·image/png가 아니면" → "Content-Type이 application/octet-stream이 아니거나, 본문이 JPEG·PNG 시그니처로 시작하지 않으면".
- U10. 상태 코드 구분: 라우터 관문(입력 크기·형식) 413 TOO_LARGE·415 UNSUPPORTED_IMAGE, 변환기 보고 422 NO_FACE·MULTIPLE_FACES·UNSUPPORTED_IMAGE·TOO_LARGE, 503 UPSTREAM_FAILED, 504 TIMEOUT.
- U11. ExternalFaceApi 임시 계약(POST {base_url}, octet-stream, Bearer 키, 200 `{"parts"}`·4xx `{"reason"}`, 리다이렉트 따르지 않음)을 "C-011 선정 전 임시"로 적고, 선정 때 다시 맞춘다. 주소가 없으면 503 UPSTREAM_FAILED.
- U12. LocalSdModel: C-011 전에는 `face_impl=local`이면 기동을 거부한다고 적는다. 연결할 때 lifespan 적재·ai-face 컨테이너 분리(E-04)를 함께 한다.
- U13. FaceTransformService 성공 결과 검증: 부위 5개가 모두 있고 각각 PNG 시그니처로 시작하지 않으면 UPSTREAM_FAILED.
- U14. 0.1 표 "ai 범위: 아바타 생성·크루 추천·AI 코멘트"에 "크루 추천은 E-03 결정 전까지 api(TagOverlapRecommender)"를 덧붙인다.
- U15. **설계 공백(서버 쪽)**: 6.1.13 AiServerFaceGateway는 "422/503/504면 reason을 FailureReason으로"만 있어 ai가 내는 413·415를 다루지 않는다. "413 → TOO_LARGE, 415 → UNSUPPORTED_IMAGE"를 추가해야 한다. 서버 Gateway가 아직 없으므로(backend에 AiServer* 없음) 서버 구현 전에 반영한다. 계약 표본 face-413-too-large.json·face-415-unsupported-image.json이 이미 있다.
