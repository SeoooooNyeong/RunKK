### 1. 설계 일치

**이름·인터페이스 대조(05-11 2.3 앱 표).** 표의 모든 이름이 코드에 있다. core.model.Gender(domain.account에서 옮김, 옛 파일 삭제), AvatarCharacter·LocalAvatarCharacter, CelebrityCharacter·CelebrityFigure, RunkkRunningFigure·rememberIsMoving·runFrameMillis·rememberHeadingLeft, KakaoRunMap·RunMapMarker·KakaoMapSupport(LocalKakaoMapKey·canShowKakaoMap·ensureKakaoMap), OpponentMarkerPlacer, UnreleasedFeature(CREW·CARD_BACK·RUNIMAL_SHARE·AVATAR_CUSTOMIZE·RUNBODY), Routes.BattleRunning.opponentGender·celebrityFigure, RandomBattleGate, BattleRunCoordinator.cancel·forfeit, BattleRepository.cancel → BattleApi.cancel(`POST battles/{id}/cancel`), Dashboard.streakWeeks, NotificationGroup.requiredFeature, InboxLabels.isVisibleIn, BetaLock의 Routes.REPORT.
설계에 없는 이름: `AccountRepository.myGender: StateFlow<Gender?>`(MainActivity가 LocalAvatarCharacter를 고르는 출처, 내 프로필 읽기·편집 성공 때 갱신), `ProfileEdit.gender·birthYear`와 ProfileEditRequest 두 항목, `MatchViewModel.me: Deferred<Profile?>`·`MatchUiState.myTier`(R2-10 성사 화면 내 티어 칩), `BattleModeUiState.randomRunsLeft·isRandomLockNoticeVisible`, `OpponentKind.isCancellable`, `BattleRunningUiState.isConfirmingCancel`, `RunkkHoppingWordmark`·RunkkAppContent의 `isIntroDone`(스플래시), `GuideBubblePlacement`·`GuideTail`, `RunimalArtTile`·`RunimalTypeCellLook`, `LoginVideoBackground`, `TierName`. 모두 화면·상태 보조 이름이고 코드가 기준이다. 설계서 갱신 요청(U10-A3)으로 넘긴다.
시그니처: D-322 (1)의 RunkkRunningFigure 8개 매개변수, (2)의 KakaoRunMap 6개 매개변수가 설계 문장과 같다. D-324의 `forfeit()`·`cancel()`은 둘 다 `end { }`로 감싸 한 번만 실행되고(BattleRunCoordinator.kt:187-209), 보고(`CoordinatedRound.report`, 다시 보낼 만한 실패면 1·2초 뒤 두 번 더)가 실패해도 측정은 끝낸다. forfeit은 `finish`(endRun, 기록 저장 → Finished), cancel은 `discard`(discardRun → Discarded)다.

**취소 뒤 측정이 실제로 멈추는가(12.9 4번).** `discard` → `CoordinatedRound.discardMeasuring`(측정 중 표시를 한 번만 내림) → `RunTracker.discardRun` → `RunSession.discard`(SELF_RUN·CELEB 카드면 FINISHED) → `complete(NotSaved)`가 `runtime.stop()`(측정 서비스·위치 수집 정지), `_routeLine` 비움, `watchBridge.publishHome`(워치 시작 화면으로)을 부른다. 보관(RunArchive)·남긴 결과에 들지 않는다. 그다음 `close`가 채널을 닫고 회의 범위를 취소한다. 설계대로 멈춘다. 다만 출발 전·카드 종류 두 경우에 빈틈이 있다(AN10-1, AN10-4).

**상대 성별(D-313, D-314, D-321).** MatchFoundJson·ActiveBattleResponse·BattleResultResponse의 `opponentGender: String? = null`을 `enumByName<Gender>`로 읽고 모르는 값은 null이다. 그림은 `AvatarCharacter.of(gender)`가 FEMALE만 여자, null·MALE·UNDISCLOSED는 남자다(D-314 "null은 남자 그림" 일치). 성사 화면(MatchScreen.kt:329), 측정 화면(BattleRunningScreen.kt:453, 셀프런은 내 캐릭터), 결과 화면(BattleResultScreen.kt:209) 세 곳이 같은 함수를 쓴다. 측정 화면 경로 인자 `Routes.BattleRunning`의 두 항목은 `@Serializable` 문자열이라 백 스택 복원에 실리고, 복원된 화면은 조정자가 그 대결을 모르면 5초 뒤 실패 화면이 된다(기존 규칙). 랜덤·친구는 MatchViewModel.kt:665, 활성 대결 복구는 :468이 값을 넘긴다. 서버 쪽 사용자 결정(2026-10-31, 비공개 회원은 회원 ID 고정값, 가상 상대만 무작위, D-327 제안 채택)은 서버가 내려 주는 값만 바꾸므로 **앱은 바꿀 것이 없다**. 앱은 응답의 opponentGender를 그대로 그린다.

### 4. 객체지향 구현

- 캡슐화: 새 public 가변 필드 없음. AccountRepositoryImpl.currentGender는 private이고 밖에는 `StateFlow`로만 연다. BattleRun.isForfeiting은 이름이 "그만두기"인 채 취소에도 쓰인다(`end`). 뜻이 넓어졌으므로 `isEnding`이 맞다(경으로 세지 않고 AN10-7 교정 때 함께).
- 다형성: OpponentKind가 종류별 그만두기 문구·isCancellable·isRecord·isPerson을 enum 속성으로 둔다. AvatarCharacter·CelebrityCharacter가 그림 고르기를 enum 표로 둔다. BattleRoute의 `when { kind != CELEBRITY …; celebrity != null …; else … }`는 그림 종류 분기 한 곳이다. 같은 분기가 BattleParts.OpponentFigure에도 있어 두 곳이다(18장 6.3 기준 3곳 미만).
- 생성자: ProfileEdit은 새 두 항목에 기본값 null을 둔 불변 data class다. RunMapMarker는 `@Immutable` data class지만 람다 항목(figure) 때문에 같음 비교가 매번 거짓이다. KakaoRunMap은 이를 알고 좌표 목록만 효과 키로 쓴다(KakaoRunMap.kt:148-151 주석).
- 절차적 스타일: 새 object는 RandomBattleGate(상태 없는 판정)와 KakaoMapInit(초기화 한 번)뿐이다.
