#### 2.2 의존 방향 (Konsist 허용 표)

- 허용 표: `domain.coach → core.model`(ArchitectureTest.kt:478), `ui.record.coach → core.designsystem, core.model, domain.coach`(:539). D-455·D-474의 화살표 4개와 같다. 병합 시점(09e568dc)의 폰 합계는 150 → 154였고, 워치 v2 병합 뒤 지금 develop은 159(:56-60, 주석 :47-50)로 05-19 5절의 "155 → 159"와 맞는다. ui.record의 Fan-Out은 7 그대로, ui.record.coach 3, domain.coach 1이다.
- 같은 모듈 생성 리소스 `ui.record.R`을 읽는 것은 화살표로 세지 않는 예외로 따로 적었다(ArchitectureTest.kt:358-359). 예외가 모듈 이름과 R 한 개로 좁혀져 있어 넓은 구멍이 아니다.
- `moduleOf`는 가장 긴 접두어가 이기므로 `ui.record` 코드가 `ui.record.coach`를 import하면 표 밖 import로 걸린다. 지금 ui.record 쪽 import는 0건이다(grep). 앱 어디에서도 CoachRepository·CoachChatViewModel·CoachChatScreen을 참조하지 않는다(시험 제외). 화면은 제품 경로에 **미연결**이다(D-451, D-474 그대로).
- domain.coach는 kotlinx.coroutines Flow만 쓰고 android·retrofit·okhttp import가 없다. 순환 0.
