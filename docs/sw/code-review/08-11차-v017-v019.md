#### 범위 B에서 경으로도 올리지 않은 확인 사항

- **이름·시그니처 대조(05-14 2·3절).** RunkkBackgroundMusic(music, volume, isPlaying), LocalCoveredBySplash, LoopingMusic(player, audio)과 hasPlayed·isCounted·companion ownPlaying·open, RunkkLoopingVideo(video, modifier)·openLoopingVideo·CroppedVideoView.detach, RunkkSoundEffects(pool, loaded, volume)·play·internal release·SILENT, rememberSoundEffects·MAX_EFFECT_STREAMS = 2, RunkkSoundVolume의 네 키와 changeMusic·changeEffects·save·toggleMusic·toggleEffects·of, FirstScreenGate.isHeld(internal set)·LocalFirstScreenGate·HoldSplashUntil, RunkkLimePill(text, modifier, textStyle), FEMALE_FIGURE_SCALE = 0.9f·FEET, FIRST_SCREEN_MAX_WAIT_MS = 4_000L, isMusicRoute, SoundSection·VolumeRow(title, level, actions, tag)·VolumeActions·두 태그, CoachViewModel.onTodayPace·saveTodayPlan, CoachUiState.todayPace, CoachActions.onTodayPace, TodayPlanCard(planned, pace, onTodayPlan, onTodayPace), PACE_CHOICES = (180..600 step 10) 모두 코드와 글자 그대로 같다.
- **한 파일 한 클래스(D-112).** 새 파일 6개의 최상위 타입은 LoopingMusic, CroppedVideoView, RunkkSoundEffects, RunkkSoundVolume, FirstScreenGate, VolumeActions 하나씩이다. 파일 이름이 컴포저블 이름(RunkkBackgroundMusic.kt, RunkkLoopingVideo.kt, SoundSettings.kt)이고 클래스는 private이라 규칙 안이다.
- **재생기 해제.** LoopingMusic·ExoPlayer는 `DisposableEffect(player) { onDispose { player.release() } }`, 영상은 같은 방식에 `AndroidView(onRelease = CroppedVideoView::detach)`, SoundPool은 `DisposableEffect(effects) { onDispose { effects.release() } }`로 놓는다. 효과는 등록 역순으로 정리되므로 음악은 `onPauseOrDispose`(pause, count(false))가 release보다 먼저 돈다. `count`는 재생기마다 한 번만 더하고 빼므로 release 뒤 pause가 와도 ownPlaying이 음수가 되지 않는다. 남는 위험은 Compose `remember { }` 안에서 재생기를 만드는 것이라, 구성이 버려지면(적용 전 취소) DisposableEffect가 등록되지 않아 재생기가 남을 수 있다. 시작 화면 한두 곳에서 드물게 일어나는 일이라 올리지 않았다(고치면 LoopingMusic이 `RememberObserver`를 구현해 `onAbandoned`에서 놓는다).
- **화면 스레드와 전역 상태.** `ownPlaying`은 LoopingMusic companion의 private 값이고 ExoPlayer 호출과 함께 화면 스레드에서만 바뀐다(Compose 효과). 밖에서 읽거나 쓸 길이 없어 공통 결합이 아니다(D-346). `RunkkSoundVolume.shared`는 `@Volatile` + `synchronized` 이중 확인이고 속성은 `private set` Compose 상태라 내용 결합이 없다(D-349). 첫 `of` 호출이 화면 스레드에서 SharedPreferences 파일을 읽는다(파일 하나, 키 4개). 크기가 작아 올리지 않았다.
- **오디오 포커스.** handleAudioFocus = false라 우리 음악이 나오는 동안 사용자가 다른 앱 음악을 켜면 둘이 함께 나온다. 한 번 튼 뒤에는 다시 확인하지 않는 것이 D-346과 srs 7.13.13 FR-235 대조(처음 틀 때만 확인)의 규칙이라 결함이 아니다. 전화가 오면 액티비티가 멈춤 상태가 되어 `onPauseOrDispose`가 멈춘다. 이어폰을 뽑을 때 멈추는 처리(`setHandleAudioBecomingNoisy`)는 없다. 1차 배포 실기기 확인 항목으로 넘긴다.
- **측정 중 멈춤.** `isMusicRoute`는 맨 위 경로만 본다. 자유런 측정 중에는 RunBackHandler(RunScreen.kt:212-219)가 뒤로가기를 막고, 대결·크루런은 BattleRunning·CrewRunLobby 경로 안에서 끝나므로 측정하면서 다른 경로로 갈 길은 확인하지 못했다. 워치에서 시작한 측정 중에 폰 앱을 홈 경로로 열어 두는 경우는 음성 안내와 겹칠 수 있으나 1차 배포 실기기 확인 항목으로 넘긴다.
- **접근성.** 새 아이콘 단추는 `contentDescription`이 있다(VolumeRow "배경음악 끄기/켜기"). 효과음·영상은 장식이다. 크기 막대는 `contentDescription = "배경음악, 60퍼센트"`를 달아 material3 Slider가 따로 내는 진행 값과 함께 퍼센트를 두 번 읽을 수 있다. 문구가 D-350에 적힌 대로라 결함으로 세지 않고 설계서 갱신 요청(U11-4)으로 넘긴다. 페이스 선택지(RunkkSelectField)는 "5:30"을 그대로 읽는다. 다른 페이스 표시는 `RunkkFormat.paceSpoken`을 쓰므로 같은 갱신 요청에 넣는다.
- **ProfileEditViewModel.onSave(D-355).** 성공 뒤 isSaving을 풀지 않는다. `_events`가 `Channel.BUFFERED`(ProfileEditViewModel.kt:39)라 화면이 잠깐 수집을 멈춰도 `Saved`가 사라지지 않아 단추가 영영 막히지 않는다.
- **RunkkAppContent.** 함수 길이 50줄(38-87행)로 상한에 닿는다. 붙잡기는 `LaunchedEffect(canReveal)`가 한 프레임 기다린 뒤 걷으므로 홈의 HoldSplashUntil이 첫 적용에서 붙잡으면 효과가 취소된다. 로그인 시작은 붙잡지 않는다. `isRevealed`도 `remember`라 AN10-6과 같은 이유로 구성 변경 때 다시 덮인다(AN10-6 추적에 적었다).
- **RunkkSoundVolume 선언 순서.** private 속성 `musicBeforeMute`·`effectsBeforeMute`가 `save()` 뒤(43-44행)에 선언되어 있다. 동작에는 영향이 없다(Kotlin 속성 초기화는 선언 순서이고 함수는 생성 뒤에 불린다).

### 4. 구조적 프로그래밍

goto 등가물(다중 레벨 break 남용, 예외를 흐름 제어로 씀) 없음. 재생기·효과음 열기의 `try { … } catch (e: Exception) { Log.w; null }`은 열기 실패를 null·SILENT로 바꾸는 경계 처리이고 흐름 제어가 아니다. 반복문 한가운데 return 없음(`RunkkSplash`의 `while (true)`는 포인터 이벤트를 기다리는 코루틴 반복이다). 중첩 깊이 3 초과 새 함수 없음. 순환 복잡도 10을 넘는 새·변경 함수는 없다(범위 A 최대 `onForfeitLongPressed` 약 7, `untilBroken` 약 5, 범위 B 최대 `RoomAvatar` 약 8, `isMusicRoute` 4, `refresh`(CoachViewModel) 3). 50줄 초과는 RoomAvatar 62 → 72, HomeScreen 72 → 74로 길어졌고(AN10-9 이월), RunkkAppContent는 50줄로 상한에 닿는다.

### 5. 객체지향 구현

- 캡슐화: 새 public 가변 필드 없음. RunkkSoundVolume.music·effects는 `private set`, FirstScreenGate.isHeld는 `internal set`, LoopingMusic·CroppedVideoView·VolumeActions는 private 클래스, RunkkSoundEffects·RunkkSoundVolume 생성자는 internal이다. VolumeActions의 `val` 셋은 private 클래스 안이라 밖으로 나가지 않는다.

- 절차적 스타일: 새 object 없음. ShownGender는 정적 팩터리(of, fallbackOf)를 둔 값 규칙 클래스다.
