# 얼굴 비동기 구현 기록

> 작성: 2026-11-04 | 버전: v0.13 | 입력: S15P31A207-276, srs/얼굴비동기-박.md, design-oo/얼굴비동기-박.md

## 구현

- FaceJobGateway와 AiServerFaceJobGateway가 AI 접수·상태·결과·최근 머리·몸 프리셋을 호출한다.
- SelfieJobService가 작업 예약, 완료 한 번 반영, 동의·회원 활성·한도 검사를 담당한다.
- SelfieJob과 V36이 회원별 사진 해시·작업 ID·처리 이력을 보관한다. 셀카 바이트와 생성 이미지 Data URL은 백엔드에 저장하지 않는다.
- Avatar는 pendingFaceRequest와 headJobId로 진행 중 요청 및 선택 얼굴을 가리킨다.
- 새 얼굴 키는 head:{회원ID}:{작업ID}이고 조회 경로는 /api/v1/avatar/heads/{ownerId}/{jobId}다.
- 옛 SelfieConversion과 동기 게이트웨이, 30초 Redis 변환 잠금은 제거했다. 이전 얼굴 이미지는 기존 FaceImageService와 저장소로 조회한다.

## 예외와 경합

- 같은 사진 재전송과 결과 중복·동시 조회는 한 번만 생성 횟수를 사용한다.
- 상태 조회의 SUCCEEDED 자체는 아직 횟수를 사용하지 않는다. 결과 조회에서 검증·반영이 끝날 때 사용한다.
- FAILED는 200의 error.code다. 접수 HTTP 오류와 JOB_NOT_READY는 별도로 전달한다.
- 503·504 접수 여부 미확정은 30초 예약으로 직렬화하고 만료 후 같은 사진 재시도 또는 새 사진 교체를 허용한다.
- Node가 작업을 잃어 JOB_NOT_FOUND를 반환하면 미완료 로컬 참조를 풀어 재접수를 허용한다.
- 기본 얼굴을 선택한 뒤 늦게 완료된 작업은 선택 얼굴을 덮어쓰지 않는다.
- 시각 예약 토큰은 DB timestamp의 마이크로초 정밀도에 맞춘다. 실제 HTTP 시험에서 나노초 비교 실패를 발견해 수정했다.

## 후속 연동

앱은 기존 /avatar/selfie의 202 응답을 처리하고 작업을 폴링한 뒤 result를 읽어야 한다. 3레이어·mobile 계약과 head: 키 해석은 앱 후속 범위다. 환경변수는 기존 RUNKK_FACE_API_URL=http://avatar:3000/api/v1, COMPOSE_PROFILES=writer,avatar와 AVATAR_GMS_KEY를 사용한다. 이 변경에서 운영 환경값을 수정하지 않았다.

## 최종 검증

2026-11-04에 JDK 21로 backend의 spotlessApply build를 실행했다. 전체 JUnit 집계 1,784건 중 실행 1,629건이 통과했고 실패·오류는 0건이다. Docker 의존 시험 155건은 건너뛰었다. 새 얼굴 계약 관련 46건에 AI 표본 19개, 실제 HTTP 동시 접수·동시 완료, 기존 얼굴 보존 마이그레이션이 포함된다. Java·보안 재검토에서 남은 조치 필요 지적은 없었다. 실제 Node 생성·운영 PostgreSQL·앱 합성은 확인 전이다.
