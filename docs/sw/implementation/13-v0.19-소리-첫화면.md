## 13. v0.19 소리·첫 화면·오늘 계획 페이스 반복 (2026-10-31 오후)

사용자가 에뮬레이터와 실기기로 앱을 보며 요청한 결정 D139~D148(`runkk-work/figma-1029/decisions-1029.md` 표 끝)을 반영한 반복이다. 요구는 srs v0.17의 CR-82~CR-91(srs/07-09: 신규 FR-234~FR-239, NFR-045~NFR-047, C-021, 바뀐 FR-007·FR-048·FR-073·FR-162), 설계는 design-oo v0.19의 D-344~D-357(design-oo/05-14)이다. 12장과 같이 설계서는 이 반복의 코드(242612e9)를 읽고 코드에 맞춰 썼으므로 아래 결정은 대부분 "설계보다 먼저 정한 것"이다. 서버·DB·REST·실시간 계약은 바뀌지 않았고, 바뀐 곳은 앱의 다섯 패키지(core.designsystem, app, ui.me, ui.home, ui.record)다. 스택·커밋 규칙(`{타입}: {내용}`, Jira 키 없음)은 1장과 같다.

### 13.1 작업 방식

- 12장과 같이 화면 확인 중심이었다. 사용자가 에뮬레이터(local 플레이버)와 실기기로 보고 요청하면 통합 폴더 `S15P31A207-fig`에서 직접 고쳐 빌드·설치만 하고 다시 보여 주었다. 요청 하나가 결정 하나(D139~D148)가 되었다.
- 이번 반복은 하위 작업자를 쓰지 않았다(한 폴더, 한 맥락).
- 확인 동안 단위 시험·스크린샷 검증을 돌리지 않고, push 직전에 게이트(13.3)를 한 번 돌렸다.
- 이번에 처음으로 실기기(SM-S918N)를 USB로 붙여 `adb reverse`로 로컬 서버에 연결해 확인했다. 실기기에서만 드러난 결함 두 건(D147, D148)을 같은 반복에서 고쳤다(13.4).

### 13.3 통합 검증

push 직전 같은 작업 트리에서 돌렸다.

| 단위 | 명령 | 결과 |
|------|------|------|
| android | `./gradlew ktlintCheck lintLocalDebug testLocalDebugUnitTest verifyRoborazziLocalDebug assembleDevelopDebug` | 성공, 단위 시험 1,465건 실패 0 |
| backend | `./gradlew spotlessCheck test` | 성공, 시험 1,679건 실패 0(서버 코드 변경 없음, 회귀만) |

- 첫 실행에서 Roborazzi 12장이 달랐다. 모두 의도한 화면 변화(홈 로딩 1: 성별 읽기 전 아바타 비움, 설정 3: 소리 묶음, 코치 1: 목표 페이스 칸, Runimal 7: 흰 배경 제거)라 기준을 다시 찍고 재실행해 통과했다.
- 12.3과 명령이 다르다. 워치(`:wear:testLocalDebugUnitTest`)는 바뀌지 않아 뺐고, develop 플레이버 빌드(`assembleDevelopDebug`)를 더해 media3 의존이 배포 플레이버에서도 묶이는지 확인했다. 앱 시험 수(1,465)가 12.3(1,819)보다 적은 것은 워치 시험을 빼서다.
- ai·infra는 바뀌지 않아 돌리지 않았다.
