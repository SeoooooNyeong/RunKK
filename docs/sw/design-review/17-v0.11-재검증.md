## 17. v0.11 재검증 (srs v0.10·코드 리뷰 반영본)

이 장은 **design-oo.md v0.11**을 입력으로 review 0~6단계를 v0.11 변경 범위에 다시 적용한 결과다. v0.11은 srs.md v0.10의 변경 요청(CR-01~CR-10)과 code-review.md 2~4차 설계 갱신 요청 41건을 따라간 판이고, 설계 담당이 구조 판정 여섯 건(부록 E.4 R-1~R-6)을 이 단계로 넘겼다. 기준선은 16장(v0.10, 합격)의 판정표다. **v0.11에서 새로 생기거나 내용이 바뀐 화살표·패키지·모듈만 새로 판정**하고, 나머지는 13장~16장 판정을 이어 쓴다. 수치는 12.2 목록과 5.1.2 표를 스크립트로 쌍 집합으로 읽어 다시 셌고(행렬, Fan-In·Fan-Out, 불안정도, 강결합 요소, 계층 규칙), 구현 저장소(S15P31A207-impl, feature/runkk-impl 45d33ae) 코드는 읽기만 했다. 코드 import에서 뽑은 서버 패키지 쌍 128개는 모두 12.2 목록 안에 있다. 개선안은 design-oo 조각에 직접 반영했고(고친 문장 끝 `(v0.11 검증, D-xxx)`), 새 결정은 D-132~D-141이다.

### 17.0 입력 정리

#### 17.0.1 검증 기준

16장과 같다. 결합도 상한 스탬프(받는 쪽이 절반 미만을 쓰면 검토, 정확히 절반은 허용), 제어는 검토, 외부·공통·내용은 불허. 응집도 하한 통신적(논리적은 변경이 드문 읽기 전용 기준 형식만 모인 경우 조건부 허용). 패키지·모듈 Fan-Out 상한 7(common 화살표도 센다, 앞 장과 같은 방식). 순환 0, 계층 역행 0. 안정성 위반은 15장처럼 검토로 센다. 6.3의 다형성 기준(같은 종류 분기 3곳 이상이면 다형성 후보)은 E.4 R-6 판정에 쓴다.

- report.target으로 crew·crew.chat이 신고용 공개 연산 셋씩을 내보낸다. 패키지 안에 숨어 있던 숨김 연산이 밖에 보이게 되므로 13.1 ArchUnit 규칙 (8)에 "reportedView·hideReported·unhideReported는 report.target만 부른다"를 더했다.
- D-132로 하위 → 하위 화살표(표현 → web.attempt)가 처음 생겼다. 12.3의 "하위 패키지는 Fan-In이 0" 문장은 "web.attempt만 Fan-In 4, Fan-Out 0"으로 고쳤고 순환 검사 범위는 그대로다(Fan-Out 0인 패키지는 순환에 들 수 없다).
- R-2·R-3은 지표 역전이 남는다. 감시 조건(D-133·D-134)과 구조 시험 규칙 (11)이 실제 흔들림 경로(쓰는 형식)를 고정한다.

### 17.7 최종 판정
