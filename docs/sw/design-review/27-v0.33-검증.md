## 27. v0.33 검증 (핫픽스 수동 확인 뒤 추가 변경, 2026-11-05)

이 장은 **design-oo.md v0.33**의 새 조각 [05-23](../design-oo/05-23-설계-핫픽스-추가변경-성.md)(D-547~D-563)을 입력으로 review 0~6단계를 적용한 결과다. 이번 설계는 코드(S15P31A207-hotfix 4a2722fd..80592a08)가 먼저 들어간 뒤 코드 기준으로 올린 것이라, 설계 문장을 코드 import·시그니처와 하나씩 대조했다(설계 담당이 쓴 "새 화살표 0"을 그대로 믿지 않고 import를 다시 셈). 장 번호는 목차의 26장이 "다음 단계"라 27로 둔다.

기준은 0.1 기본값 그대로다(결합도 상한 스탬프, 응집도 하한 통신적, Fan-Out 7, 순환 0, 클래스 협력 객체는 Clock·CoroutineScope를 빼고 7 이하). 결함 등급은 25장과 같다(치명 = 불허, 중·경 = 검토).

#### 27.4.3 경합·수명

- 예열 작업은 회 범위(`run.round.scope`)에서 돌고 `begin`이 취소한다. `showGps`는 같은 battleId의 Matched·Countdown만 바꾸므로, 측정이 시작된 뒤 늦게 온 READY가 Running 상태를 덮지 않는다(C: `_state.update`에서 else → 그대로).
- 측정 서비스의 위치 요청과 예열 요청이 `begin` 직후 잠깐 겹친다. 같은 FusedLocationProvider라 기기에서 하나로 합쳐지고 예열 쪽 위치는 버리므로 기록에 영향 없다.
- 워치 다시 읽기는 결과 화면을 떠나면 멈추고, 회원이 바뀌면 nextPlacementRound를 지운다. `awaitPlacement`는 결과 화면의 viewModelScope라 화면 수명보다 길지 않다.

#### 27.4.4 개인정보

예열 위치는 RunTracker로 가지 않고 정확도만 본 뒤 버린다(D-560). 로그 없음(C7). 문제 없음.
