# 얼굴 비동기 설계 검증

> 작성: 2026-11-04 | 버전: 다음 판 변경 | 입력: design-oo/얼굴비동기-박.md, S15P31A207-276, 기존 설계 의존 표와 ArchitectureTest

## 검토 기준

대상은 기존 패키지 안의 얼굴 작업 변경이다. 결합도는 스탬프 이하, 응집도는 통신적 이상, 패키지 Fan-Out은 기존 상한 7, 새 순환은 허용하지 않는다.

| 방향 | 메시지 | 결합도 | 판정 |
|------|--------|--------|------|
| web.avatar → avatar | 회원·사진·작업 ID와 작업·머리 결과 | 데이터·스탬프 | 허용 |
| avatar → member | 동의·활성 상태·얼굴 공개 투영 | 데이터·스탬프 | 허용 |
| avatar → policy | 기존 셀카 한도·기능 스위치 | 스탬프 | 허용 |
| avatar → common | 기존 업무 거부 코드 | 데이터 | 허용 |
| infra.avatar → avatar | 작업 저장소 포트·엔티티 | 스탬프 | 허용 |
| infra.integration.ai → avatar | AI 얼굴 작업 포트·전송 값 | 스탬프 | 허용 |

새 패키지와 역방향 의존은 없다. 저장소는 infra.avatar 한 곳에서만 구현한다. 외부 네트워크 호출은 트랜잭션 밖에 있다. 아바타 변경·작업 반영은 같은 Avatar 행 잠금에 직렬화한다.

## 발견과 반영

1. 상태 조회에서 이미지 조회까지 연속 호출하면 앱 읽기 제한 20초를 넘을 수 있다. 상태는 상태만 반환하고 결과 API가 반영을 수행하도록 수정했다.
2. 접수 여부를 모르는 예약은 30초 뒤 재시도·교체할 수 있다. 늦게 돌아온 이전 호출은 예약 시각으로 차단한다.
3. 회원 상태는 아바타 잠금을 얻은 뒤 처음 읽는다. 탈퇴와 겹치면 새 아바타 생성도 롤백된다.
4. 새 얼굴 참조는 기존 기본·5파츠 얼굴과 분기한다. 기존 테이블의 5파츠 데이터는 삭제하거나 변환하지 않는다.

판정은 자동 구조 검증과 변경 범위 검토 기준 조건부 합격이다. 실제 앱 폴링·합성 및 Node 얼굴 파기는 시스템 연동 확인으로 남긴다.
