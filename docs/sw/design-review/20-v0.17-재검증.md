## 20. v0.17 재검증 (19장 2차 재검증, 2026-10-31)

이 장은 **design-oo.md v0.17**을 입력으로 19장 지적의 해소 여부를 확인하고, v0.17이 더한 것에 review 0~6단계를 적용한 결과다. 19장은 v0.16 본문을 불합격(불허 R51·R52, 검토 R-2·R-3·R53~R56)으로 판정하고 권고 반영 계획(19.6, 폰 150개, 조건부 합격)을 냈다. 설계 담당은 이를 05-12 D-331~D-335로 반영했다. 같은 판에 코드 리뷰 10차 반영 D-336~D-340(표시 성별 ShownGender, 출발 전 취소, 남은 대결 정리, 잠금 빌드 푸시 차단, 지도 오류 격자)도 들어왔다. 기준선은 19장 v0.16 본문과 코드 cfbd103c 대조 결과다. **v0.17에서 새로 생기거나 바뀐 화살표·모듈·클래스만 새로 판정**하고 나머지는 19장 판정을 이어 쓴다.

구현 저장소 S15P31A207-fig feature/runkk-figma-v1 HEAD 3b59215b를 읽기만 했다. 이 커밋은 fix/design-review-v016(de6f17ed, 56c6d90b, f0691b78, c26b1be5, 5f861d0e)을 병합한 것이다. 대조 방법은 19.0.5와 같다. main 소스(시험·빌드 산출물 제외, localDebug 포함)의 import를 서버는 5.1.1 패키지 65개로, 앱은 5.1.2 모듈로 묶어 쌍을 셌다. 그리고 ArchitectureTest.java ALLOWED, Konsist ArchitectureTest.kt ALLOWED, 05-01 5.1.2 표와 대조했다. 앱은 Konsist가 예외로 두는 두 경우(data.\*의 api.core.R, localDebug E2E 토큰 창구의 app → ui.me)를 뺐다.

### 20.1 의존 행렬과 지표

**서버.** 65개 패키지, 179개 화살표로 19장 값 그대로다. 핵심 사이 행렬과 불안정도도 바뀌지 않았다. R-2 member(0.143) → policy(0.154), R-3 reward(0.455) → battle(0.46)은 그대로다. 정방향 여유가 가장 작은 쌍도 그대로 running(0.19) → member(0.143), 0.045다. 최대 Fan-Out은 crew·analysis 7이다.

### 20.7 최종 판정

**조건부 합격** (design-oo.md v0.17 본문, 코드 3b59215b 대조). 불허 0건, 검토 5건(R-2, R-3, R54, R57, R58).

19장의 불허 둘은 설계서와 코드 모두에서 해소되었다. ui.battle은 7(R51), app은 6(R52)이다. 받는 값도 MySummary로 줄었다(R53). 랭킹 표시 성별은 읽을 때 붙는다(R55). 문서 넷도 고쳐졌다(R56). R54는 계약 시험으로 완화되었지만 상수 사본이 남아 검토를 이어 간다. 코드 import를 다시 세면 폰은 149쌍이고, 허용만 있는 api.live → api.core를 더하면 Konsist 허용 표 150개, 5.1.2 표 150개와 행마다 같다. 서버는 비common 116쌍이 ArchUnit ALLOWED와 같다. 새 의존(domain.sync → domain.settings·notification·record, ReleaseLock·GatedFeature, ShownGender·shownGendersOf)은 순환·계층 역행·안정성 역전·쓰레기통을 만들지 않았다.

새 검토 둘은 같은 판 후반(D-336~D-340)에서 생겼다. R57은 규칙 복제 둘이다. 1차 배포 잠금 식이 :app·:data Gradle 스크립트에 따로 있고(H-48), 취소 가능 종류가 서버와 앱 두 곳에 따로 있다(H-50). R58은 D-336·D-339가 5.1.2·클래스 명세·추적표·12.4에 옮겨지지 않은 문서 불일치(M66~M68)다. 둘 다 화살표를 바꾸지 않으므로, 반영하면 검토는 R-2·R-3·R54 셋이 된다(19.6 계획과 같은 상태).
