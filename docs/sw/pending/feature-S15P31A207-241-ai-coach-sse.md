## 다른 담당에게 요청

- 회원 담당은 FR-015와 동의 API 계약에 기존 `PUT /api/v1/me/consents/LLM_TRANSFER?version=2`를 반영한다. 앱 동의 안내와 연결은 #273에서 확인한다.

## 합의된 동작과 표본

- 앱은 `POST /api/v1/coach/questions`에 `{"conversationId":null,"text":"어제 러닝 어땠어?"}`를 보낸다. 기존 대화에는 색인에서 받은 ID를 넣는다. 앱 경계는 질문 500 코드 포인트, AI 서버 자체 허용 범위는 1,000자다.
- 백엔드는 인증에서 사용자 ID를 얻고 AI 서버에 `{"userId":"42","conversationId":null,"message":"어제 러닝 어땠어?"}`를 보낸다. 앱 요청의 사용자 ID를 신뢰하지 않는다.
- 앱 SSE의 정상 순서는 `started`(대화 ID), `delta`(답 조각), `done`이다. AI의 `meta`는 `started`로 바꾸고 `tool`은 내부에 둔다. 스트림 중 오류·시간 초과·종료 이벤트 없는 연결 종료는 재시도 가능한 실패로 다룬다.
- 요청 전 오류 표본은 기능 닫힘·미동의 403, 대화 만료 410, 질문 길이 초과 400, 한도 소진 429다. 백엔드 사용량은 정상 답변 완료만 센다. AI의 별도 접수 한도도 429로 연결한다.
- `GET /api/v1/coach/conversations`는 `[{"conversationId":"conv-1","firstQuestion":"어제 러닝 어땠어?","lastAskedAt":"2026-11-04T10:00:00"}]` 형태를 반환한다. 제목은 첫 질문의 앞 40 코드 포인트다.

## 확정된 범위

- 기존 LLM_TRANSFER 항목을 사용한다. 최신 고지 2판에 이미 동의한 회원은 그 동의를 사용하고, 이전 고지 1판 회원은 코치 사용 전에 최신 고지를 확인한다.
- 이전 대화는 목록에서 선택한 ID로 다음 질문을 이어간다. 본문 복원과 조회 API는 이번 범위에서 제외한다.
- 질문 중계와 이전 대화 목록은 기존 계획의 두 경로를 사용한다. 잔여 횟수 전용 조회 API는 추가하지 않는다.
## 확인 대기

- AI 저장소의 본문 정리 구현은 확인했다. 배포 구성에서 활성 모델로 연결, 실제 90일 본문 정리, NFR-052 p95는 통합 시험에서 확인한다.


## SSE 계약 테스트용 표본

정상 응답 (`Content-Type: text/event-stream`).

```text
event: started
data: {"conversationId":"conv-1"}

event: delta
data: {"text":"회복 러닝을 한 번 넣어 보세요."}

event: done
data: {}

```

스트림을 연 뒤 AI 응답이 실패하면 마지막 이벤트를 아래와 같이 보낸다. 이 경우 사용량은 늘리지 않는다.

```text
event: failed
data: {"reason":"RETRY"}

```

정상 종료 이벤트에는 기존 앱의 CoachEvent.Done에 맞춰 별도 데이터를 두지 않는다. Figma의 잔여 횟수 표시 계약은 화면 연동 범위에서 다시 확인한다.
## 계약 시험 완료 조건

1. 새 대화와 기존 대화가 인증된 사용자로만 전달되고, 다른 회원의 대화 ID는 차단된다.
2. AI 이벤트를 분할 전송해도 started → delta → done이 순서대로 도착하고 tool 이벤트가 노출되지 않는다.
3. 정상 완료만 한도를 차감한다. 중복·동시 요청에서도 상한을 넘기지 않는다.
4. 스트림 중 실패·타임아웃·클라이언트 취소를 각각 확인한다. 취소는 AI 연결까지 전파된다.
5. 목록은 해당 회원의 만료되지 않은 대화만 반환하며 표시용 첫 질문과 마지막 질문 시각을 담는다.
