### 6.2 자료사전

v0.18(CR-92~CR-102)에서 새로 정의한 워치 자료 10개는 [06-08-자료사전-워치](06-08-자료사전-워치.md)에 이어서 둔다(이 조각이 100KB에 가까워 나눴다).

기호: `=` 구성, `+` 연결, `{ }` 반복(0회 이상), `( )` 생략 가능, `[ a | b ]` 선택(`|`로 나열, 이 저장소의 선택 표기), `* *` 주석. 항목마다 첫 줄이 정의, `* *` 줄이 설명이다. 가나다순으로 정렬했다(영문 이름은 끝).

기본 요소 명명 규칙: 아래 끝말을 가진 기본 요소는 따로 항목을 두지 않고 이 규칙으로 정의한다.

| 이름 끝말 | 뜻·형식 | 예 |
|-----------|---------|----|
| ID | 시스템 또는 외부 제공자가 붙인 고유 식별자 | 회원ID, 기록ID, 제공자계정ID |
| 일시 | 날짜와 시각, 초 단위(YYYY-MM-DD hh:mm:ss) | 시작일시, 측정일시 |
| 일 | 날짜(YYYY-MM-DD) | 시작일, 계획일, 생년월일 |
| 거리 | km 단위 0 이상 실수, 소수 둘째 자리. 표시는 단위 설정을 따른다 | 누적거리, 계획거리 |
| 시간 | 초 단위 0 이상 정수 | 경과시간, 완주시간 |
| 여부 | [예 \| 아니오] | 저장여부, 동의여부 |
| 횟수, 수, 인원, 순위, 번호, 일수 | 0 이상 정수 | 총횟수, 인원수, 연속러닝일수 |
| 률, 일치도 | 0 이상 백분율, 소수 첫째 자리 | 진행률, 거리달성률 |
| 명, 사유, 내용, 문, 문구, 설명, 근거, 소개 | 문자열. 길이 제한은 설계 단계 | 크루명, 실패사유, 안내문 |
| 이미지 | 이미지 파일 | 카드이미지, 지도이미지 |
| 값 | 해당 항목에 정한 형식의 값 | 지표값, 변경전값 |
| 주소, 표기, 선 | 문서 주소, 출처 문구, 지도 위 경로선 | 문서주소, 출처표기, 경로선 |
| 위도, 경도, 반경, 축척 | 위치 좌표(도 단위 실수), 정확도 반경(m), 지도 축척 | 중심위도, 정확도반경 |
| 가격, 적립량, 잔액 | 리워드 포인트, 0 이상 정수. 화면 단위는 P(v0.13 변경, CR-47) | 리워드잔액 |

가상닉네임 = * 가상 기록에 붙이는 표시용 이름. 닉네임 규칙(2~20자)과 같은 형식으로 무작위로 만들고, 회원 닉네임과 겹치지 않는다(결정 Q-75) *

가이드확인여부 = 여부
    * 회원레코드 안의 첫 사용 가이드 확인 표시. 건너뛰거나 마지막 단계까지 보면 예가 되고 가이드를 다시 보이지 않는다(FR-231) (v0.13 신규, CR-51) *

가입결정 = 요청자ID + 크루ID + 가입신청ID + [승인 | 거절]

가입대기목록 = 크루ID + {가입신청ID + 표시명 + (티어) + (Runimal유형) + 신청일시} + (거부사유)

    * 5.3.1 → 러너 *

가입신청레코드 = 가입신청ID + 크루ID + 회원ID + 신청일시 + 신청상태 + (결정일시)
    * D8 크루 파일 안의 가입 신청 행 *

가입신청취소요청 = 회원ID + 가입신청ID
    * 러너 → 5.3.1. 신청자가 대기 중 신청을 직접 취소(FR-143) *

가장빠른1km = 구간번호 + 페이스
    * 구간페이스 중 가장 짧은 값. 기록 상세에 구간 번호를 함께 보인다(FR-059) (v0.13 변경, CR-41) *

감사 로그 = {감사기록}
    * 저장소 D14. 추가만 하고 고치지 않는다. 6개월 보존 뒤 지운다(FR-176) *

감사기록 = 기록일시 + 행위자ID + 행위자역할 + 행위종류 + 대상ID + (변경전값) + (변경후값)
    * 1.2, 1.4, 1.5, 5.1.3, 5.1.4, 5.1.5, 5.3.4, 5.4.1~5.4.5, 5.8, 7.1, 7.2, 7.7 → D14. D14 → 7.4 (v0.10 변경, CR-08) *

강제퇴장결과 = 크루ID + 대상회원ID + 처리상태 + (거부사유)

개인스트릭 = 연속러닝주수 + 연속러닝일수
    * 연속러닝주수는 이번 주(월요일 시작)에 유효 러닝이 있으면 이번 주부터, 없으면 지난주부터 거꾸로 센 유효 러닝 1번 이상인 주의 연속 수다. 연속러닝일수는 오늘 또는 어제부터 거꾸로 센 유효 러닝 연속 일수다. 홈은 주 수만, 기록 화면 연속 칸은 둘 다 보인다(FR-052, FR-057) (v0.15 변경, CR-66) *

개인잔디 = {날짜 + 러닝여부 + (거리)}
    * 표시 기간 (제안) 최근 12주 *

개인정보공개 = {[나이대 | 성별] + 공개여부}

거절요청 = 회원ID + 초대ID
    * 러너(초대받은 쪽) → 4.2. 참가 확인 화면의 "거절"(FR-229) (v0.13 신규, CR-50) *

검증된심박값 = 측정일시 + 심박수
    * 2.5에서 동의·워치 연동·측정 상태를 확인하고 남긴 심박 *

게스트시작요청 = 필수동의 + 만14세확인 + (선택동의)

게시결과 = (게시글ID) + 처리상태 + (거부사유)

    * 러너(크루 구성원) → 5.4.5. 본문이 비어 있으면서 사진도 없으면 거부한다. 앨범조회는 사진이 있는 게시글의 사진만 모아 본다(FR-211, FR-212) (v0.10 추가, CR-08) *

게시내용 = 본문 + (크루런거리) + (응답마감일시)
    * 응원·일정·공지·게시글의 글. 크루런거리는 크루런 일정에만, 응답마감일시는 일정에만 쓴다. 응답마감일시는 일정 참석 응답의 마감이며 투표의 마감일시와 다르다(v0.9 이름 투표마감일시를 바꿈). 일정의 일시·장소는 크루게시레코드의 일정일시·장소명에 둔다. 지도 좌표·위치 항목이 없다(FR-132) (v0.10 변경, CR-08) *

    * 게시글 하나에 0~5장. 앱이 고르는 원본은 장당 10MB 이하 JPEG·PNG (제안)이고, 앱이 장당 1MB 이하 JPEG로 줄여 보내며 서버는 줄인 JPEG만 받는다(FR-211). 저장 전에 위치 정보 메타데이터를 지운다(NFR-042) (v0.10 보완, test.md v0.6 TF-VC-25, TF-SY-25). 작성자가 탈퇴하면 지운다 (제안, FR-021) (v0.10 추가, CR-08) *

게시삭제결과 = 게시글ID + 처리상태
    * 5.4.1~5.4.5 → 크루장·운영진 (v0.10 변경, CR-08) *

게시종류 = [응원 | 일정 | 공지 | 투표 | 게시글]
    * v0.9의 [응원글 | 모집글]을 바꿨다. v0.9의 크루런 모집글은 일정종류가 크루런인 일정이다 (v0.10 변경, CR-08) *

경로파기지시 = 회원ID + 파기기한
    * 1.4 → D2, D15. 위치 수집 동의 철회 뒤 7일 안에 위치포인트·코스를 파기(FR-026) *

계정연동결과 = 처리상태 + (제공자종류) + (거부사유)
    * 1.1 → 러너. 그 소셜 계정이 이미 다른 회원과 연동되어 있으면 거부하고 거부사유로 "이미 가입된 계정"을 알린다. 두 계정을 합치지 않는다 (제안) (FR-198) (v0.10 추가, CR-09) *

    * 게스트 = 소셜 계정을 연동하지 않은 회원(FR-197). 연동하면 연동회원이 되고 회원ID는 그대로다(FR-198). 다른 러너에게는 보이지 않는다 (제안, FR-006) (v0.10 추가, CR-09) *

    * 러너 → 3.7.2 *
