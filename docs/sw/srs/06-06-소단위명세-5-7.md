#### 5.1.1 크루 생성
입력: 크루생성요청, 크루레코드, 크루멤버십 / 출력: 크루생성결과, 크루레코드, 크루멤버십 / 관련 FR: FR-110, FR-112, FR-124
```
크루생성요청을 받으면
    IF 요청자에게 퇴장일시가 없는 크루멤버십이 있으면
        크루생성결과 ← 거부 + "이미 크루 소속"                   * 1인 1크루 (Q-34) *
    ELSE IF 요청자의 가장 최근 퇴장사유가 탈퇴·강제퇴장이고 퇴장일시 + 24시간이 지나지 않았으면
        크루생성결과 ← 거부 + "퇴장 뒤 24시간 동안 만들 수 없음" + 가능 시각   * FR-124 *
    ELSE IF 크루명이 2~20자가 아니거나 다른 크루레코드와 같으면
        크루생성결과 ← 거부 + "크루명 오류"
    ELSE IF 크루태그가 3.5.1 고정 목록에 없거나 모두 1~3개가 아니면     * v0.28 변경, CR-156: 성향태그 분류마다 1개·1~5개 규칙을 바꿨다 *
        크루생성결과 ← 거부 + "태그 오류"
    ELSE
        초대코드 ← 다른 크루와 겹치지 않는 6자리 영문·숫자, 초대코드만료일시 ← 지금 + 7일
        크루레코드(크루로고이미지 포함) 저장, 크루멤버십(요청자, 크루장, 가입일시) 저장
        크루생성결과 ← 크루ID + 초대코드 + 완료
* 주간 공동 목표는 크루를 만들 때 받지 않고 만든 뒤 5.6.1에서 정한다. 처음 만든 크루는 목표가 없다 (v0.10 변경, CR-08, FR-110, FR-138) *
* 크루 태그는 크루만 고른다(CR-04, FR-110). v0.28에서 성향 태그를 요일·시간대 크루태그로 바꿨다(CR-156) *
```

#### 5.1.2 크루 설정 변경
입력: 크루설정변경요청, 크루레코드, 크루멤버십 / 출력: 크루설정결과, 크루레코드 / 관련 FR: FR-113, FR-114, FR-128
```
크루설정변경요청(요청자ID, 크루ID, ...)을 받으면
    IF 요청자가 그 크루의 크루장이 아니면 (운영진도 거부, v0.10 변경, CR-08, FR-113)
        크루설정결과 ← 거부 + "권한 없음"
    ELSE IF 크루정보변경 이면
        IF 바꿀 값이 형식에 맞지 않거나 크루명이 다른 크루와 같으면 크루설정결과 ← 거부 + "입력 오류"
        ELSE 들어온 항목(공개여부·가입방식 포함)을 크루레코드에 반영하고 크루설정결과 ← 완료
            * 대기 중인 가입 신청은 그대로 두고 크루장이 처리한다 (Q-36) *
    ELSE (초대코드재발급)
        새초대코드 ← 겹치지 않는 새 코드, 초대코드만료일시 ← 지금 + 7일, 이전 코드는 바로 무효
        크루설정결과 ← 완료 + 새초대코드
```

#### 5.1.3 크루장 양도
입력: 크루장양도요청, 크루멤버십 / 출력: 양도결과, 크루멤버십, 감사기록, 알림사건 / 관련 FR: FR-115, FR-128
```
IF 요청자가 그 크루의 크루장이 아니면
    양도결과 ← 거부 + "권한 없음"
ELSE IF 새크루장ID가 같은 크루의 소속 중인 크루원이 아니면
    양도결과 ← 거부 + "대상 오류"
ELSE
    요청자의 크루역할 ← 크루원, 새크루장의 크루역할 ← 크루장 (두 변경을 한 번에)
    감사기록 ← 행위종류 "크루장양도" + 대상ID 새크루장ID
    알림사건 ← 새크루장ID + 크루장양도
    양도결과 ← 새크루장ID + 완료
```

#### 5.1.4 크루 삭제
입력: 크루삭제요청, 크루멤버십 / 출력: 크루삭제결과, 크루삭제지시, 감사기록, 알림사건 / 관련 FR: FR-116, FR-128
```
IF 요청자가 그 크루의 크루장이 아니면
    크루삭제결과 ← 거부 + "권한 없음"
ELSE IF 삭제확인여부 = 아니오 이면
    크루삭제결과 ← 대기 + "삭제 취소"
ELSE
    소속 중인 크루원마다 알림사건 ← 회원ID + 크루삭제
    크루삭제지시(크루ID)를 D8(크루레코드, 소속 행, 대기 중 가입 신청), D9(게시글·크루런), D10(크루 주간 거리·공동 목표), D18(크루 채팅 메시지)에 보낸다 (v0.10 변경, CR-08, FR-116)
    감사기록 ← 행위종류 "크루삭제" + 대상ID 크루ID
    크루삭제결과 ← 완료
* 소속이 없어진 크루원은 바로 다른 크루에 가입할 수 있다. 퇴장 쿨타임은 탈퇴·강제 퇴장에만 적용한다 (FR-124, 제안) *
```

#### 5.2.1 크루 목록 조회
입력: 크루검색조건, 크루레코드, 크루멤버십, 회원레코드, 레이스레코드 / 출력: 크루목록 / 관련 FR: FR-117
```
크루검색조건을 받으면
    대상 ← 공개여부 = 공개인 크루레코드 (비공개 크루는 나오지 않는다, Q-38)
    IF 크루태그가 있으면 고른 태그를 모두 가진 크루만 남긴다 (AND)
        * 크루 태그 조건(「조건 설정하기」)이 크루 찾기의 주 경로다 (v0.10 변경, CR-04. v0.28 변경, CR-156, FR-117) *
    IF 키워드가 있으면 크루명 또는 한줄소개에 키워드가 들어간 크루만 남긴다
    크루마다 인원수 ← 퇴장일시 없는 크루멤버십 수
        지난주크루거리 ← 그 크루의 지난 주 레이스레코드 합산거리 (없으면 0)
    크루목록 ← 소개·태그·로고·인원·가입방식·지난 주 크루 거리만 담아 생성일시 최신순        * 크루 밖 열람 범위 (Q-45, W-16) *
* v0.28 변경, CR-159: 크루장표시명·이번주크루거리 대신 지난주크루거리 (FR-117) *
* 러너 성향 태그가 없어져 요청자 태그와의 태그일치수를 계산하지 않고, 크루가 없는 러너에게 추천(FR-118)을 함께 보이지 않는다 (v0.10 변경, CR-04, FR-117) *
```

| 결정 = 승인 | - | N | Y | Y |

#### 5.3.3 크루 탈퇴 처리
입력: 크루탈퇴요청, 크루멤버십 / 출력: 크루탈퇴결과, 크루멤버십 / 관련 FR: FR-125, FR-126
```
크루탈퇴요청(크루ID, 회원ID)을 받으면
    IF 회원이 그 크루에 소속 중이 아니면
        크루탈퇴결과 ← 거부 + "소속 아님"
    ELSE IF 회원이 크루장이고 다른 크루원이 1명 이상이면
        크루탈퇴결과 ← 거부 + "크루장 양도 필요"
    ELSE IF 회원이 크루장이고 혼자이면
        크루탈퇴결과 ← 거부 + "크루 삭제 필요" + 크루 삭제 안내
    ELSE
        크루멤버십의 퇴장일시 ← 지금, 퇴장사유 ← 탈퇴
        그 회원의 응답 정리: 일정일시가 지나지 않은 일정의 일정응답(모집참여)과 마감일시가 지나지 않은 투표의 투표응답은 지운다.

#### 5.4 크루 게시글 관리

v0.10에서 5.4를 게시종류별 5.4.1~5.4.5로 나눴다 (v0.10 변경, CR-08, 6.1.2). 5.4 자체는 최하위 프로세스가 아니다. 다섯 절이 함께 쓰는 규칙은 다음과 같다.

- 크루 밖 러너의 요청은 모두 거부한다 (3.0.3).
- 조회에는 삭제여부 = 예 이거나 숨김여부 = 예 인 글을 넣지 않는다 (FR-212, FR-215). 숨김은 신고 처리(7.7)가 정한다.
- 삭제는 FR-213 한 규칙을 쓴다. 각 절의 "삭제" 표는 모두 같은 표다. 작성자 본인, 크루장, 운영진만 지울 수 있고, 남의 글을 지우면 감사기록에 남긴다.
- 탈퇴한 작성자의 글은 남고 작성자 표시명이 "탈퇴한사용자"다 (FR-021).

#### 5.7.2 크루런 출발 신호 발행
입력: 크루게시레코드, 운영기준 / 출력: 크루게시레코드, 크루런시작신호, 알림사건 / 관련 FR: FR-148, FR-193
```

#### 5.7.3 크루런 진행 중계
입력: 러닝진행값, 크루런정지요청, 크루런중단요청, 크루게시레코드, 회원레코드 / 출력: 크루런중계, 크루게시레코드 / 관련 FR: FR-149, FR-192, FR-300 (v0.28 변경, CR-160: 순위·순위안내(FR-190 삭제)를 빼고 합산·참가자상태로 바꿨다)
```
러닝진행값(크루런게시글ID 있음)을 받으면
    크루게시레코드를 읽는다. IF 크루런상태 ≠ 진행 이거나 보낸 사람이 진행 참가자가 아니면 무시한다
    그 참가자의 최신 누적거리를 기억한다
    IF 그 참가자의 참가자상태 = 멈춤 이고 받은 경과시간 > 정지 때 경과시간 이면 참가자상태 ← 달리는 중
    IF 그 참가자의 참가자상태 = 연결 확인 중 이면 참가자상태 ← 달리는 중
    크루합산거리 ← 진행 참가자 전원(끝낸 사람 포함)의 최신 누적거리 합
    참가자마다 크루런중계 ← 게시글ID + 크루합산거리 + {표시명 + 누적거리 + 참가자상태 + 본인여부} (대기실 입장 순)

한 참가자의 러닝진행값이 3초 넘게 오지 않으면 (제안)
    그 참가자의 참가자상태 ← 연결 확인 중, 크루런중계를 보낸다
크루런정지요청(게시글ID, 회원ID, 경과시간)을 받으면 (FR-300)
    IF 크루런상태 ≠ 진행 이거나 요청자가 끝내지 않은 진행 참가자가 아니면 거부 "참가자 아님"
    ELSE 참가자상태 ← 멈춤, 정지 때 경과시간을 기억한다(크루게시레코드에 남기지 않는다), 크루런중계를 보낸다
        * 정지한 시간은 5.7.4의 종료 상한을 늦추지 않는다 *
크루런중단요청(게시글ID, 회원ID, 누적거리, 경과시간)을 받으면 (FR-192 내 크루런 끝내기)
    IF 크루런상태가 진행·종료가 아니거나 요청자가 진행 참가자가 아니면 거부 "참가자 아님"
    ELSE IF 누적거리가 0~100km 밖이거나 경과시간이 0~24시간 밖이면 거부 "입력 오류"
    ELSE IF 그 참가자의 끝냄여부 = 예 이면 아무것도 바꾸지 않고 완료 (재시도 안전)
    ELSE
        끝냄여부 ← 예, 마감거리 ← 누적거리(없으면 기억한 최신 값), 마감경과시간 ← 경과시간(없으면 최신 값)
        크루게시레코드를 저장한다. 참가자상태 ← 끝냄, 크루런중계를 보낸다
    * 그 참가자 기기는 확인을 받은 뒤 러닝을 끝내고 기록을 저장한다 (2.6). 기록은 크루 주간 거리에 더해진다 *
```

#### 5.7.4 크루런 결과 확정
입력: 러닝기록, 크루게시레코드, 운영기준, 레이스레코드 / 출력: 크루게시레코드, 크루런결과, 크루런중계 / 관련 FR: FR-146, FR-191 (v0.28 변경, CR-160: 도착·순위 대신 종료 두 조건과 합산 결과)
```
러닝모드 = 크루런인 러닝기록이 저장되면
    같은 크루런게시글ID의 모집참여(기록 주인)의 연결기록ID ← 그 기록ID (한 참여에 1건, FR-146)

크루런상태 = 진행인 크루런마다
    IF 진행 참가자 모두 끝냄여부 = 예 이거나, 지금 ≥ 출발일시 + 크루런거리 × 15분(운영기준 크루런종료기준, 제안) 이면

        크루게시레코드를 저장하고 참가자에게 종료 신호를 보낸다
            * 아직 달리던 기기는 종료 신호를 받으면 측정을 끝내 기록을 저장한다 (2.6) *

    참가자마다 거리 ← 연결된 기록의 거리, 없으면 마감거리, 없으면 0. 경과시간·평균페이스도 같은 순서

    크루반영거리 ← 참가자 기록 중 그 주 레이스레코드에 더해진 거리 합 (합산은 5.6.2가 한다)
    첫크루런여부 ← 요청자의 이전 크루런 참여 기록이 없으면 예
    크루런결과 ← 게시글ID + 크루런상태 + 크루런제목 + 크루런거리 + 출발일시 + 크루합산거리 + {표시명 + 거리 + 경과시간 + 평균페이스 + 끝냄여부 + 본인여부}(대기실 입장 순) + (내기록ID) + 첫크루런여부 + 크루반영거리
    * 크루런상태 = 진행 이면 아직 달리는 사람이 있고, 내기록ID가 없으면 기록이 아직 올라가지 않았다. 앱은 다시 읽는다 *
* 지난 크루런의 결과는 5.4.2의 일정 목록에서 다시 연다 (v0.10 변경, CR-08). 연결된 유효 러닝이 Runimal 동행 축의 소셜런 근거다 (6.2, FR-153) *
```

#### 6.2 러닝 기반 유형 갱신
