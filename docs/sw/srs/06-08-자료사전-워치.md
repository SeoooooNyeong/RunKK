### 6.2 자료사전 (이어서: 워치 자료, v0.18)

[06-04-자료사전](06-04-자료사전.md)에 이어지는 항목이다. v0.18 변경 요청 CR-92~CR-102(7.13.14)에서 새로 정의한 워치 자료만 둔다. 기호와 기본 요소 명명 규칙은 06-04 머리를 따르고, 이름은 06-04의 항목과 겹치지 않는다(전수 확인, 7.13.14 변경 점검). 가나다순이다.

```
결과머리말 = [FINISH | GOAL | STOP | WIN | LOSE | BEST | GOOD]
    * 워치 결과 화면의 큰 글자. 모드와 조건별 값은 FR-249 표를 따른다 (v0.18 신규, CR-94) *

미로그인안내 = 안내문
    * 1.1 → 러너(워치 화면). 워치에 로그인 정보가 없을 때 메인 대신 보인다(FR-242) (v0.18 신규, CR-98) *

서버연결상태 = [연결 | 연결끊김]
    * 워치가 서버에 닿는지. 폰을 거친 연결과 워치 자체 무선망을 모두 본다. 워치연결상태(폰-워치)와 다르다(FR-250, FR-251, FR-260) (v0.18 신규, CR-100) *

워치결과표시 = 결과머리말 + (안내문) + 누적거리 + 평균페이스 + 경과시간 + (평균심박수) + (결과보류여부)
    * 2.6·4.5 → 러너(워치 화면). 안내문은 FR-249 표의 결과 문구다. 결과보류여부가 예이면 머리말 대신 "결과를 확인하고 있어요"를 보인다 (v0.18 신규, CR-94) *

워치대결상대목록 = {대결거리 + (본인최고기록시간) + ({경과시간 + 누적거리})} + {유명인기록} + 받은일시
    * 4.6 → 워치 보관. 셀프런·셀럽런 상대 기록을 미리 받아 둔 것(FR-260). 앞 반복은 내 거리별 최고 기록(1km·3km·5km·10km·하프)과 진행용 경과시간별 누적거리, 뒤 반복은 공개된 셀럽 기록(유명인기록, 06-04)이다. 이것으로 연결 없이 달린 셀프런·셀럽런은 워치에서만 판정하고 기록은 자유런으로 보낸다 (v0.18 신규, CR-100) (v0.18 정정, W18). 뒤 반복의 유명인기록은 목록(표시명·거리·완주 시간·출처)만 미리 받고, 경과시간별 누적거리는 러너가 고른 셀럽만 그때 받아 둔다(FR-259) (v0.21 변경, CR-119) *

워치러닝선택 = [자유런 | 배틀런 | 셀프런 | 셀럽런]
    * 워치 메인에서 고른 카드(FR-243). 크루런은 없다. 자유런은 러닝모드 일반, 나머지는 러닝모드 대결이다 (v0.18 신규, CR-93) *

워치로그인정보 = [회원ID + 계정유형 + 인증정보 + 보낸일시 | 로그아웃표시 + 보낸일시]
    * 폰 → 워치(시스템 안 기기 사이 자료). 인증정보는 서버가 발급한 로그인 증표이며 형식과 보호 방법은 설계 단계에서 정한다(NFR-050). 로그아웃표시를 받으면 워치는 로그인 정보, 워치대결상대목록을 지운다(FR-240, FR-241) (v0.18 신규, CR-98) *

워치메인화면 = {워치러닝선택 + 카드제목 + 한줄설명 + (잠금여부)} + 배경그림 + 캐릭터그림
    * 워치 첫 화면(FR-243). 네 카드가 순환한다. 잠금여부는 공개기능목록(FR-223)에서 정한다 (v0.18 신규, CR-93) *

진행중활동표시 = 러닝모드 + 누적거리 + 상태문구 + 돌아가기안내
    * 2.4 → 러너(워치 시계 화면·최근 앱 목록). 상태문구는 "러닝 기록 중", 돌아가기안내는 "탭해서 돌아가기" **(제안)** (FR-255) (v0.18 신규, CR-102) *

측정중기기 = [없음 | 폰 | 워치]
    * 폰과 워치가 연결되어 있을 때 서로 알리는 현재 측정 기기. 폰·워치 동시 측정 막기에 쓴다(FR-252) (v0.18 신규, CR-99) *
```

새 이름 가운데 기본 요소 규칙으로 정의되는 것: 목표거리(거리), 진행률(률), 받은일시·보낸일시(일시), 결과보류여부·잠금여부(여부), 카드제목·한줄설명·상태문구·돌아가기안내(06-04 규칙의 문자열 끝말 "설명", "문구"와 같은 문자열로 본다), 배경그림·캐릭터그림(이미지와 같은 그림 파일), 평균심박수(수). 인증정보는 위 워치로그인정보 설명대로 설계 단계에서 형식을 정한다.

### 6.2 자료사전 (이어서: 배치고사·티어 표시·화면 개편 자료, v0.24)

v0.24 변경 요청 CR-139~CR-145(7.13.19)에서 새로 정의한 자료다. 06-04가 100KB에 가까워 여기에 둔다. 06-04·이 파일의 기존 이름과 겹치지 않는 것을 확인했다(기존 `최근러닝`은 프로필용이라 홈용은 `최근러닝요약`으로 이름을 달리했다). 06-04에서 바뀐 항목: 대결종류(+배치고사), 회원레코드(+배치진행), 대시보드정보(+티어표시·이번달요약·최근러닝요약·5주잔디), 티어(주석).

```
배치진행 = 배치판수 + {배치판기록} + (임시티어)
    * 회원레코드(D1) 안. 확정 티어가 있으면 비어 있다. 탈퇴·게스트 파기 때 회원레코드와 함께 지운다(J24-9). 서버에만 둔다(J24-8) (FR-275, FR-277, FR-278) *
배치판수 = * 0~3 정수. 센 배치고사 판 수 (FR-275) *
배치판기록 = 대결ID + 러닝점수 + 대결거리 + 대결판정
    * 센 판 하나. 포기·무효 판은 들어가지 않는다 (FR-275) *
임시티어 = [브론즈 | 실버 | 골드 | 플래티넘 | 마스터]
    * 센 판 평균 러닝점수의 단계. 본인에게만 보인다. 다른 러너에게 가는 응답에 담지 않는다 (FR-277, FR-282) *
배치고사매칭요청 = 회원ID + 대결거리 + 배치판수 + (임시티어)
    * 4.1 → 4.6. 대기열을 거치지 않는다 (FR-274, FR-276) *
배치판결과 = 대결ID + 대결판정 + 배치종료사유 + 러닝기록ID
    * 4.5 → 1.6. 1.6이 판으로 셀지 정한다 (FR-275) *
배치종료사유 = [도착 | 카운트다운종료 | 포기 | 출발전취소]
배치고사상대기록 = 대결거리 + 상대점수 + 상대페이스 + 완주시간 + 가상닉네임 + {경과시간 + 누적거리}
    * 4.6이 판마다 만드는 가상 상대. 같은 페이스로 달린다. 1판 상대점수 = 가상기록생성규칙의 열린 구간 아래 점수(기본 27), 2·3판 = 임시티어 구간 가운데 점수 (FR-276, J24-1, J24-2). 대결상대기록으로 4.4에 간다 *
상대점수 = * 러닝점수와 같은 형식(VDOT). 배치고사 상대 페이스를 정하는 점수 *
상대페이스 = 페이스
티어표시 = 표시종류 + (티어 | 임시티어)
    * 1.3 → 러너. 본인에게는 확정·임시·배치중, 다른 러너에게는 확정·배치중만 (FR-282) *
표시종류 = [확정 | 임시 | 배치중]
티어배지 = 티어표시 + 배지크기
    * 엠블럼 6모양(배치 중 「?」, 브론즈~마스터)과 글자. 색만으로 구분하지 않는다 (FR-283) *
배지크기 = [아주작게 | 작게 | 크게]
배틀런진입시트 = 랜덤대결카드 + 친구대결카드
    * 랜덤대결카드 = (배치판수) + (티어배지). 배치 중이면 「배치고사 n/3」 (FR-284) *
랜덤대결카드 = (배치판수) + (티어배지)
친구대결카드 = * 고정 문구와 두 캐릭터 *
랜덤대결화면 = 티어배지 + 대결거리 + {대결거리 + (거리별최고기록)}
    * 확정 티어 러너 (FR-285) *
거리별최고기록 = 대결거리 + 경과시간 + 시작일
    * 그 거리 본인 최고 기록. 없으면 비운다 (FR-063, FR-285) *
배치고사진행화면 = 배치판수 + (티어배지) + 대결거리
    * FR-279 *
배치고사판결과화면 = 기록상세 + 대결판정 + 배치판수 + (티어배지) + 판인정여부
    * FR-280. 판인정여부 = [예 | 아니오] *
판인정여부 = [예 | 아니오]
배치고사완료화면 = 티어 + {배치판기록}
    * FR-281. 승·패·무 수를 함께 보인다 *
친구대결화면 = (최근대결친구목록) + 대결거리
    * FR-286 *
최근대결친구목록 = {회원ID + 표시명 + 캐릭터성별 + 함께달린일시}
    * 나와 친구 대결을 끝낸 상대, 최근 순 3명까지(제안), 탈퇴 러너 제외. 고르는 것은 초대를 묶지 않는다 (FR-286, J24-18) *
이번달요약 = 거리 + 횟수
    * 이번 달 1일 0시부터의 유효 러닝 (FR-287) *
최근러닝요약 = 기록ID + 러닝모드 + (대결종류) + 시작일시 + 거리 + 경과시간 + 평균페이스
    * 기록 목록 맨 위 1건 (FR-287) *
5주잔디 = {날짜 + 달림여부}
    * 이번 주(월요일 시작)를 포함한 35칸. 달림여부 = 그날 유효 러닝 1건 이상. 오늘 뒤 날짜는 미래 칸 (FR-287) *
달림여부 = [예 | 아니오 | 미래]
러닝결과화면 = 기록상세 + (적립리워드) + {성과}
    * FR-289. 심박 구간은 4단계(FR-185의 4·5구간을 합침, J24-17) *
성과 = [신기록 | 크루목표반영 | 리워드]
```

### 6.2 자료사전 (이어서: 얼굴 작업·ai 자료 파기 자료, v0.26)

v0.26 병합(7.13.21)에서 정의한 자료다. 얼굴 작업은 변경 요청 CR-154(FR-293~FR-298, [얼굴비동기-박](얼굴비동기-박.md)), ai 자료 파기는 FR-272 보충([ai-자료파기-박](ai-자료파기-박.md), 새 CR 없음)이다. 06-04가 100KB에 가까워 여기에 둔다. 06-04의 `얼굴변환요청`·`변환얼굴`·`얼굴구성`·`SD얼굴부위`·`행위종류` 주석에 이 절을 연결했다.

```
얼굴작업접수 = 셀카이미지
    * 러너 → 6.3. JPEG·PNG, 최대 1MiB, 가로·세로 4096 이하. 앱은 회원ID를 보내지 않고 서버가 인증에서 읽는다. FACE_TRANSFER 동의·셀카생성사용·성공 일일 한도·실패 상한을 지킨다 (FR-293, FR-155) *
얼굴작업요청 = 회원ID + 셀카이미지
    * 6.3 → 얼굴 변환 서비스(ai 서버 얼굴 작업). 회원ID는 경로 값이다. 이름·연락처·프로필은 넣지 않는다 (NFR-024 v0.26) *
얼굴작업 = 작업ID + 얼굴작업상태 + (머리ID) + (작업오류)
    * 6.3 → 러너. 접수 응답은 202, 상태 조회 응답은 200(FAILED도 200). 다른 회원의 작업ID는 ai 서버에 묻기 전에 404 (FR-293~FR-295) *
얼굴작업상태 = [QUEUED | RUNNING | SUCCEEDED | FAILED]
    * 대기 | 만드는 중 | 완료 | 실패. 끝나지 않은 작업은 변환 실패로 안내하지 않는다 (FR-295) *
작업오류 = 오류코드 + (오류문구)
    * FAILED의 사유(error.code) (FR-295) *
머리결과 = 머리ID + 얼굴이미지 + 눈이미지 + 머리카락이미지 + 합성정보
    * 6.3 → 러너. ai 서버 계약 이름은 faceImage·eyesImage·hairImage. SUCCEEDED 뒤에만 오고, 끝나지 않았으면 409 JOB_NOT_READY. 최근 완료 머리 조회는 없으면 404 HEAD_NOT_FOUND (FR-296) *
머리참조 = 회원ID + 작업ID
    * 캐릭터레코드의 얼굴구성 값. 고른 새 얼굴의 조회는 기존 프로필 얼굴 공개 규칙을 따른다 (FR-296, FR-298) *
얼굴작업기록 = 회원ID + 사진해시 + 작업ID + 접수일 + 얼굴작업상태 + 반영여부
    * 서버 저장. 셀카 원본·이미지를 두지 않는다. 같은 사진을 다시 보내면 기존 작업을 돌려주고, 결과를 여러 번 읽어도 반영여부로 생성 횟수를 한 번만 늘린다 (FR-297, FR-157) *
ai자료파기응답 = [세션결과수 + 코치메시지수 + (아바타이미지수) | 미완료]
    * ai 서버 → 1.5. 200의 sessionResults·coachMessages는 음수가 아닌 정수, avatarImages는 있으면 0 또는 1. 없는 사용자와 반복 삭제도 성공이다. 401·422·503·504·통신 실패·손상 응답은 미완료 (FR-272) *
ai자료파기요청기록 = 회원ID + 탈퇴일시 + 파기진행 + 다음실행일시 + 재확인완료여부
    * 1.5 저장. 탈퇴와 같은 트랜잭션에서 만들고 커밋 뒤 바로 ai자료파기지시를 보낸다. 이름·대화·분석 결과·이미지를 두지 않는다. 파기 지시가 없던 기존 탈퇴 회원은 매일 배치가 실제 탈퇴 일시로 만든다(탈퇴하지 않은 회원은 대상 아님) (FR-272) *
파기진행 = [대기 | 완료 | 경과알림]
    * 대기: 처음이거나 실패해 다음 날 03시 05분 배치를 기다림. 완료: 성공(첫 성공 뒤에도 탈퇴 7일 뒤 한 번 더 지시하고, 그것도 성공하면 재확인완료). 경과알림: 탈퇴 7일이 지나도 실패해 감사 AI자료파기경과를 남김, 그 뒤에도 매일 다시 지시 (FR-272) *
```
