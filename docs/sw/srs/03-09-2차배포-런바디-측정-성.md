#### 3.9.1 런바디 러닝 점수와 최근 10회 변화

| 항목 | 내용 |
|------|------|
| ID | FR-301 |
| 명칭 | 런바디 러닝 점수 |
| 설명 | 러너는 런바디 러닝 선택 목록에서 러닝마다 런바디 점수(화면 이름 「러닝 점수」)와 직전 점수 대비 변화를 볼 수 있어야 한다 (v0.29 추가, CR-166) |
| 입력 | 런바디요청(목록), 런바디분석작업(상태, 런바디점수), 러닝기록목록 |
| 처리 | 런바디 점수는 분석 결과의 다섯 축 점수 가운데 점수가 있는 축들의 평균을 반올림한 값(0~100, 0.5는 올림)이다. 미산출 축은 빼고 센다. 점수 있는 축이 없으면 점수가 없다. 예: 78, 84, 72, 미산출, 80 → 314 ÷ 4 = 78.5 → 79. 분석이 완료될 때 점수 하나만 분석 작업에 남기고 결과 본문은 남기지 않는다(FR-265의 "결과는 ai에서 읽는다" 원칙의 예외). 그때 읽지 못했거나 v0.29 전에 완료된 작업은 그 러닝의 결과를 처음 볼 때(FR-266) 채우고, 그 전까지 점수는 없다(일괄 채우기 없음). 변화는 이 러너의 직전 점수 있는 러닝(러닝 시작 순서) 대비 차이이며 양수는 「▲ n」, 음수는 「▼ n」이다. 이 러닝이나 이전 러닝에 점수가 없으면 변화를 보이지 않는다. 목록은 러닝 시작 일시의 역순이고(늦게 올린 예전 러닝이 맨 위에 오지 않는다 (v0.29 보정, MR !91 결함 수정 e2e 3, 사용자 결정 2026-11-08: 저장 순서에서 바꿈) 한 번에 1~100개를 읽는다. 점수를 읽지 못하거나 기능이 닫혀 있으면 러닝 목록은 점수 없이 그린다. 기다리던 분석이 끝나면 점수를 다시 읽는다 |
| 출력 | 런바디점수목록 |
| 우선순위 | 필수 (확정) **(2차 배포)** |
| 출처 | 피그마 G-30 「러닝 점수 78 ▲6」, runbody contract v1.2 7절, 2026-11-07~08 사용자 결정(점수 하나만 저장, 일괄 채우기 없음), 변경 요청 CR-166(7.13.23) |
| DFD | 3.4.5 |

| 항목 | 내용 |
|------|------|
| ID | FR-302 |
| 명칭 | 런바디 최근 10회 변화 |
| 설명 | 러너는 런바디 요약에서 최근 10회 러닝과 직전 10회 러닝의 변화를 볼 수 있어야 한다 (v0.29 추가, CR-166) |
| 입력 | 런바디요청(변화), 러닝기록(유효 러닝), Runimal유형 |
| 처리 | 유효 러닝을 순번(저장 일시, 기록 ID 순. 티어·Runimal과 같은 순번)대로 10회씩 묶은 고정 회차를 쓴다. 1~10번째가 1회차, 11~20번째가 2회차다. 마지막으로 다 찬 회차가 최근 10회, 그 앞 회차가 직전 10회다(Runimal 유형 확정 회차 FR-153과 같은 묶음). 23회째면 최근 10회는 11~20번째다. 회차마다 평균 페이스(10회 전체 시간 ÷ 전체 거리), 주간 빈도(10회 ÷ 첫 러닝 날~마지막 러닝 날 날 수 × 7, 날 수가 7보다 작으면 7), 월간 빈도(× 30, 날 수가 30보다 작으면 30), 평균 심박(심박 있는 러닝이 3회 미만이면 없음)을 보인다. 같은 심박 페이스 변화 = 직전 페이스 − 최근 페이스 × 최근 심박 ÷ 직전 심박(반올림, 양수면 「n초 단축」, 음수면 「n초 늘어남」). 심박 있는 러닝이 회차마다 3회 미만이면 보이지 않는다. 예: 직전 362초·149bpm, 최근 348초·150bpm → 12초 단축. 주간/월간 토글은 빈도 줄만 바꾼다. 나의 러닝 유형(확정, 없으면 임시)을 함께 보인다. 10회 전이면 「러닝 N번 더 하면 최근 10회 변화를 보여 드려요」, 1회차면 최근 10회 값만 변화·직전 값 없이 보인다. 이 값은 분석 서비스를 부르지 않고 저장된 러닝 기록으로 셈한다. 읽기 실패나 기능 닫힘이면 그 카드 자리에 공통 오류 문구와 다시 시도를 보인다. 회차는 러닝 시작 순서가 아니라 저장 순서를 그대로 쓴다(티어·Runimal 순번과 같아야 한다 (v0.29 보정, MR !91 결함 수정 e2e 3, 사용자 결정 2026-11-08) |
| 출력 | 런바디변화 |
| 우선순위 | 권장 (확정) **(2차 배포)** |
| 출처 | 피그마 G-14 「최근 10회 변화」·「2회차, 11~20번째 러닝」, runbody contract v1.2 8절, 2026-11-08 사용자 결정(10회 고정 회차 비교), 변경 요청 CR-166(7.13.23) |
| DFD | 3.4.5 |

#### 3.9.2 속도·케이던스

용어(1.3에 넣었다): **케이던스**는 분당 걸음 수(spm)다. **움직임 표본**은 측정 시각과 그때의 속도(m/s)·케이던스(spm) 한 묶음이다. 둘 중 하나는 없을 수 있다.

| 항목 | 내용 |
|------|------|
| ID | FR-303 |
| 명칭 | 속도·케이던스 측정 |
| 설명 | 시스템은 러닝 측정 중 기기가 재는 속도와 케이던스를 움직임 표본으로 남겨야 한다 (v0.29 추가, CR-168) |
| 입력 | 위치측정값(속도), 걸음측정값 |
| 처리 | 측정 중(일시정지 제외)에만 남기고 쓸 수 없는 값(음수, 숫자 아님)은 버린다. **폰 단독**: 위치가 속도를 함께 알려 주고 정확도가 30m 이하이면 그 속도를 쓴다. 케이던스는 폰 걸음 센서의 누적 걸음 수로 최근 10초 동안의 분당 걸음 수를 셈한다. **워치 단독**: 워치가 운동 중 속도와 분당 걸음 수(없으면 누적 걸음 수로 셈함)를 지원하고 신체 활동 권한이 있으면 쓴다. 지원하지 않거나 권한이 없거나 지원 조회가 실패하면 넣지 않는다. **워치 동행**: 워치가 손목 걸음을 심박 묶음과 함께 폰에 보내고, 손목 케이던스가 있으면 폰 걸음 센서 케이던스를 쓰지 않는다(폰 속도는 그대로). 손목 걸음은 심박과 같은 허용 규칙이라 심박 동의(FR-014)가 없으면 보내지 않는다. 권한이 없거나 센서가 없으면 케이던스 없이 측정을 이어 간다. 별도 동의는 받지 않는다. 측정 중에 신체 활동 권한을 허용하면 그때부터 걸음을 잰다 (v0.29 보정, MR !91 결함 수정 AN-4) |
| 출력 | 러닝기록(움직임표본) |
| 우선순위 | 권장 (확정) **(2차 배포)** |
