### 3.4 대결 관리 (DFD 프로세스 4)

| 항목 | 내용 |
|------|------|
| ID | FR-080 |
| 명칭 | 랜덤 매칭 요청 |
| 설명 | 러너는 배틀런 화면의 랜덤 대결에서 대결 거리 1·3·5·10km 중 하나를 골라 랜덤 매칭을 요청할 수 있어야 한다 (v0.13 변경, CR-49) |
| 입력 | 매칭요청(회원ID, 대결거리), 회원레코드(티어, 위치수집 동의여부) |
| 처리 | 홈의 배틀런 카드("랜덤 또는 친구와 대결")를 누르면 배틀런 화면을 연다. 배틀런 화면은 랜덤 대결과 친구 대결(FR-227) 두 분절이고 처음에는 랜덤 대결이 골라져 있다. 랜덤 대결 분절에는 1·3·5·10km 카드를 두고 카드마다 그 거리의 내 최고 기록과 날짜(FR-063)를 보인다. 기록이 없는 거리도 고를 수 있다 **(제안)**. 처음에는 기본대결거리(FR-109) 카드가 골라져 있고 **(제안)**, 러너가 카드를 고른 뒤 "n km 랜덤 매칭 시작"을 눌러야 매칭을 요청한다. 홈에서 기본대결거리로 바로 매칭을 요청하던 흐름은 없앤다 (v0.13 변경, CR-49). 대결거리가 1·3·5·10km가 아니면 거부한다. 위치 수집 동의가 없으면 거부한다. 티어가 언랭(유효 러닝 3회 전)이면 랜덤 대결 분절의 매칭 시작 버튼에 자물쇠를 보이고, 누르면 매칭을 요청하지 않고 "러닝을 n번 더 뛰면 배틀런이 가능해요!"를 보인다. n은 3 − 유효 러닝 횟수이고 1보다 작으면 1이다. 유효 러닝 횟수를 알 수 없으면 "러닝을 더 뛰면 배틀런이 가능해요!"를 보인다. 친구 대결 분절은 잠그지 않는다 (v0.15 변경, CR-61). 그래도 언랭 러너의 랜덤 매칭 요청이 서버에 오면 거부한다 (v0.13 변경, CR-32). 언랭 러너도 친구 대결(FR-227)은 할 수 있다 (v0.13 추가, CR-50). 이미 매칭 대기 중이거나 친구 대결 초대 대기 중(FR-228)이거나 진행 중인 대결이 있으면 거부한다 (v0.13 변경, CR-50). 통과하면 대기열레코드를 만들고, 요청한 대결거리를 대결설정의 기본대결거리로 저장한다(다음에 배틀런 화면을 열 때 이 거리가 골라져 있다, N-10) (v0.13 변경, CR-49). 매칭 대기 화면에서 거리를 바꾸는 기능은 두지 않는다(N-10 제외). 재요청 횟수는 제한하지 않는다(Q-31). 언랭 거절(RANKED_ONLY)을 받은 매칭 화면은 그 화면을 떠날 때까지 매칭을 다시 요청하지 않아야 한다 (v0.12 추가, CR-22) |
| 출력 | 매칭접수결과(대기등록 / 거부 + 거부사유), 대기열레코드, 회원레코드(대결설정의 기본대결거리) |
| 우선순위 | 필수 (확정) |
| 출처 | plan.md 3.1 F-05 ②, 3.3 법적, 2026-10-19 결정 Q-03, Q-31, 와이어프레임 2-1 "지난번 거리 그대로", 와이어프레임 결정 N-10, 변경 요청 CR-22(7.13.8), CR-32·CR-49·CR-50(7.13.9, 피그마 C-1), CR-61(7.13.11, 2026-10-31 사용자 결정 D115) |
