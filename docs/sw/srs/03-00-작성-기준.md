#### 3.0.2 확정·가변 표시와 삭제
우선순위 칸에 확정 또는 가변을 함께 적는다. 가변은 규칙 값이 아직 남은 미결(7.10.2)에 걸린 요구다. 결정으로 없어진 요구는 번호를 비워 두지 않고 "삭제됨(사유)"으로 남긴다(FR-037, FR-046, FR-084, FR-118, FR-119, FR-150, FR-167). v0.8에서 FR-004·FR-124를 와이어프레임 결정으로 되살렸다(W-01, W-02). v0.10에서 FR-118·FR-119를 지우고(CR-04), v0.8에 지웠던 FR-138·FR-141을 같은 번호로 되살렸다(CR-08, N-15 번복) (v0.10 변경). v0.13에서 FR-028(가입 때 기록 공개 고지, CR-39), FR-182(앱 화면 잠금, CR-26), FR-195(장시간 정지 자동 종료, CR-25)를 지웠다. 이로써 삭제된 요구는 FR-028, FR-037, FR-046, FR-084, FR-118, FR-119, FR-150, FR-167, FR-182, FR-195 10건이고, 유효 FR은 219건이다 (v0.13 변경).

**(2차 배포) 표기 (v0.13 신규, CR-24).** 첫 정식 출시(1차 배포)에서 빼는 요구는 요구에서 지우지 않고 우선순위 칸에 **(2차 배포)** 를 붙인다. 요구의 일부만 미루면 그 부분을 우선순위 칸에 적는다(예: FR-068은 뒷면만, FR-162는 얼굴 고르기 안내만). 표시가 없는 요구는 1차 배포 대상이다. 2차 배포 요구의 진입점은 1차 배포 앱에서 잠그거나(하단 크루 탭) 숨기고, 잠긴 진입점은 FR-223이 안내한다. 추적표(7.1)의 배포 열이 같은 구분을 한 번 더 보인다. 확정·가변 구분과는 별개이며, 둘을 함께 적을 수 있다(예: 필수 (확정) (2차 배포)).

번호 규칙(v0.8): 절마다 비어 있던 번호(FR-048, FR-049, FR-078, FR-079, FR-109, FR-147~FR-149, FR-168, FR-178)를 먼저 썼고, 모자란 요구는 FR-180부터 붙였다. FR-180~FR-193은 절과 관계없이 v0.8에서 추가한 번호이며 해당 절 안에 둔다. v0.10에서 추가한 FR-194~FR-218도 절과 관계없이 이어 붙인 번호이며 해당 절 안에 둔다. v0.11의 FR-219(자유런 취소)는 3.2 안에 둔다. 기존 번호는 다시 매기지 않았다 (v0.10 추가).

#### 3.0.4 경계·오류 해석 기준 (2026-10-21, test.md v0.2)

테스트 단계에서 기대 결과를 정하며 여러 FR에 걸쳐 쓰이는 해석 규칙을 한 곳에 모았다. 개별 FR이 따로 정하지 않은 경계·오류는 아래 기준으로 읽고, FR 본문에는 같은 문장을 반복하지 않는다 (v0.9 추가, test.md v0.2).

| 구분 | 기준 | 적용 예 |
|------|------|---------|
| 시간 경계 "N 이내", "N 안에" | 경과 ≤ N이다. 정각을 포함하고 아직 유효하다 | 탈퇴 자료 7일 안 삭제(FR-021)는 7일 정각에도 삭제 대상이다. 최근 12주는 84일 이내(FR-053) |
| 시간 경계 "N 뒤 만료", "N 지나면", "N 지났을 때", "지나도" | 경과 ≥ N이면 정각에 만료·종료한다 | 접근 토큰 1시간(FR-001), 알림 30일(FR-175), 대결 결과 보류 24시간(FR-092, FR-108), 크루런 종료 기준(FR-191), 승인제 가입 신청 7일(FR-121) |
| 시간 경계 시작 시각 "N 전에 개방" | 정각부터 가능하다 | 크루런 대기실(FR-147) |
| 쿨타임 "N 동안 불가" | 경과가 N 미만이면 불가이고 N 정각부터 가능하다 | 크루 가입·퇴장 쿨타임 24시간(FR-124) |
| 수량 경계 | "최대 N"은 N을 허용하고 N+1부터 거부한다. "N 이상"은 N을 포함하고 "N 초과"는 N을 뺀다 | 닉네임 2~20자(FR-003), 미전송 기록 최대 20건(FR-039) |
| 오류 응답 매핑 | 입력 형식·범위 위반 400, 인증 없음·인증 실패 401, 권한 없음 403, 없는 자원 404, 상태 충돌 409, 업무 규칙 위반은 사유 코드와 함께 응답한다. 응답 본문에 입력값을 되돌려 주지 않는다(NFR-024). 크루 밖 러너의 크루 전용 요청(3.0.3)은 권한 없음으로 거부하고 자료를 바꾸지 않는다(응답 코드는 설계 5.7) (v0.10 보완, test.md v0.6 TF-VB-24, TF-SY-26) | 운영자 로그인 실패는 401이고 토큰을 발급하지 않는다 |
| 앱의 응답 해석 | 409에 사유 코드가 없으면 상태 충돌 기본 사유로 거부 처리하고, 400·403·404도 사유 코드를 달아 거부 처리한다. 499까지의 4xx는 서버가 거부한 것이라 기록을 지우지 않고 거부 사유와 함께 보존하며, HTTP 상태로 볼 수 없는 값(600 등)은 재시도 대상으로 본다 | 미전송 기록 전송(FR-038~FR-040) |
| 없는 자원·남의 자원 | 없는 ID와 남의 자원 ID는 모두 404로 같게 응답해 존재 여부를 알리지 않는다. 남의 자원을 바꾸려는 시도는 상태 변화가 0건이다 | 모든 ID 지정 조회·변경 |
| 동시 요청·중복 제출 | 같은 요청 둘 중 정확히 하나만 반영하고 다른 하나는 409 또는 같은 결과(멱등)로 응답하며 저장은 1건이다 | 유명인 기록 중복 등록은 두 번째 요청이 409 사유 코드이고 기록·감사기록이 각 1건이다(FR-170) |
| 빈 값·목록 밖 값 | 필수 항목이 비면 400이다. 열거형 목록 밖 필터 값은 400이며 조회 0건이고 입력값을 되돌리지 않는다. 선택 항목이 비면 자료사전·설계의 기본값을 쓰고 없으면 "미설정"이다 | 크루 목록 필터(FR-117) |
| 정해지지 않은 표시 문구 | 문구 대신 관찰 가능한 결과(화면 상태, 사유 코드, 저장 건수)로 판정하고 문구는 SRS 미정으로 둔다 | 규칙 기반 코멘트 20개 중 하나(FR-066), 개인 랜드마크가 없을 때의 표기(FR-051) |
| SRS 안 문장이 충돌할 때 | 결정 기록(7.10), 3장 FR 본문, 6.3 소단위 명세, 6.2 자료사전, 2.6 시나리오 순으로 앞선 쪽을 따른다. 같은 단계 안이면 수치·조건이 더 구체적인 쪽을 따른다 | v0.9에서 이 순서로 정정한 문장에 "v0.9 정정" 표시를 달았다 |
| 위 기준으로 정해지지 않을 때 | 사용자 안전·개인정보 쪽으로 보수적인 값(거부, 비공개, 저장 안 함)을 따른다 | 가입 연령 판정(FR-004), 재동의 때 파기 지시 유지(FR-026) |
