출처: `docs/sw/plan.md` v0.28 부록 G와 결정 A1~A9(`runkk-work/ai-api/decisions.md`), 계약 기준 runkk-ai OpenAPI 0.1.0(`runkk-work/ai-api/runkk-ai-openapi-0.1.0.json`), 2026-11-02 사용자 결정 4건(코치 질문 한도 하루 20회, 코치 대화 보관 90일, 런바디 분석 대상은 폰·워치 모든 러닝, 성능 제안값 확정). 승인자: 사용자(대화 결정, 2026-11-01·02). 일정: schedule.md v0.8 12절 A1(임계 경로).

배경도 균형: ai 서버를 새 단말로 더한다. 들어가는 흐름은 코치질문요청·런바디분석요청·모델변경지시·ai자료파기지시, 나오는 흐름은 코치답변조각·런바디분석상태·런바디분석결과·런바디월간집계·모델목록이다. ai 서버가 외부 LLM 서비스와 주고받는 흐름은 ai 서버 안의 일이라 이 시스템 경계 밖이다. 자료가 프로세스를 지나면 이름이 바뀐다(코치답변조각 → 코치답변, 런바디분석결과 → 런바디화면자료, 모델목록 → 모델현황).

자료사전 추가 항목은 [06-08-자료사전-워치](06-08-자료사전-워치.md) 끝 "v0.20 ai 연결 자료"에 두었다.

소단위 명세서

```
3.4.4 코치 대화
  IF 회원레코드.LLM전송동의여부 = 아니오 THEN 동의 안내를 보내고 끝낸다
  IF 오늘 질문 수 >= 코치일일질문한도 THEN 한도 안내를 보내고 끝낸다
  IF 질문문장 길이가 1~500자가 아니면 THEN 입력 오류 안내를 보내고 끝낸다
  대화ID가 있으면 그 대화를 잇고, 없으면 새 대화를 연다
  코치질문요청을 ai 서버로 보낸다
  코치답변조각을 받는 대로 러너에게 이어 보낸다
  IF 종료표시를 받으면 THEN 오늘 질문 수를 1 늘린다
  ELSE IF 실패 또는 시간 초과면 THEN 다시 묻기 안내를 보내고 질문 수를 늘리지 않는다

3.4.5 런바디 분석
  러닝기록이 저장되면:
    IF 런바디분석사용 = 꺼짐 OR 집계 제외 기록 THEN 요청하지 않는다
    런바디분석요청을 만들어 ai 서버로 보내고 작업 상태를 대기로 저장한다
    상태가 완료나 실패가 될 때까지 상태를 조회한다. 실패면 3회까지 다시 요청한다 (제안)
    완료면 런바디분석결과를 저장한다. 3회 모두 실패면 상태를 실패로 둔다
  러너가 런바디를 열면:
    상태가 완료면 결과를, 대기·분석중이면 "분석 중이에요"를, 실패면 "분석하지 못했어요"를 보낸다

7.8 모델 관리
  모델목록요청 → ai 서버의 모델목록과 활성 모델을 보낸다
  모델변경요청이 등록이면: 같은 이름이 있으면 거부, 아니면 등록한다
  활성화면: 등록된 모델이 아니면 거부, 아니면 활성 모델을 바꾼다
  되돌리기면: 직전 활성 모델이 없으면 거부, 아니면 직전 모델로 바꾼다
  변경이 성공하면 감사기록(운영자, 변경 종류, 모델이름, 시각)을 남긴다
```
