#### 7.13.15 워치 v2 구현·리뷰 뒤 갱신 변경 요청 (2026-11-01, v0.19)

출처: `docs/sw/design-oo/05-17-설계-결정-v0.23.md` 9절 "srs 갱신 요청" 8건(D-395~D-413, 12차 코드 리뷰 U12-5·U12-6·U12-9~U12-11), 2026-11-01 사용자 결정 W23~W28(`runkk-work/watch-v2/decisions.md`). 승인자: 사용자(대화 결정, 2026-11-01. W08의 문서 반영 위임). 구현 사실은 설계서 v0.23 결정 표와 워치 작업 트리 S15P31A207-watch의 문구 파일(`wear/src/main/res/values/strings.xml`)·`WatchFlowViewModel.REJECTED_NOTICES`를 읽어서만 확인했다.

처리 원칙:

- 이미 구현했거나 사용자가 정한 동작을 요구 문장에 맞춘다. 새 FR·NFR은 없다. 새 CR은 CR-103부터, 새 제약은 C-023이다.
- 기술 이름(경로 `DELETE /auth/watch-session`·`POST /auth/watch-session`, 응답 코드 403·429·503, 마이그레이션 V33~V35, gzip)은 2.4 제약 C-023과 이 절의 구현 대조에만 쓴다. 3~5장은 기술 중립 표현을 쓴다.
- 9절 요청 가운데 FR-181·FR-248의 길게 누르기 시간은 사용자 결정이 없어 "1초 **(제안)**"을 그대로 둔다(아래 "바꾸지 않은 요청").
- NFR-050에 들어가지 않는 서버 규칙(발급 한도, 세대 폐기 방식, 응답 압축)은 5.4 통신 인터페이스와 C-023에 둔다.
