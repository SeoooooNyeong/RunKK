## 6. 분석 모델

### 6.1 자료 흐름도

#### 6.1.1 표기와 구성

- 표기는 `references/dfd-notation.md`를 따른다. `[ ]` 단말(□), `( )` 프로세스(○), `║ ║` 저장소, `──▶` 자료 흐름. 자료 흐름 이름은 명사, 프로세스 이름은 "동사+목적어"를 명사형으로 쓴 형태(예: 성적 검증 → 이 문서의 위치 포인트 검증)다.
- 각 레벨은 프로세스마다 들어오고 나가는 흐름을 모은 그림(별 모양 배치)과 흐름 목록 표로 나타낸다. 같은 단말·저장소를 여러 번 그린 것은 선 교차를 피하기 위해서다. 그림과 표는 같은 원본 자료에서 만들었다.
- DFD에는 순서가 없다. 그림의 줄 순서, 표의 번호는 읽기 위한 번호이지 실행 순서가 아니다. 순서와 조건은 6.3 소단위 명세서와 6.4 상태전이도가 맡는다.
- Level 1에서는 사람 단말(러너, 크루장, 운영자)과의 흐름을 배경도와 같은 복합 흐름 이름으로 쓴다. Level 2부터는 자료사전의 구성 흐름으로 나눈다. 복합 흐름의 구성은 6.2 자료사전에 있다.
- Level 2·3 그림에서 다른 상위 프로세스는 Level 1 번호로 표시한다(예: `( 4 대결 관리 )`). 해당 흐름의 실제 도착 하위 프로세스는 그 프로세스의 하위 DFD에 있다.
- v0.10에서 배경도에 더한 사람 단말 흐름 8개(2.1의 L0-31~L0-33, L0-35~L0-39. L0-34 근접알림은 지우고 번호를 비웠다)는 Level 1에서도 배경도와 같은 이름으로 쓴다. 게스트시작요청·계정연동요청·일시정지요청·신고요청·신고결과는 단독 흐름이고, 크루채팅요청·크루채팅정보·신고처리는 Level 2에서 구성 흐름으로 나뉘는 복합 흐름이다(6.1.3 아래 표) (v0.10 추가, CR-01·CR-03·CR-08·CR-09. v0.10 변경, CR-02: L0-34 삭제).
- [크루장] 단말은 크루 관리 권한으로 요청하는 사람(크루장, v0.10부터 운영진 포함)이다. 크루장 전용 요청(크루 설정 변경, 크루장 양도, 크루 삭제, 강제 퇴장, 운영진 지정)인지 운영진도 보낼 수 있는 요청(가입 결정, 가입 대기 조회, 남의 게시글 삭제, 공동 목표 설정)인지는 프로세스가 3.0.3 권한표로 검사한다(FR-128). 게시글류 작성(응원·일정·공지·투표·게시글), 채팅, 신고는 크루 구성원의 [러너] 흐름으로 그리고, 공지 작성 권한은 5.4.3이, 남의 채팅 메시지 삭제 권한은 5.8이 검사한다 (v0.10 추가, CR-08).
- 근접알림은 4.4가 만들어 2.4로 보내는 프로세스 사이 흐름이다. 러너는 2.4가 바꾼 워치표시정보(비프음·진동)로 받으며, 이것은 러닝화면정보(L0-08)의 구성이다. 그래서 배경도에는 근접알림 흐름을 따로 두지 않는다 (v0.10 추가, CR-02. 배경도 L0-34 삭제는 v0.10 변경).
- v0.13(7.13.9)에서 외부 단말 [카카오톡]을 더했다. 친구 대결(FR-227~FR-230)의 초대 메시지 전송(4 → 카카오톡 초대메시지, 배경도 L0-40)과 초대 링크로 앱 열기(카카오톡 → 4 초대링크, 배경도 L0-41)가 이 단말과 주고받는 흐름이다. 친구 대결은 새 프로세스를 만들지 않고 4.1(초대 등록·대기·취소·만료)과 4.2(참가·거절 → 대결 생성)에 싣는다. 친구대결초대레코드는 ║D5 매칭 대기열║에 둔다. 카카오톡은 사람 단말이 아니므로 Level 1에서도 배경도와 같은 이름을 쓴다 (v0.13 신규, CR-50).
- v0.13에서 화면잠금요청(FR-182 삭제)은 러닝조작의 구성에서, 자동종료안내(FR-195 삭제)는 러닝화면정보의 구성에서 빠졌다. 진행알림표시(FR-224)는 러닝화면정보의 구성에 들어간다. 이 복합 흐름의 이름은 배경도·Level 1에서 그대로여서 흐름 수는 변하지 않는다 (v0.13 변경, CR-25·CR-26·CR-33).
- 2차 배포로 미룬 요구(크루 전체, 카드 뒷면·공유, 아바타 꾸미기, 7.13.9)의 프로세스(5 전체, 3.5, 6.3, 6.5~6.8의 일부)와 흐름은 DFD에서 지우지 않고 그대로 둔다. 1차 배포 앱이 진입점을 잠그거나 숨길 뿐 시스템 모델은 바뀌지 않는다. 잠긴 진입점 안내(FR-223)는 7.6의 잠금진입요청·잠금안내다 (v0.13 신규, CR-24).

#### 6.1.3 Level 1

개요(프로세스 사이 흐름만):

```
                         ┌──────────────────── 러닝진행값 ────────────────────┐
                         │                                                    ▼
( 1 회원 관리 )     ( 2 러닝 측정 )     ( 3 기록 분석 )                ( 4 대결 관리 )
                         ▲                   │                                │
                         └───────────────────┼─────────── 근접알림 ───────────┘   (v0.10 추가, CR-02)
                                             │ 알림사건          ( 4 )──알림사건──┐
                                             ▼                                    │
( 5 크루 관리 ) ──알림사건──▶ ( 7 운영 관리 ) ◀───────────────────────────────────┘
                                  ▲
                                  └──알림사건── ( 6 캐릭터 관리 )
                                             │
                                             └──푸시요청──▶ [푸시 알림 서비스]
```
