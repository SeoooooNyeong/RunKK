# 결합도(Coupling) 6등급

`sw-design` review 2단계에서 읽는다. 결합도는 **서로 다른 두 모듈 사이의 연결 강도**다. 낮을수록 모듈이 독립적이고, 높을수록 한쪽을 고치면 다른 쪽이 흔들린다. 등급은 낮은(좋은) 것부터 높은(나쁜) 것 순서로 데이터 → 스탬프 → 제어 → 외부 → 공통 → 내용이다.

## 1. 등급 정의

### 데이터 결합도 (Data Coupling) — 가장 낮음, 이상적

한 모듈이 다른 모듈에 **필요한 단순 값만** 매개변수로 넘기고, 호출된 모듈은 결과만 돌려준다. 서로의 내부 구조를 전혀 몰라도 동작한다.

```python
# 호출하는 쪽
area = calculate_area(radius=5)

# 호출받는 쪽
def calculate_area(radius):
    return 3.14 * radius * radius
```

특징: 인터페이스(입출력 형식)만 맞으면 독립적으로 수정·재사용·테스트할 수 있다.

### 스탬프 결합도 (Stamp Coupling)

배열·구조체·레코드·객체·DTO 같은 **복합 자료 구조 전체**를 넘긴다. 받는 쪽이 그중 일부만 쓰더라도 구조 전체에 의존하게 된다.

```python
def print_student(student):          # student 딕셔너리 전체를 받음
    print(student['name'], student['score'])   # 두 필드만 씀

process({'name': '홍길동', 'score': 90, 'dept': '컴공', 'year': 2})
```

문제: 자료 구조에 필드를 추가·삭제하면 그 구조를 받는 모든 모듈을 다시 확인해야 한다. 쓰지도 않는 필드 변경에 영향받는다.

언제 허용하는가: 받는 쪽이 구조의 대부분(절반 이상)을 쓸 때. 두 필드만 쓰는데 열 필드짜리 구조를 넘기면 "검토" 표시를 하고 필요한 값만 넘기는 개선안을 쓴다.

### 제어 결합도 (Control Coupling)

flag, mode, type 같은 **제어 신호**를 넘겨 호출받는 모듈의 **내부 분기를 호출하는 쪽이 결정**한다.

```python
def print_report(data, detailed):    # detailed 플래그
    if detailed:
        print_full(data)
    else:
        print_summary(data)
```

문제: 호출하는 쪽이 호출받는 쪽의 내부 논리(상세/요약 두 갈래가 있다는 것)를 알아야 한다. 분기가 늘면 양쪽을 함께 고친다.

개선: 플래그 대신 `print_full()`과 `print_summary()`로 분리하거나, 다형성(전략 객체)으로 분기를 호출자 밖으로 뺀다.

### 외부 결합도 (External Coupling)

두 모듈이 **외부 자원**(파일, 장치, 환경 변수, DB 테이블, 프로토콜 형식)을 직접 공유한다.

```python
CONFIG_FILE = "config.json"

def read_config():                   # 모듈 A
    with open(CONFIG_FILE) as f: ...

def write_config():                  # 모듈 B
    with open(CONFIG_FILE, 'w') as f: ...
```

문제: 외부 자원의 형식·위치가 바뀌면 그것을 직접 쓰는 모든 모듈이 바뀐다. 테스트 때 외부 자원을 준비해야 한다.

개선: 외부 자원 접근을 인프라 모듈 하나에 몰고, 나머지는 그 모듈의 인터페이스만 쓴다.

### 공통 결합도 (Common Coupling)

여러 모듈이 **전역 변수**(또는 static 가변 상태, 싱글턴의 가변 필드)를 함께 읽고 쓴다.

```python
shared_count = 0                     # 전역

def module_a():
    global shared_count
    shared_count += 1

def module_b():
    print(shared_count)              # A가 언제 바꿨는지 모름
```

문제: 누가 언제 값을 바꿨는지 추적할 수 없다. 오류가 전역 변수를 타고 어디로든 전파된다. 모듈을 따로 테스트할 수 없다.

개선: 전역 변수를 없애고 필요한 값을 인자로 넘긴다. 설정값이면 불변 설정 객체를 주입한다.

### 내용 결합도 (Content Coupling) — 가장 높음, 최악

한 모듈이 다른 모듈의 **내부 데이터나 코드를 직접 참조하거나 수정**한다. private 필드 직접 접근, 다른 모듈 내부 라벨로 점프, 내부 자료 구조 가정.

```python
def module_a():
    module_b.internal_state = 10     # B의 내부 변수를 직접 조작
```

```java
enrollment.status = "CONFIRMED";     // 다른 패키지 객체의 필드를 직접 수정
```

문제: B의 내부 구현을 바꾸면 A가 깨진다. B는 자기 상태가 어떻게 바뀌는지 통제할 수 없다. 정보 은닉이 완전히 깨진 상태.

개선: 내부 필드를 감추고(private) 공개 메서드로만 접근하게 한다. `enrollment.status = "CONFIRMED"` → `enrollment.confirm()`.

## 2. 판정 질문표 (나쁜 것부터)

화살표 하나를 놓고 위에서부터 묻는다. 먼저 "예"가 나오는 것이 등급이다.

| 순서 | 질문 | 등급 | 기본 판정 |
|------|------|------|-----------|
| 1 | 상대 모듈의 내부 필드·private 멤버·내부 클래스를 직접 읽거나 고치는가? | 내용 | 불허 |
| 2 | 전역 변수, static 공용 가변 상태, 싱글턴의 가변 상태를 같이 쓰는가? | 공통 | 불허 |
| 3 | 같은 파일·DB 테이블·장치·환경 변수를 직접 공유하는가? | 외부 | 불허 |
| 4 | flag, mode, type 같은 제어 신호를 넘겨 상대 내부 분기를 결정하는가? | 제어 | 검토 |
| 5 | 구조체·객체·DTO·배열 전체를 넘기는가? (일부만 쓰더라도) | 스탬프 | 허용 (일부만 쓰면 검토) |
| 6 | 필요한 단순 값만 인자로 넘기고 결과만 받는가? | 데이터 | 허용 |

나쁜 것부터 묻는 이유: 한 화살표가 "값도 넘기고 전역 변수도 공유"하면 그 화살표는 공통 결합이다. 좋은 쪽부터 물으면 데이터 결합으로 잘못 판정한다.

## 3. 의존 형태별 판정 힌트

| 설계서·코드에 보이는 형태 | 보통 등급 | 주의 |
|--------------------------|-----------|------|
| `f(a, b)` 단순 값 호출 | 데이터 | |
| `f(dto)` 객체 통째로 | 스탬프 | 받는 쪽이 몇 필드 쓰는지 센다 |
| `f(data, isRetry=True)` | 제어 | 불리언 매개변수는 거의 항상 제어 |
| FK로 다른 패키지 테이블의 ID 참조 | 데이터 | ID 하나만 참조하면 데이터. 상대 테이블 컬럼을 복사해 오면 스탬프 이상 |
| 같은 테이블을 두 패키지가 직접 읽고 씀 | 외부 | 접근 모듈을 하나로 |
| `Config.taxRate` 전역 참조 | 공통 | 불변이고 시작 시 고정이면 "외부"로 낮춰 볼 수 있으나 가변이면 공통 |
| `other.field = x` | 내용 | |
| 다른 패키지의 내부 클래스 import | 내용 | 공개 인터페이스가 아닌 것을 쓰면 내용 |
| 파생 컬럼(다른 패키지 데이터에서 계산) | 숨은 의존 | FK 화살표로 안 보임. 갱신 책임표에 올린다 |

## 4. 패키지 쌍 요약 규칙

같은 두 패키지 사이에 화살표가 여럿이면 **가장 나쁜 등급**이 그 쌍의 결합도다. 데이터 5건 + 내용 1건 = 내용 결합.

양방향이면(A→B, B→A) 등급과 별개로 **순환 의존**으로 `structural-defects.md`에 넘긴다.

## 5. 개선 기법 대조

| 등급 | 개선 기법 | 적용 원리 |
|------|-----------|-----------|
| 내용 | 필드를 private으로, 공개 메서드로만 접근 | 정보 은닉 |
| 공통 | 전역 제거, 인자 전달 또는 설정 객체 주입 | 데이터 결합으로 하향 |
| 외부 | 외부 자원 접근을 한 모듈에 집중, 인터페이스 제공 | 추상화, 계층 분리 |
| 제어 | 메서드 분리 또는 다형성으로 분기 이동 | 기능 추상화 |
| 스탬프 | 실제 쓰는 값만 전달 (필요할 때만) | 데이터 결합으로 하향 |

## 6. 비유로 기억하기

| 등급 | 비유 |
|------|------|
| 데이터 | 필요한 값만 주고받는 동료 |
| 스탬프 | 서류철 통째로 건네는 동료 |
| 제어 | "이럴 땐 이렇게 해"라고 상대 일하는 방식까지 지시하는 동료 |
| 외부 | 같은 공용 서랍을 함께 쓰는 동료 |
| 공통 | 같은 통장을 함께 쓰는 동료 |
| 내용 | 서로 비밀번호까지 공유하는 동료 |
