# 자료 흐름도(DFD) 표기법

`sw-srs` 4단계에서 읽는다. 구조적 분석의 중심 도구로, 시스템 안에서 자료가 어디서 생겨 어떻게 처리되고 어디로 가는지를 그림으로 나타낸다.

## 1. 네 가지 구성 요소

| 요소 | 도형 | 이름 짓기 | 뜻 |
|------|------|-----------|----|
| 프로세스(Process) | 원 ○ 또는 둥근 사각형 | 동사+목적어 ("성적 검증") | 자료를 입력받아 변환해 출력하는 처리. "버블"이라고도 부른다 |
| 자료 흐름(Data Flow) | 화살표 → | 명사 ("성적입력", "검증된 성적") | 자료가 이동하는 방향. 화살표 위에 자료 이름을 쓴다 |
| 자료 저장소(Data Store) | 평행선 두 줄 ║ 또는 열린 사각형 | 명사 ("학생 파일", "성적 DB") | 자료가 머무는 곳. 파일, DB, 대장 |
| 단말(Terminator) | 사각형 □ | 명사 ("교수", "학생", "기존 학적 DB") | 시스템 밖의 개체. 자료를 주거나 받는 외부 주체. 외부 개체(External Entity)라고도 한다 |

텍스트로 그릴 때의 관례:

```
[교수]  ──성적입력──▶  (1. 성적 검증)  ──검증된 성적──▶  (2. 성적 저장)  ──▶  ║성적 DB║
  □                        ○                                  ○                 저장소
```

- `[ ]` 단말, `( )` 프로세스, `║ ║` 저장소, `──이름──▶` 자료 흐름.
- mermaid로 그릴 때는 단말을 `[ ]`, 프로세스를 `(( ))`, 저장소를 `[( )]`로 구분한다.

## 2. 레벨과 세분화

| 레벨 | 이름 | 내용 |
|------|------|------|
| Level 0 | 배경도(Context Diagram), 기본 시스템 모델 | 시스템 전체를 **원 하나**로. 단말과의 입출력 흐름만. 저장소 없음 |
| Level 1 | 상위 프로세스 분해도 | 배경도의 원을 3~7개 프로세스로. 저장소가 처음 등장 |
| Level 2 이상 | 세부 프로세스 상세도 | 각 프로세스의 내부를 더 쪼갬. 최하위 프로세스는 소단위 명세서로 서술 |

번호 규칙: Level 1 프로세스는 `1`, `2`, `3`. Level 2에서 프로세스 2를 쪼개면 `2.1`, `2.2`, `2.3`. Level 3이면 `2.1.1`.

**균형(Balancing) 규칙:** 상위 프로세스로 들어오고 나가는 자료 흐름은 그 프로세스를 쪼갠 하위 DFD에서도 모두 나타나야 한다. 상위에 없던 외부 입출력이 하위에서 생기면 상위를 고친다.

## 3. 작성 규칙

1. **자료가 처리되면 새 이름을 붙인다.** 프로세스를 지나 의미가 달라진 자료에 같은 이름을 쓰면 그 프로세스는 아무 일도 안 한 것이다. (입력 "성적입력" → 출력 "검증된 성적")
2. **시간·순서 개념이 없다.** DFD는 자료의 이동만 보여 준다. 어느 흐름이 먼저인지, 몇 번 반복하는지는 표현하지 않는다. 순서는 소단위 명세서나 상태전이도가 맡는다.
3. **저장소는 입력만 있어도 된다.** 로그, 이력 저장소처럼 쓰기만 하고 이 시스템 안에서 읽지 않는 저장소가 있을 수 있다. 입력 화살표가 있다고 출력 화살표를 억지로 그리지 않는다.
4. **직접 흐름 금지.** 단말→단말, 단말→저장소, 저장소→저장소는 그리지 않는다. 자료는 반드시 프로세스를 거쳐 변환된다.
5. **단말은 시스템 밖이다.** 시스템이 통제하지 않는 사람·조직·외부 시스템만 단말이다. 시스템 안의 관리자 화면은 단말이 아니라 프로세스다. 관리자(사람)는 단말이다.
6. **프로세스는 입력과 출력이 모두 있어야 한다.** 입력만 있는 프로세스(블랙홀)와 출력만 있는 프로세스(기적)는 오류다.
7. **한 레벨에 프로세스 7개 이하.** 넘으면 묶어서 상위 레벨을 하나 더 두거나 세분화 기준을 다시 본다.
8. **흐름 이름은 구체적으로.** "데이터", "정보", "자료"처럼 내용을 알 수 없는 이름을 쓰지 않는다.

## 4. 자주 틀리는 표기

| 틀린 것 | 맞는 것 |
|---------|---------|
| 단말을 원으로 그림 | 단말은 사각형. 원은 프로세스 |
| 배경도를 Level 1이라 부름 | 배경도는 Level 0 |
| 배경도에 저장소를 그림 | 배경도에는 단말과 흐름만 |
| 화살표에 순서 번호를 붙임 | DFD에 순서 없음. 번호는 프로세스에만 |
| 프로세스에서 저장소로 간 자료가 같은 이름으로 다시 나옴 | 저장 후 읽은 자료는 같은 이름이어도 되지만, 가공을 거쳤다면 새 이름 |
| "정의(Definition)"를 DFD 구성 요소에 넣음 | 정의는 자료사전의 구성 요소. DFD 요소는 프로세스·흐름·저장소·단말 넷뿐 |

## 5. DFD와 자료사전의 역할 분담

| 구분 | DFD | 자료사전 |
|------|-----|----------|
| 보여 주는 것 | 자료가 어디로 흐르는가 | 그 자료 안에 무엇이 들어 있는가 |
| 표현 | 그림(원·화살표·평행선·사각형) | 문장과 기호(`=`, `+`, `{ }`, `( )`, `|`, `* *`) |
| 단위 | 프로세스, 흐름, 저장소, 단말 | 자료 항목의 정의와 설명 |
| 시간 개념 | 없음 | 없음 |

DFD의 모든 흐름 이름과 저장소 이름은 자료사전에 정의가 있어야 한다. 하나라도 빠지면 그 자료는 "무엇인지 모르는 것"이 흐르는 것이다.

## 6. 학사관리 시스템 배경도 예

```
                    ┌──────────┐
                    │  교무처   │
                    └────┬─────┘
          학생등록정보, 수강승인기준│     ▲ 등록결과, 수강통계
                              ▼     │
┌──────┐  성적입력     ┌──────────────────┐   수강신청    ┌──────┐
│ 교수 │ ───────────▶ │                  │ ◀─────────── │ 학생 │
│      │ ◀─────────── │  학사관리 시스템   │ ───────────▶ │      │
└──────┘  입력확인      │        0         │  신청결과,    └──────┘
                      └────────┬─────────┘  성적표
                   학적조회요청 │     ▲ 학적정보
                              ▼     │
                    ┌──────────────┐
                    │ 기존 학적 DB  │  (외부 시스템 = 단말)
                    └──────────────┘
```

단말 4개(교무처, 교수, 학생, 기존 학적 DB), 프로세스 1개(0), 저장소 0개. 이것이 Level 0의 전부다.
