# 하향식 비용 산정 (전문가 감정, 델파이)

`sw-estimate` 절차 2·4에서 읽는다. 전체 비용을 먼저 추정한 뒤 세부로 나누는 방식이다. 전문가의 경험에 기대므로 빠르지만 주관적이다.

## 1. 하향식 vs 상향식

| 구분 | 하향식 | 상향식 |
|------|--------|--------|
| 방향 | 전체 → 세부 | 세부 → 합산 |
| 근거 | 전문가 경험, 유사 사례 | 작업 단위 측정(LOC, 단계별 인월) |
| 속도 | 빠름 | 느림 |
| 정확도 | 낮음 (주관적) | 높음 (데이터 기반) |
| 쓰는 시점 | 제안, 예비 추정, 교차 검증 | 계획 확정 |

둘 중 하나만 쓰지 않는다. 하향식으로 범위를 잡고 상향식으로 확인하거나, 상향식 결과를 하향식으로 검증한다.

## 2. 전문가 감정 (Expert Judgment)

### 절차

1. 조직 안에서 유사 프로젝트 경험이 있는 전문가 **2명 이상**을 고른다. 1명이면 편향을 걸러낼 수 없다.
2. 계획서(범위, 제약, 품질 목표)를 보여 주고 노력(인월)과 기간을 묻는다.
3. 각자의 근거(어떤 과거 프로젝트와 비교했는가, 무엇이 달라서 가감했는가)를 함께 받는다.
4. 추정값과 근거를 표로 남긴다.

### 한계

- 과거 경험이 새 프로젝트에 그대로 적용되지 않는다 (기술·규모·팀이 다르면 빗나간다)
- 개인적·주관적이다
- 데이터가 아니라 감에 기반해 정확도가 낮다

예비 추정 단계에서 "대략 이 정도"를 잡을 때 쓴다. 최종 확정값으로는 쓰지 않는다.

## 3. 델파이 기법 (Delphi Technique)

전문가 감정의 주관성을 줄이기 위해 **익명**으로 의견을 모으고 **반복** 조정해 합의점을 찾는다.

### 절차

1. 조정자(위원장)가 프로젝트 개요와 산정 양식을 전문가들에게 배포한다.
2. 전문가들이 **서로 모르게** 각자 추정치와 근거를 제출한다.
3. 조정자가 결과를 요약해 다시 배포한다. 평균·중앙값·범위와 함께 "낮게/높게 본 사람의 이유"를 익명으로 공유한다.
4. 전문가들이 요약을 보고 자기 추정치를 **수정**해 다시 제출한다.
5. 추정치의 범위가 기준 안으로 수렴할 때까지 3 ~ 4를 반복한다. 보통 2 ~ 4회.

### 수렴 기준

| 라운드 | 수렴 조건 |
|--------|-----------|
| 1 | 없음 (초기 분포 확인) |
| 2 이후 | (최댓값 − 최솟값) ÷ 중앙값 ≤ 0.3 이면 종료 |
| 4 | 수렴하지 않아도 종료. 중앙값을 쓰고 범위를 함께 기록 |

### 핵심 요소

- 익명성: 직급·영향력 있는 사람의 의견에 끌려가지 않는다
- 반복: 극단값이 근거 없이 유지되기 어렵다
- 조정자: 의견을 내지 않고 요약·배포만 한다

### 기록 양식

| 라운드 | 전문가 A | 전문가 B | 전문가 C | 전문가 D | 중앙값 / 범위 |
|--------|----------|----------|----------|----------|---------------|
| 1 | | | | | |
| 2 | | | | | |
| 3 | | | | | |

전문가 이름은 결과서에 적지 않는다. 익명성을 끝까지 유지한다.

## 4. 유사 프로젝트 참조

하향식의 가장 현실적인 형태다.

1. 규모·도메인·기술이 비슷한 과거 프로젝트를 2 ~ 3건 고른다.
2. 각 프로젝트의 실적 인월, 기간, 인원, 최종 LOC 또는 FP를 적는다.
3. 이번 프로젝트와의 차이(기능 수, 연동 수, 신뢰도 요구, 팀 경험)를 항목별로 ±%로 보정한다.
4. 보정 후 값을 추정치로 쓴다.

| 과거 프로젝트 | 실적 PM | 차이 요인 | 보정 | 환산 PM |
|---------------|---------|-----------|------|---------|
| | | | | |

## 5. 절대 쓰지 않는 방법

"일단 시작하고 나중에 비용을 계산한다." 프로젝트가 지연되고 비용이 무한정 들어간다. 계획 단계에서 비용 추정을 빼는 선택지는 없다.
