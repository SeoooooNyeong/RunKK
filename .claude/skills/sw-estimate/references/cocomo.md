# COCOMO (Constructive Cost Model)

`sw-estimate` 절차 4·5에서 읽는다. Barry Boehm이 1981년 과거 프로젝트 데이터를 통계 분석해 만든 경험적 모델이다. 입력은 원시 코드 라인 수(LOC)다.

## 1. 기본식

```
노력(인월, PM) = a × (KLOC)^b
기간(개월)     = c × (노력)^d
인원           = 노력 ÷ 기간
```

- KLOC: 1,000라인 단위 코드 수. 9,000 LOC = 9 KLOC
- a, b, c, d: 프로젝트 유형별 상수
- 결과 단위는 **인월**이다. 기간이 아니다.

## 2. 프로젝트 유형 3가지

| 유형 | 규모 | 특징 | 예 |
|------|------|------|----|
| Organic (기관형·조직형) | 50 KLOC 이하 | 단순, 익숙한 업무, 소규모 팀, 안정된 환경 | 회계, 급여, 학사·행정, 과학 계산 |
| Semi-detached (반분리형) | 300 KLOC 이하 | 중간 복잡도, 일부는 익숙하고 일부는 새로움 | 트랜잭션 처리, DBMS, 컴파일러, OS 일부 |
| Embedded (내장형) | 300 KLOC 이상 또는 하드웨어 밀착 | 실시간 제약, 하드웨어 결합, 오류 시 치명적, 고신뢰 | 미사일 유도, 항공 제어, 신호 제어 |

유형은 규모만으로 정하지 않는다. 규모가 작아도 실시간·고신뢰 제약이 강하면 Embedded다. 반대로 규모가 커도 단순 업무면 Semi-detached까지만 올린다.

### 유형 판별 질문

| 질문 | 예 | 아니오 |
|------|----|--------|
| 하드웨어·실시간 제약이 강하고 오류가 치명적인가 | Embedded | 다음 |
| 팀이 이런 종류의 시스템을 만들어 본 적이 있고 규모가 50 KLOC 이하인가 | Organic | Semi-detached |

## 3. Basic COCOMO 상수

| 유형 | a | b | c | d |
|------|---|---|---|---|
| Organic | 2.4 | 1.05 | 2.5 | 0.38 |
| Semi-detached | 3.0 | 1.12 | 2.5 | 0.35 |
| Embedded | 3.6 | 1.20 | 2.5 | 0.32 |

c, d는 강의 범위 밖의 표준값이다. 명목 기간 비교용으로만 쓴다.

### 계산 예

9 KLOC, Organic
```
9^1.05 = 10.0
노력 = 2.4 × 10.0 = 24.1 PM
기간 = 노력 ÷ 인원 = 24.1 ÷ 5명 ≈ 4.8개월 → 5개월
(참고) 명목 기간 = 2.5 × 24.1^0.38 = 2.5 × 3.35 = 8.4개월
```

기간은 강의의 공식 `노력 ÷ 인원`으로 정한다. 명목 기간 공식은 팀을 새로 구성하는 경우의 통계 참고치이며 결론을 좌우하지 않는다.

Basic은 규모와 유형만 보므로 정확도가 낮다. 초기 예산 감을 잡을 때 쓴다.

## 4. Intermediate COCOMO

Basic에 **비용 영향 요인(cost driver) 15개**를 곱해 보정한다.

```
노력 = a' × (KLOC)^b × EAF
EAF = 15개 요인 배율의 곱
```

| 유형 | a' | b |
|------|----|---|
| Organic | 3.2 | 1.05 |
| Semi-detached | 3.0 | 1.12 |
| Embedded | 2.8 | 1.20 |

### 15개 요인 (4개 군)

| 군 | 요인 | 높을 때 비용 |
|----|------|-------------|
| 제품 | 요구 신뢰도 | 증가 |
| 제품 | 데이터베이스 크기 | 증가 |
| 제품 | 제품 복잡도 | 증가 |
| 컴퓨터 | 실행 시간 제약 | 증가 |
| 컴퓨터 | 메모리 제약 | 증가 |
| 컴퓨터 | 가상 기계(플랫폼) 변동성 | 증가 |
| 컴퓨터 | 응답 소요 시간(Turnaround) | 증가 |
| 인력 | 분석가 능력 | 감소 |
| 인력 | 응용 분야 경험 | 감소 |
| 인력 | 프로그래머 능력 | 감소 |
| 인력 | 플랫폼 경험 | 감소 |
| 인력 | 언어 경험 | 감소 |
| 프로젝트 | 현대적 기법 사용 | 감소 |
| 프로젝트 | 도구 사용 | 감소 |
| 프로젝트 | 개발 일정 제약 | 압축·연장 모두 증가 |

### 배율 참고 범위

각 요인은 매우 낮음 ~ 매우 높음 등급에 0.7 ~ 1.65 사이 배율을 가진다. 보통(nominal)은 1.0이다. 인력 요인은 높을수록 배율이 1 아래로 내려가고(0.71 ~ 0.86), 제품·컴퓨터 요인은 높을수록 1 위로 올라간다(1.15 ~ 1.65).
정확한 표는 Boehm의 원서를 따르되, 조직에서 쓸 때는 과거 프로젝트로 보정한 값을 쓴다.

### 계산 예

9 KLOC, Organic, 인력 요인 모두 높음(분석가 0.86, 응용 경험 0.91, 프로그래머 0.86, 언어 경험 0.95), 도구 사용 높음(0.91), 나머지 보통
```
EAF = 0.86 × 0.91 × 0.86 × 0.95 × 0.91 = 0.58
노력 = 3.2 × 10.0 × 0.58 = 18.6 PM
```

## 5. Detailed COCOMO

Intermediate를 개발 단계(요구분석·설계·코딩·테스트)별로 나눠 요인을 따로 적용한다. 설계가 구체화된 프로젝트 후반에 쓰며 정확도가 가장 높다. 초기에는 입력이 없어 쓰기 어렵다.

| 모델 | 입력 | 쓰는 시점 | 정확도 |
|------|------|-----------|--------|
| Basic | 규모, 유형 | 제안·초기 계획 | 낮음 |
| Intermediate | + 15개 요인 | 계획 확정 | 중간 |
| Detailed | + 단계별 요인 | 설계 이후 | 높음 |

## 6. 조직 데이터와의 관계

COCOMO 상수는 1970년대 프로젝트 데이터다. 프레임워크, 라이브러리 재사용, 자동화 도구가 보편화된 현재 웹·업무 시스템에서는 Basic 값이 실측보다 1.5 ~ 2.5배 높게 나오는 경우가 많다.

사용 규칙
1. 조직 실측 생산성이 있으면 LOC 방법을 1차로 쓰고 COCOMO는 상한 참고치로 둔다.
2. 실측이 없으면 Intermediate로 인력·도구 요인을 반영한다.
3. 두 값의 차이를 문서에 적고, 차이만큼을 예비 노력의 근거로 삼는다.

## 7. 재사용 반영

재사용 모듈은 등가 LOC로 환산해 신규 LOC에 더한다.

```
등가 LOC = 재사용 LOC × (0.4 × 설계 수정 비율 + 0.3 × 코드 수정 비율 + 0.3 × 통합 노력 비율)
```

수정 없이 그대로 쓰는 모듈도 통합·테스트 노력은 들어가므로 0으로 치지 않는다. 보통 10 ~ 30%를 적용한다.

## 8. 흔한 오류

- 유형을 object, dynamic, function, medium 같은 이름으로 적는다. 유형은 Organic, Semi-detached, Embedded 셋뿐이다.
- 결과 인월을 개월로 읽는다.
- 모든 시스템에 같은 상수를 쓴다. 유형에 따라 다르다.
- Putnam과 혼동한다. Putnam은 Rayleigh-Norden 곡선 기반이고 도구는 SLIM이다. COCOMO는 LOC 기반 회귀식이다.
