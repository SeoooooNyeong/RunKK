# 범위 요소와 품질 목표 정의

`sw-plan` 절차 3(범위)과 절차 7(품질 목표)에서 읽는다.

## 1. 범위 5요소 상세

| 요소 | 반드시 적을 것 | 적지 말 것 |
|------|----------------|-----------|
| 기능 | 포함 기능 목록, 제외 기능 목록, 각 기능의 주 사용자 | 화면 설계, DB 구조 (설계 단계) |
| 성능 | 응답 시간(초), 처리량(건/시간), 동시 사용자 수, 데이터 보존 기간 | 서버 사양 (제약 조건으로) |
| 제약 조건 | 운영체제, 하드웨어, 메모리·저장 용량, 예산 상한, 마감 기한, 사용 언어·프레임워크 지정 여부 | 개발팀 규모 (자원으로) |
| 인터페이스 | 사용자 유형별 접점(웹·모바일·창구), 연동 기존 시스템, 외부 시스템(결제·인증·메일), 하드웨어 장치 | 연동 프로토콜 세부 (설계 단계) |
| 신뢰도 | 허용 장애 시간(월/년), 허용 오류율, 복구 목표 시간, 데이터 손실 허용 범위 | "안정적이어야 한다" 같은 비수치 표현 |

### 범위에 넣지 않는 것

- 개발 환경(IDE, 서버, 도구): 자원 절
- 인적 자원(인원, 역할): 자원 절과 `schedule.md` 조직 절
- 개발 방법론: 3P의 프로세스 절

### 인터페이스 분류

| 분류 | 예 |
|------|----|
| 소프트웨어 ↔ 하드웨어 | 지문 인식기, 프린터, 바코드 스캐너 |
| 기존 소프트웨어 ↔ 신규 소프트웨어 | 기존 학적 DB, 레거시 회계 시스템 |
| 사용자 ↔ 컴퓨터 | 웹 화면, 모바일 앱, 키오스크 |
| 장치 ↔ 장치 | 서버 간 통신, 외부 API |

"무언가와 무언가 사이를 연결하는 것"은 모두 인터페이스다. 빠뜨린 인터페이스는 설계 후반에 발견되어 일정을 가장 많이 흔든다.

## 2. 품질 목표 속성 정의

| 속성 | 정의 | 측정 방법 예 |
|------|------|-------------|
| 정확성(Correctness) | 요구한 기능을 정확하게 수행하는 정도 | 인수 테스트 통과율 100% |
| 신뢰성(Reliability) | 주어진 시간·조건에서 오류 없이 기능을 수행하는 정도 | 월 가동률 99.5%, 치명 결함 0건 |
| 효율성(Efficiency) | 최소 자원으로 동작하는 정도 | 응답 2초 이내, CPU 사용률 70% 이하 |
| 사용성(Usability) | 배우고 사용하기 쉬운 정도 | 신규 사용자 교육 없이 핵심 작업 10분 내 완료 |
| 이식성(Portability) | 다른 환경에서도 동작하는 정도 | Windows·Linux 양쪽 설치 테스트 통과 |
| 무결성(Integrity) | 허가되지 않은 접근·변경을 막는 정도 | 권한 우회 테스트 0건 통과 |
| 유지보수성(Maintainability) | 수정·보완이 쉬운 정도 | 결함 1건 수정 평균 2일 이내 |
| 유연성(Flexibility) | 요구 변화에 따라 쉽게 수정되는 정도 | 신규 보고서 추가 시 기존 모듈 변경 0건 |
| 시험 용이성(Testability) | 테스트하기 쉬운 정도 | 단위 테스트 커버리지 80% |
| 재사용성(Reusability) | 다른 프로그램에 재사용 가능한 정도 | 공통 모듈 비율 |
| 상호운용성(Interoperability) | 다른 시스템과 데이터를 교환하며 함께 동작하는 정도 | 연동 시스템과의 인터페이스 테스트 통과 |

### 관점 구분

- 사용자 관점: 정확성, 신뢰성, 효율성, 사용성, 무결성
- 개발자 관점: 유지보수성, 유연성, 시험 용이성, 이식성, 재사용성, 상호운용성
- 간결성은 품질 목표가 아니다. 코드가 간결한지는 코딩 스타일(`sw-code-review`)의 영역이다.

### 작성 규칙

1. 속성마다 측정 방법과 목표 수치를 함께 쓴다.
2. 측정할 수 없는 목표는 삭제하거나 측정 가능한 것으로 바꾼다.
3. 신뢰도 목표를 높이면 비용이 올라간다. `sw-estimate`의 비용 결정 요소에 반영된다.

## 3. 품질 보증의 네 조건

계획서가 품질을 보증하려면 다음 네 가지가 모두 문서에 있어야 한다.

| 조건 | 계획서 어느 절에 있는가 |
|------|------------------------|
| 요구사항 충족 | 범위 기능 목록 → `srs.md`로 상세화 |
| 성능 만족 | 범위 성능·신뢰도 |
| 예산·기간 준수 | 제약 조건 → `estimate.md`, `schedule.md` |
| 유연성(수정·보완 가능) | 품질 목표의 유지보수성·유연성 |
