# 용어 대조표 (sw-code-review)

강의에서 쓰는 암기법과 표현을 이 스킬의 용어로 대조한다. 본문에서는 왼쪽 표현을 쓰지 않는다.

## 생명주기와 단계

| 강의 표현 | 스킬 용어 |
|-----------|-----------|
| 계분설구(테유), 닭똥설구 | 계획 → 분석 → 설계 → 구현 → 테스트 → 유지보수 |
| 구현 = 코딩 | 설계 명세서를 코드로 변환하는 단계 |
| 모듈 단위 코딩·디버깅·단위 테스트가 일어나는 단계 | 구현 단계 |

## 결합도 (낮을수록 좋음)

설계 일치 점검에서 새로 생긴 의존 화살표의 등급을 매길 때 쓴다. 위에서부터 묻고 먼저 걸리는 것이 등급이다.

| 강의 암기 | 등급 | 판정 질문 | 리뷰 결함 등급 |
|-----------|------|-----------|----------------|
| 내 | 내용 결합도 | 다른 모듈의 내부 필드·private 멤버를 직접 읽거나 고치는가 | 치명 |
| 공 | 공통 결합도 | 전역 변수·static 가변 상태를 같이 쓰는가 | 치명 |
| 외 | 외부 결합도 | 같은 파일·DB 테이블·환경 변수를 직접 공유하는가 | 중 |
| 제 | 제어 결합도 | flag·mode 같은 제어 신호를 넘겨 상대 내부 분기를 정하는가 | 중 |
| 스 | 스탬프 결합도 | 구조체·객체 전체를 넘기는가 (일부만 쓰더라도) | 경 (기준 상한) |
| 데 | 데이터 결합도 | 필요한 값만 인자로 넘기고 결과만 받는가 | 없음 |

"데스제외공내"는 약한 것부터 강한 것 순서의 암기법이다.

## 응집도 (높을수록 좋음)

| 강의 암기 | 등급 | 판정 질문 |
|-----------|------|-----------|
| 기 | 기능적 | 모든 요소가 하나의 기능만을 위해 존재하는가 |
| 순 | 순차적 | 한 요소의 출력이 다음 요소의 입력인가 |
| 통 | 통신적 | 같은 데이터를 다루기 때문에 모였는가 |
| 절 | 절차적 | 실행 순서상 함께 있어서 모였는가 |
| 시 | 시간적 | 같은 시점(초기화 등)에 실행되어 모였는가 |
| 논 | 논리적 | 종류가 비슷해서 모였는가 (유틸 모음) |
| 우(의) | 우연적 | 아무 이유 없이 모였는가 |

"의논시절통순기"는 약한 것부터 강한 것 순서의 암기법이다. "응 하이, 결 로"는 응집도 High, 결합도 Low.

## 객체지향

| 강의 표현 | 스킬 용어 |
|-----------|-----------|
| 붕어빵틀 / 붕어빵 | 클래스 / 객체(인스턴스) |
| 감기약 캡슐 | 캡슐화, 정보 은닉 |
| 민증까() | 메소드 |
| extends | 상속 |
| private + getter/setter | 정보 은닉 구현 |
| this | 현재 객체 참조. 필드와 매개변수 이름 충돌 해소 |

## 형상 관리

| 강의 표현 | 스킬 용어 |
|-----------|-----------|
| 형상 = 모든 결과물 | 형상 항목 |
| 형상 식별 / 통제(제어) / 버전 제어 / 감사 / 상태 보고 | 다섯 활동 |
| 기준선 | 공식 확정된 산출물 상태 |
