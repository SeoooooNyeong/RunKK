# 코딩 스타일 점검표

코딩 스타일은 일관된 규칙으로 코드를 작성해 유지보수를 쉽게 만드는 표준이다. 사람마다 작성 방식이 다르기 때문에 규칙이 없으면 같은 프로젝트 안에서도 코드가 읽히지 않는다. 프로젝트가 자체 규약을 가지고 있으면 그것이 우선이고, 아래는 규약이 없을 때 적용하는 기본값이다.

## 1. 명명

| 항목 | 규칙 | 나쁜 예 | 좋은 예 |
|------|------|---------|---------|
| 변수 | 역할을 드러내는 명사. 한 글자·숫자 접미사 금지 | `a`, `tmp`, `data1` | `studentId`, `totalScore` |
| 불리언 | is/has/can 접두 | `flag`, `check` | `isPassed`, `hasPrerequisite` |
| 함수·메소드 | 동사 + 목적어 | `process()`, `doIt()` | `calculateGrade()`, `registerCourse()` |
| 클래스 | 단수 명사 | `Datas`, `Manager` 단독 | `Student`, `GradeCalculator` |
| 상수 | 대문자와 밑줄 | `max`, `Limit` | `MAX_SCORE`, `PASS_THRESHOLD` |
| 같은 역할 | 같은 패턴. `getX`/`fetchX`/`loadX` 혼용 금지 | | |

판정: 이름만 보고 무엇인지 알 수 없는 식별자 1개 = 경 결함 1건. 같은 파일에 5개 이상이면 중 결함 1건으로 합산한다.

## 2. 들여쓰기와 배치

- 블록 한 단계당 공백 4칸(또는 프로젝트 규약). 탭과 공백 혼용 금지.
- 중괄호 위치는 파일 안에서 한 가지 스타일만 쓴다.
- 한 줄 길이 120자 이하. 넘으면 줄을 나눈다.
- 관련 있는 문장끼리 빈 줄로 묶는다. 함수 안에 빈 줄이 하나도 없으면 단락 구분이 없는 글과 같다.

판정: 들여쓰기가 블록 구조와 어긋난 곳 1개 = 경 결함. IDE 자동 포맷으로 고칠 수 있으므로 지적보다 포맷터 적용을 권한다.

## 3. 제어 구조 단순화

| 패턴 | 문제 | 교정 |
|------|------|------|
| `if (a) { if (b) { if (c) {…}}}` | 중첩 3단계 초과 | 조건 결합(`a && b && c`) 또는 가드 절로 조기 반환 |
| `if (x) {…} else {}` | 빈 else | else 제거 |
| `if (cond) return true; else return false;` | 불필요한 분기 | `return cond;` |
| `if (!a) {…} else {…}` | 부정 조건 우선 | 긍정 조건을 먼저 둔다 |
| `switch`에 `break` 누락 | 의도하지 않은 fallthrough | break 추가 또는 의도를 주석으로 명시 |
| 반복문 안에서 반복 변수 수정 | 종료 조건 추적 불가 | 반복 변수는 반복문 헤더에서만 바꾼다 |

판정: 중첩 깊이 4 이상 = 중 결함. 빈 else, 불필요한 분기 = 경 결함.

## 4. 모듈화

- 함수 하나는 한 가지 일만 한다. 함수 이름에 "and"가 들어가면 둘로 나눈다.
- 함수 길이 50줄 이하. 화면 한 장에 들어와야 한다.
- 매개변수 4개 이하. 5개 이상이면 (1) 함수를 나누거나 (2) 매개변수들이 실제로 한 덩어리인지 확인해 값 객체로 묶는다. 단, 묶는 것이 스탬프 결합을 만들지 않는지 본다. 호출자가 그 객체의 필드 하나만 쓰기 위해 객체 전체를 만들어야 하면 묶지 않는다.
- 같은 코드 블록이 두 곳 이상 있으면 함수로 뽑는다.

판정: 매개변수 5개 이상 = 중 결함. 함수 50줄 초과 = 중 결함. 중복 블록(5줄 이상 동일) = 중 결함.

## 5. 변수 사용

- 임시 변수를 남발하지 않는다. 한 번만 쓰이는 임시 변수는 식에 직접 넣는다. 단, 식이 길어 이름이 설명 역할을 하면 남긴다.
- 변수 하나를 두 목적으로 쓰지 않는다. `result`에 중간 합계를 넣었다가 평균을 덮어쓰는 식의 재사용이 전형이다.
- 변수는 처음 쓰이는 곳 가까이에서 선언한다. 함수 맨 위에 모든 변수를 선언하는 방식은 수명이 길어져 추적이 어렵다.
- 매직 넘버(`90`, `0.1`)는 이름 있는 상수로 바꾼다.

판정: 변수 용도 재사용 = 중 결함. 매직 넘버 = 경 결함. 불필요한 임시 변수 = 경 결함.

## 6. 주석과 문서화

- 주석은 "무엇을"이 아니라 "왜"를 적는다. 코드가 하는 일을 다시 쓰는 주석은 지운다.
- 주석 처리된 코드는 지운다. 버전 관리가 이력을 가지고 있다.
- 공개 메소드에는 입력 조건, 반환값, 예외를 적는다.
- 주석과 코드가 다르면 주석이 틀린 것이다. 코드를 고칠 때 주석도 고친다. 이것이 유지보수 단계의 "문서화 부작용"을 막는 첫 단계다.

## 7. 예시: 성적 계산

나쁜 예:

```java
public String calc(int s, int t, boolean f, int m, int b) {
    String r;
    if (s >= 90) { r = "A"; } else { if (s >= 80) { r = "B"; } else { if (s >= 70) { r = "C"; } else { r = "F"; } } }
    if (f) { if (m > 0) { if (b > 0) { r = r + "+"; } } }
    return r;
}
```

문제: 이름(`s`, `t`, `f`, `m`, `b`, `r`)으로 역할을 알 수 없음, 매개변수 5개, 중첩 3단계, `t`는 쓰이지 않음, 매직 넘버.

교정 예:

```java
private static final int GRADE_A_MIN = 90;
private static final int GRADE_B_MIN = 80;
private static final int GRADE_C_MIN = 70;

public String calculateGrade(int score) {
    if (score >= GRADE_A_MIN) return "A";
    if (score >= GRADE_B_MIN) return "B";
    if (score >= GRADE_C_MIN) return "C";
    return "F";
}

public String applyBonus(String grade, boolean isEligible, int bonusPoint) {
    if (!isEligible || bonusPoint <= 0) return grade;
    return grade + "+";
}
```

가드 절로 조기 반환하는 것은 단일 출구 원칙의 허용된 예외다. 중첩 깊이가 1로 줄었고 함수가 둘로 나뉘어 각각 한 가지 일만 한다.
