# 재공학 계획: 학사관리 시스템 (기존 학적 연동 모듈)

> 작성: 2026-07-03 | 버전: v1.0 | 입력: docs/sw/maintenance/*.md (CR-001~008), docs/sw/design-review.md v1.4, docs/sw/code-review.md (2026-06-26), docs/sw/test.md v1.4

이 예시는 학사관리 시스템이 **전산실로부터 인수받아 재사용 중인 기존 학적 DB 연동 모듈(`legacy.StudentSyncAdapter`)** 을 대상으로 한다. 신규 개발 패키지(academic, grade, enrollment)는 설계서·추적표가 있어 재공학 대상이 아니다.

## 1. 배경과 목적

- 유지보수 현황: 운영 전환(2026-05-01) 후 2개월간 CR 8건. 유형별 수정 4 / 적응 1 / 개선 2 / 예방 1 (CR-006 PDF 라이브러리).
- 문제: 수정 보수 4건 중 3건(CR-001, 002, 007)이 모두 `legacy.StudentSyncAdapter`에서 발생. 이 모듈은 전산실이 2014년 작성한 Java 코드를 그대로 가져와 썼고, 설계 문서가 없으며, 원작성자가 2021년 퇴사했다. CR당 평균 이해 소요 9시간, 수정 소요 3시간.
- 목적: 유지보수성 향상, 수명 연장, 유지보수 비용 절감. 기능 추가나 개발 생산성은 목적이 아니다.
- 유형: 예방 보수

## 3. 역공학 (문서 복원이 필요한 모듈)

| 모듈 | 복원할 것 | 방법 | 산출물 위치 |
|------|-----------|------|-------------|
| StudentSyncAdapter | 의존 행렬 (내부 3클래스 + 외부 호출자 academic.StudentRepository) | 정적 분석(import·호출 추출), `sw-design` 1단계 형식 | design-oo.md v1.5 "역공학 복원: legacy" 절 |
| StudentSyncAdapter | 공개 인터페이스 7개 메소드의 입력·출력·예외 | 시그니처 + 호출자 사용 패턴 | 위와 같음 |
| StudentSyncAdapter | 학적 DB 뷰 `V_STUDENT_SYNC` 컬럼 19개의 의미와 형식 | DB 스키마 + 코드의 파싱 로직 관찰 | srs.md v1.4 부록 "자료사전 (역공학 복원)" |
| StudentSyncAdapter | 관찰 요구 FR-R-001~006 (예: "휴학 상태 코드 'L'을 재학 'E'로 변환해 저장한다") | 동작 관찰 + 로그 분석 (2026-05~06) | srs.md v1.4 부록 |

사용자 확인 필요 항목:
- FR-R-003: 제적(코드 'X') 학생을 동기화에서 **제외**한다. 의도인지 결함인지 전산실 확인 필요. (CR-007이 이 동작 때문에 발생)
- FR-R-005: 야간 동기화 실패 시 재시도 없이 다음 날까지 대기. 현재 요구(NFR-003 연동 100%)와 충돌 가능.

역공학 소요: 2명 × 2주 = 1 PM. 복원 문서는 `sw-design`으로 검증(의존 행렬·결합도 판정)한다.

## 4. 재구성 (기능 불변)

| 모듈 | 개선 내용 | 목표 지표 | 기능 불변 증명 |
|------|-----------|-----------|----------------|
| StudentSyncAdapter.syncAll (V(G) 23) | 상태 코드 변환·날짜 파싱·DB 쓰기를 각각 메소드로 분리. 중첩 5단계 → 2단계 | V(G) ≤ 8 (메소드별) | 비교 검사 TC-R-001~040: 2026-05~06 실제 동기화 입력 40일치 스냅샷 → 출력 레코드 100% 동일 |
| static 연결 객체 (공통 결합 2건) | 연결을 생성자 주입으로 바꿔 데이터 결합으로 | 공통 결합 0 | 위와 동일 TC |
| 환경 종속 코드 11곳 | `legacy.SyncConfig` 한 클래스로 집약 (JDBC URL, 인코딩 EUC-KR, 날짜 yyyyMMdd) | 외부 결합 4 → 1 (SyncConfig만) | 위와 동일 TC + 설정 변경 TC-R-041 |
| 혼재된 유틸 (로그·암호화) | 로그는 common.Logger로, 암호화는 academic.CryptoUtil로 이동. StudentSyncAdapter는 동기화만 | 응집도 우연적 → 기능적 | 이동 전후 호출 결과 비교 |

재구성 중 **기능을 바꾸지 않는다.** FR-R-003, 005처럼 결함으로 의심되는 동작도 재구성 단계에서는 그대로 둔다. 전산실 확인 후 수정 보수 CR로 별도 처리한다. 둘을 섞으면 비교 검사로 재구성의 정확성을 증명할 수 없다.

## 5. 이식 (환경 변경이 있을 때)

| 항목 | 현재 | 목표 | 범위 | 검증 |
|------|------|------|------|------|
| 문자 인코딩 | EUC-KR 하드코딩 | UTF-8 (전산실 DB 2026-09 전환 예정) | SyncConfig 1곳 (재구성 후) | 이전(EUC-KR)·새(UTF-8) 환경 비교 검사 TC-R-001~040 |
| JDBC 드라이버 | ojdbc6 (2011) | ojdbc11 | SyncConfig + 의존성 | 동일 |
| PDF 라이브러리 (우선순위 2) | iText 5.5 | OpenPDF 2.x | grade.GradeReportPrinter | TC-040~047 + 레이아웃 비교 30건 |

재구성(4절)으로 환경 종속 코드를 SyncConfig에 모은 **뒤에** 이식한다. 순서를 바꾸면 11곳을 다 고쳐야 한다.
