# 블랙박스 테스트

프로그램 **내부 구조를 보지 않고** 입력과 출력만으로 수행하는 테스트다. 사용자 관점에서 요구사항을 충족하는지 검증한다. 코드가 없어도 SRS만 있으면 설계할 수 있다. 주로 검증·시스템 테스트 단계에서 쓰지만, 단위 테스트에서도 값 선택에 쓴다.

## 1. 동치 분할 (Equivalence Partitioning)

입력 조건을 "프로그램이 같은 방식으로 처리할 것으로 기대되는" 값의 집합(동치 클래스)으로 나누고, 각 클래스에서 대표값 하나만 테스트한다. 같은 클래스의 다른 값으로 발견될 오류는 대표값으로도 발견된다는 가정이다.

| 입력 조건 유형 | 유효 클래스 | 무효 클래스 |
|----------------|-------------|-------------|
| 범위 (0 ≤ score ≤ 100) | 1개: 범위 안 | 2개: 미만, 초과 |
| 특정 값 집합 (학년 ∈ {1,2,3,4}) | 값마다 1개 | 1개: 집합 밖 |
| 개수 (수강 과목 1~8개) | 1개 | 2개: 0개, 9개 이상 |
| 불리언 (재학 여부) | 1개: 참 | 1개: 거짓 |
| 형식 (학번 10자리 숫자) | 1개 | 위반 유형별 1개: 길이 부족, 길이 초과, 문자 포함, 빈 값, null |
| 필수 여부 | 1개: 있음 | 1개: 없음 |

규칙:
- 유효 클래스는 한 케이스에 여러 개를 함께 넣어도 된다.
- 무효 클래스는 **한 케이스에 하나만** 넣는다. 둘 이상 넣으면 어느 것이 오류를 일으켰는지 알 수 없고, 첫 번째 검사에서 걸려 두 번째가 테스트되지 않는다.

예: 성적 입력 (score 0~100, 학번 10자리, 과목코드 존재)

| 클래스 | 값 | 유효/무효 |
|--------|----|-----------|
| score 범위 안 | 85 | 유효 |
| score 미만 | −5 | 무효 |
| score 초과 | 105 | 무효 |
| 학번 10자리 | 2024123456 | 유효 |
| 학번 9자리 | 202412345 | 무효 |
| 학번 문자 포함 | 20241234A6 | 무효 |
| 과목코드 존재 | CS101 | 유효 |
| 과목코드 미존재 | XX999 | 무효 |

케이스: 유효 1개(85, 2024123456, CS101) + 무효 5개(각각 하나씩 바꿈) = 6개.

## 2. 경곗값 분석 (Boundary Value Analysis)

오류는 동치 클래스 한가운데보다 **경계**에서 훨씬 자주 난다. `>=`를 `>`로 쓰는 실수, 배열 인덱스 하나 차이, 반복 종료 조건 때문이다. 범위 조건마다 여섯 값을 테스트한다.

| 위치 | 값 | 기대 |
|------|----|------|
| 최소 − 1 | min − 1 | 거부 |
| 최소 | min | 허용 |
| 최소 + 1 | min + 1 | 허용 |
| 최대 − 1 | max − 1 | 허용 |
| 최대 | max | 허용 |
| 최대 + 1 | max + 1 | 거부 |

예: score 0~100 → −1, 0, 1, 99, 100, 101.

등급 경계처럼 **내부 경계**가 있으면 그것도 포함한다. A/B 경계 90이면 89, 90, 91. B/C 경계 80이면 79, 80, 81.

경곗값은 동치 분할을 **보완**한다. 동치 분할의 대표값을 경곗값으로 고르면 케이스 수를 줄일 수 있지만, 클래스 한가운데 값도 하나는 남긴다.

## 3. 원인-효과 그래프 (Cause-Effect Graphing)

입력 조건(원인)이 여러 개 조합되어 출력(효과)을 결정할 때, 조합을 체계적으로 고른다. 동치 분할은 조건을 하나씩 보기 때문에 조건 간 상호작용을 놓친다.

절차:
1. 원인(입력 조건)과 효과(출력·동작)를 나열하고 번호를 붙인다.
2. 원인과 효과 사이의 논리 관계(AND, OR, NOT)를 그린다.
3. 그래프를 결정표(decision table)로 바꾼다. 열 하나가 원인 조합 하나다.
4. 각 열을 테스트 케이스로 만든다.

예: 수강신청 승인

원인: C1 재학 상태, C2 선수과목 이수, C3 정원 여유, C4 시간표 충돌 없음
효과: E1 승인, E2 "정원 초과" 반려, E3 "선수과목 미이수" 반려, E4 "휴학·제적" 반려, E5 "시간 충돌" 반려

| 규칙 | C1 | C2 | C3 | C4 | 효과 |
|------|----|----|----|----|------|
| R1 | 참 | 참 | 참 | 참 | E1 |
| R2 | 거짓 | − | − | − | E4 |
| R3 | 참 | 거짓 | − | − | E3 |
| R4 | 참 | 참 | 거짓 | − | E2 |
| R5 | 참 | 참 | 참 | 거짓 | E5 |

"−"는 무관(don't care). 검사 순서가 정해져 있으면 뒤 조건은 무관이 된다. 규칙 5개 = 케이스 5개. 조합 전체(2^4 = 16)를 돌릴 필요가 없다. 입력 조건이 3개 이상 조합될 때만 쓴다.

## 4. 오류 예측 (Error Guessing)

경험상 틀리기 쉬운 입력을 일부러 넣는다. 체계적 기법이 아니라 체크리스트다. 기능마다 한 번 돌린다.

| 범주 | 값 |
|------|----|
| 빈 값 | "", null, 공백만 |
| 0과 음수 | 0, −1, 가장 작은 음수 |
| 극단 크기 | 최대 길이, 최대 길이 + 1, 매우 큰 수 |
| 형식 | 특수 문자, 이모지, SQL 인용부호, 앞뒤 공백, 전각 숫자 |
| 타입 | 정수 자리에 실수(10.5), 숫자 자리에 문자 |
| 시간 | 윤년 2월 29일, 자정, 시간대 경계, 과거·미래 날짜 |
| 동시성 | 같은 요청 두 번 빠르게, 두 사용자가 같은 레코드 수정 |
| 상태 | 이미 확정된 성적 재입력, 삭제된 과목에 신청 |

## 5. 비교 검사 (Comparison Testing)

같은 요구사항으로 만든 둘 이상의 버전(이전 릴리스, 기존 시스템, 다른 팀 구현)에 같은 입력을 넣고 출력이 같은지 비교한다.

- 유지보수 단계의 회귀 테스트: 수정 전 버전의 출력을 기대 결과로 쓴다. 단, 수정 목적이 그 출력을 바꾸는 것이면 해당 케이스는 제외한다.
- 이식(적응 보수): 이전 환경과 새 환경에서 같은 결과가 나오는지.
- 재구성(재공학): 기능이 바뀌지 않았음을 증명하는 유일한 방법이다.

## 6. 기법 선택 기준

| 상황 | 기법 | 케이스 수 감각 |
|------|------|----------------|
| 숫자·날짜·길이 범위 입력 | 동치 분할 + 경곗값 | 조건당 3 + 6 |
| 열거형·집합·불리언 입력 | 동치 분할 | 값 수 + 1 |
| 조건 3개 이상 조합 | 원인-효과 그래프 → 결정표 | 규칙 수 |
| 모든 기능 | 오류 예측 체크리스트 | 범주당 1~2 |
| 수정·이식·재구성 | 비교 검사 | 기존 케이스 전부 |

## 7. 용어 대조

| 강의 표현 | 이 문서 |
|-----------|---------|
| 동치 분할 검사, Valid / Invalid 대표값 | 1절 |
| 경곗값 분석, 최소·최대 근처 | 2절 |
| 원인-효과 그래프 검사 | 3절 |
| 오류 예측 검사 (Fault-Based, Mutation) | 4절 |
| 비교 검사 | 5절 |
| 블랙박스 = 외부, 입력·출력, 기능 검사 | 문서 전체 |
